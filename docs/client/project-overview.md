## 背景

現行は、表計算で来場者・座席・購入状況を管理し、印刷した表へ当日の来場状況を手書きしています。二重入力、集計、再入場確認を改善する必要があります。

## 目的

- QRコードを利用して受付作業を簡略化する。
- 来場者ごとの受付状態を正確に管理する。
- 公演当日の来場状況を関係者が確認できるようにする。
- 要件、設計、テスト、運用上の判断を追跡可能にする。

## 期待する効果

- 受付担当者の確認作業を削減できる。
- 二重受付や受付状況の記録漏れを防止できる。
- 公演運営に必要な来場状況を把握しやすくなる。

## 対象範囲

- 既存購入者名簿から受付に必要な項目を取り込み、内容を検証する。
- 公演ごとのQRを発行し、家庭印刷用・印刷業者向けデータを出力する。
- 複数端末でQR受付、受付不可判定、再入場確認、手動受付、例外対応を行う。
- 座席・支払い・発行・発送・例外の状態、来場・未来場、競合、操作履歴を管理する。
- 通信停止中も受付を継続して復旧後に統合し、利用不能時は紙の運営表へ切り替える。
- 集計、CSV、当日運営表の出力、権限、無効化・削除を扱う。
- 公開リポジトリを確認する第三者評価者が、依頼者から分離した評価環境と架空データで主要機能を試せるようにする。将来公開ライセンスを採用する場合にも、個人コンサート主催者が分かりやすく自分専用環境を設定・利用できる構成にする。

## 対象外

- チケット販売、オンライン決済、返金、領収書発行、お釣り計算
- チケットの実印刷、発送、来場者への送信
- 完全な購入者名簿の管理、公的身分証による厳密な本人確認、QR複製の完全防止
- グループ一括受付、現時点での第三者への利用許諾・個別運用支援、企業向け専用機能またはコンサート以外を前提とした汎用化

電子チケット、任意項目、再入場メモ、座席表、自動座席配置、全スタッフ向け連絡欄は、個別の要件IDと受入条件IDを付けて正式要件へ追加済みです。専用カメラモードと、依頼者へ影響しない公開リポジトリの評価環境、将来の公開ライセンス採用を妨げない分かりやすさと環境分離も、Issue #23の最終承認対象へ追加しています。

## 前提と制約

- 通常200～300人、最大500人程度を約30分、少なくとも6台で受け付けます。
- 入場口は最大2か所で、担当者は個人所有スマートフォンを使用します。
- 会場は毎回変わり、Wi-Fiと携帯回線を前提にできません。
- システム構成と使用技術は未決定です。公開リポジトリの評価者は、依頼者環境を使わずローカルまたは自分の評価専用環境で試します。公開ライセンスは現時点で採用せず、将来採用する場合に利用条件を別途決定します。
- 初期の受付用データは必要最小限とし、完全な購入者名簿はシステム外で管理します。
- 依頼者用環境の継続費用は原則ゼロで、費用発生前に承認を必要とします。評価者にはローカルで試せる方法を優先し、外部サービスを使う場合も依頼者用環境を使用しません。
- 年1～2回、当面3年程度の利用を想定します。

## 関係者

具体的な氏名や連絡先は本リポジトリに記載せず、役割で管理します。

| 役割 | 主な責任 |
|---|---|
| 依頼者 | 業務要件の説明、要件と受入条件の確認・承認 |
| 開発担当者 | 要件整理、設計、実装、テスト、文書管理 |
| 受付担当者 | 当日の受付業務、操作性に関する確認 |
| 運用担当者 | 公演情報や来場者情報の管理、障害時の対応 |
