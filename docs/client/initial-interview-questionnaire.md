# 初回要件ヒアリング質問票

## この文書について

| 項目 | 内容 |
|---|---|
| 目的 | QRコードを利用するコンサート受付について、要件と受入条件を確定するために必要な事実、希望、制約、優先順位を確認する |
| 主な読者 | 依頼者、受付担当者、運用担当者、開発担当者 |
| 使用時期 | 初回ヒアリング前、初回ヒアリング実施時、未決定事項の追加確認時 |
| 記載する内容 | 質問、確認理由、回答後の反映先、未決定の場合の影響 |
| 記載しない内容 | 実在する来場者の個人情報、秘密情報、未承認の要件、確定していない技術選定 |
| 関連文書 | [要件定義書](requirements.md)、[受入条件書](acceptance-criteria.md)、[初回要件ヒアリング議事録](meeting-notes/2026-08-30-initial-requirements-interview.md) |
| 関連Issue | [#1](https://github.com/EU0207/concert-reception-system/issues/1) |
| 状態 | Draft |
| 承認情報 | 未承認 |

## 使用方法

- 上から順に確認し、回答は対応する議事録の同じ質問IDへ記録します。
- 回答が確定していない場合は推測で補わず、確認担当と期限を決めて未決定事項として記録します。
- 個人情報は「氏名」「連絡先」などの項目名と利用目的だけを確認し、実在する値や名簿は記録しません。
- QRコードの内容、認証方式、端末構成、通信方式などの重要な技術選定は、要件と制約の合意後に候補を比較し、必要に応じてADRへ記録します。
- 「更新する文書」は、回答が依頼者に確認され、要件または受入条件として採用された後の反映先です。

## ヒアリング完了時の確認

初回ヒアリング終了時に、次を参加者間で確認します。

- 回答を「確認した事実」「決定事項」「未決定事項」のいずれかに分類したか。
- 決定事項ごとに反映先を決めたか。
- 未決定事項ごとに確認担当の役割と期限を決めたか。
- 実在する個人情報や秘密情報を議事録へ記録していないか。
- 重要な技術選定を要件として確定していないか。
- 要件定義書と受入条件書の更新・レビュー・承認が完了するまで実装を開始しないことを確認したか。
