## 対象範囲

### 今回の対象として決定済み

| 区分 | 対象要素 |
|---|---|
| 公演準備 | 既存の購入者名簿から受付に必要な項目を取り込む、取込内容を検証する、座席・支払い・発行・発送・例外の状態を管理する |
| チケット準備 | 公演ごとのQRを発行する、家庭印刷用データと印刷業者向けデータを出力する |
| 当日受付 | QR受付、受付不可の判定、再読取り・再入場確認、手動受付、来場・未来場の確認を行う |
| 座席・例外 | 座席の追加・変更、特別な案内、当日手渡し・現金受領等の例外を管理する |
| 障害対応 | 複数端末で受付し、通信停止中も継続して復旧後に記録を統合する。利用不能時は紙の運営表へ切り替える |
| 管理 | 権限、操作履歴、競合確認、集計、CSV・当日運営表の出力、削除を扱う |

### 購入者名簿から受付データへの流れ

既存の購入者名簿を元データとして利用し、受付用に同じ内容を一から入力し直さない運用を想定する。

`既存の購入者名簿（氏名・住所・電話番号・メールアドレス等）` → `管理者権限を持つ利用者が取込項目と内容を確認` → `受付用データ（氏名・座席・必要な状態・例外対応）`

- 氏名・座席等の必要項目は、専用テンプレートへのコピーまたは列の対応付けにより取り込めるようにする。
- 住所・電話番号・メールアドレスは初期の受付用データへ取り込まず、完全な購入者名簿はシステム外で管理する。
- 任意項目として連絡先等を追加する要望は、利用目的、閲覧権限、保存・削除、出力、受付端末への配布可否を決めてから採否を確定する。
