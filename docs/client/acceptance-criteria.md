# 受入条件書

## この文書について

| 項目 | 内容 |
|---|---|
| 目的 | システムを完成として受け入れるための確認条件を合意する |
| 主な読者 | 依頼者、開発担当者、確認担当者 |
| 作成・更新時期 | 要件定義工程、要件または確認方法の変更時 |
| 記載する内容 | 受入条件、関連要件、確認方法、期待結果 |
| 記載しない内容 | 詳細な実装方法、未承認の要求 |
| 関連文書 | [要件定義書](requirements.md)、[トレーサビリティ表](../development/traceability-matrix.md) |
| 関連Issue | [#1](https://github.com/EU0207/concert-reception-system/issues/1) |
| 状態 | Draft |
| 承認情報 | 未承認 |

## 記載方法

- 受入条件には `AC-001` から始まるIDを付けます。
- 各条件に対応する要件IDを記載します。
- 依頼者が確認できる具体的な操作、条件、期待結果を記載します。
- 判定は `未実施`、`合格`、`不合格` のいずれかで記録します。

## 受入条件

要件の確定後に作成します。現時点では確定した受入条件はありません。

| 受入条件ID | 関連要件ID | 確認内容 | 確認方法 | 期待結果 | 判定 |
|---|---|---|---|---|---|
| 未登録 | 未登録 | 要件確定後に記載 | 要件確定後に記載 | 要件確定後に記載 | 未実施 |

## 承認

受入条件の確認依頼と結果はGitHub Issueに記録し、承認後に本欄へIssue番号と承認日を記載します。
