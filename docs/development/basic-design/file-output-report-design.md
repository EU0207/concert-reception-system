## 結論

入出力はすべて公演単位とし、主担当・代理管理者が対象公演、出力種別、対象件数、含める項目を確認してから端末内で処理する。入力原本と生成物本体をFirestoreへ保存せず、アプリ管理の一時領域は成功、失敗、取消し、画面離脱のいずれでも破棄する。利用者がブラウザーの保存先へ明示保存したファイルは、アプリ外の運用管理対象とする。

Excel取込はシステムが生成した`.xlsx`テンプレートだけを対象とし、数式、マクロ、外部リンクを実行しない。QRには個人情報を入れず、推測困難な資格識別子と形式版だけを格納する。CSVは表計算ソフトで値が式として実行されないよう安全化する。PDF、ZIP、Excel、CSVのファイル名へ氏名を含めない。

座席番号、欠番、スペースセルは別々に扱う。実在する座席だけを座席数の対象にし、座席表の配置上のスペースセルを席として出力しない。来場者未割当ての確保済み席は座席表に出力するが、チケットとQRの出力対象にしない。座席番号版と座席表示名版は同じ確定済み座席配置から生成し、見た目だけで別の席順を作らない。名前付き座席表のPDFとExcelは舞台を左端に配置し、席番号を各座席枠の左隣へ自動表示する。

## BD-07-02 公演用Excelテンプレート

### ワークブック構成

| 項目 | 設計 |
|---|---|
| ファイル形式 | Office Open XMLの`.xlsx`だけを使用する。`.xls`、`.xlsm`、`.csv`、パスワード付きファイルは取込対象外 |
| ファイル名 | `attendee-template-YYYYMMDD.xlsx`。公演名や氏名を含めない |
| シート | `入力`と`説明`の2シート。取込対象は`入力`だけ |
| 見出し | 1行目を固定見出し、2行目を架空の入力例、3行目以降を入力欄とする。取込時は2行目の例を無視する |
| 件数 | 1公演最大500データ行。空行は件数へ含めない |
| サイズ | 圧縮状態5MB以下、展開後20MB以下。画像、図形、埋込みファイルは許可しない |
| セル | 結合セルを許可しない。表示値ではなくセル値を検査し、数式セルはエラーにする |

### 列定義

列名は完全一致で検査し、重複、変更、余分な列を理由付きで拒否する。会場で使用しない区画と列は空欄にできる。任意項目列は、公演で先に定義した表示順にテンプレートへ追加する。

| 順序 | 列名 | 必須 | 制約・扱い |
|---:|---|---:|---|
| 1 | 購入者名 | ○ | 前後の空白を除去後、内部の空白を含めて1～50文字。同じ名前の複数席を許可する。超過時は省略せずエラーにする |
| 2 | 座席表示名 | － | 半角・全角の空白を除いて0～6文字。空欄時は購入者名が同じ上限内なら初期値にし、超過時は6文字以内の略称入力を求める |
| 3 | 区画 | － | 初回取込では空欄を許可する。入力する場合は座席構成と照合し、階は区画名に含める |
| 4 | 列 | － | 対象区画で使用する場合だけ入力する |
| 5 | 表示用座席番号 | － | 初回取込では空欄を許可する。席配置時に確定し、入力する場合は文字列として先頭ゼロ、英字・数字接頭部、記号を保持する |
| 6 | グループID | － | 0～50文字。空欄は個人客。同じ公演の同じ指定を同じ所属として扱い、内部UUIDへの対応は[DD-97の所属契約](../detailed-design/customer-ticket-detail-design.md#excelのグループ所属から配置への契約251)による（#251・PR #253で承認済み） |
| 7以降 | 管理者が定義した任意項目名 | － | 最大10列、各値0～200文字。未入力でもQR発行を妨げない |

席番号が空欄の行は座席未割当として取り込み、名簿順と取込行の識別子で区別する。同じ購入者名の複数行を統合しない。後の会場席作成・席配置で座席を確定し、席未割当の行にはチケットとQRを発行しない。席番号を入力した行だけ`区画`、`列`、`表示用座席番号`の組合せで照合する。区画または列を使わない会場では空文字を組合せへ含める。未登録番号から座席を自動作成しない。

## BD-07-03 取込検証と確定

取込は`選択 → 安全検査 → 全行検証 → プレビュー → 確定`の順とする。解析、文字数、重複、座席整合性の検証と最大500件のプレビューは端末内で行う。利用者が確認して`確定`するまで、Firestore更新、QR発行、来場者登録を行わない。

### 席未割当の名簿行を配置対象にする

本項は第三者品質レビューM-04への是正案であり、UIモックと基本設計の再レビューで確認する。

`CONF-048`により、REQ-F-001の公演用Excelテンプレートは初回取込時の席番号を任意とする。席番号が空欄の行を座席未割当の来場者として登録し、REQ-F-036の自動配置対象にする。別の専用テンプレートや重複する登録経路は設けない。入力は1人1行、最大500行とし、購入者名を必須にする。座席表示名とグループIDは任意とする。座席、チケット、QRはこの段階で生成しない。

安全検査、全行検証、プレビュー、管理者の確定を初回取込で行う。プレビューには登録数、席未割当数、グループ人数、同じ購入者名の複数行を示す。既存の来場者と重複する可能性がある行は自動統合せず確認対象とする。席未割当の来場者はBD-06の`P-05`で席へ割り当てる。未配置のまま発券、QR発行、当日受付データの配布は行わない。

| 検査段階 | 検査内容 | エラー時の扱い |
|---|---|---|
| ファイル | 拡張子、ZIP署名、Office Open XML構造、サイズ、暗号化・マクロ・埋込み・外部リンクの有無 | ファイル全体を拒否し、再選択を案内する |
| シート | `入力`の存在、見出し行、結合セル、重複列、余分な列 | ファイル全体を拒否し、テンプレート再取得を案内する |
| セル | 数式、制御文字、不可視文字、文字数、型、改行 | 行・列・理由を表示する。数式を評価しない |
| 業務 | 購入者名の欠損・50文字超過、入力済み番号の未登録座席、同じ座席への複数割当、既存データとの重複 | 席番号の空欄だけでは初回取込を拒否しない。他の不備行は確定不可とし、購入者名を省略しない。同じ購入者名だけではエラーにしない |
| 件数 | 500行超過、任意項目11列以上 | 全体を確定不可とする |

エラー一覧は行番号、列名、入力値の短い表示、理由、修正方法を示す。氏名と任意項目値をログへ残さず、画面でも対象行の確認に必要な範囲だけ表示する。正常行だけの部分確定は行わない。利用者がすべてのエラーを修正し、件数、追加件数、更新件数、除外件数を確認してから1回で確定する。

確定直前にオンライン状態、現在役割、対象公演を再確認する。入力済みの座席番号がある場合は座席構成版も照合し、検証中に変わった場合は確定せず再検証する。席番号なしの名簿取込は会場席作成前でも許可する。原本ファイルと取込途中の平文は、確定、取消し、失敗、画面離脱後にアプリ管理の一時領域から破棄する。

## BD-07-04 QRと確認コード

### QRペイロード

QRの論理形式は`crs:v1:<credential>`とする。`credential`は暗号学的乱数から生成した128ビット以上の値をBase64urlで表現し、氏名、公演名、開催日、座席、連番、環境名を含めない。資格識別子から公演とチケットを直接推測できないようにする。

QRは資格識別子の検索キーであり、権限証明や電子署名の代わりにしない。オンライン時は対象環境のFirestoreとSecurity Rules、完全オフライン時は対象公演用に事前取得した資格一覧で照合する。別環境・別公演で一致しない資格は受け付けない。

QR資格は1席ごとに1つの現行版を持つ。座席変更と座席表示名変更では同じ資格を維持する。紛失再発行では旧資格を理由付きで無効化し、新しい乱数資格を作る。旧資格は履歴照合のため識別子を保持するが、受付可能には戻さない。

### 確認コード

読取り不能時の確認コードは、QR資格ごとに別のランダム値を生成する。紛らわしい文字を除いた英数字8文字を`ABCD-EFGH`の形で表示し、公演内で一意にする。氏名、座席、QR資格の先頭文字から導出しない。確認コード検索は管理者だけに許可し、候補が1件に一致した後も公演名、現在席、資格状態を確認してから手動受付へ進む。

### 描画条件

| 項目 | 設計 |
|---|---|
| 色 | 黒いモジュール、不透明な白背景 |
| 余白 | QR規格の4モジュール以上を四辺に確保する |
| 大きさ | A6 PDFではコード本体32mm四方を基準とし、余白を別に確保する |
| 誤り訂正 | レベルMを初期値とし、ペイロードを短く保つ。変更する場合は対象3実機と紙で再試験する |
| 加工 | 透過、反転、装飾、ロゴ重ね、縦横比変更、画像補間によるぼかしを行わない |

## BD-07-05 A6電子チケットPDFとZIP

PDFはA6縦105mm×148mmの1ページとする。フォントは日本語を表示できるものを埋め込みまたは適切にサブセット化し、端末依存フォントへ置換されても情報が欠けない方式を実装時に選ぶ。

```text
┌──────────────────────────┐
│ 架空公演 2027/10/10 18:00 │
│ 架空会館                 │
│ 東京都架空区1-2-3         │
├──────────────────────────┤
│ 購入者名: 購入者A         │
│ 座席: 1階 A列 A-12       │
│                          │
│       [  QR 32mm  ]      │
│                          │
│ 確認コード: ABCD-EFGH     │
└──────────────────────────┘
```

表示項目は公演名、開催日時、購入者名、会場名、会場住所、区画、列、表示用座席番号、QR、確認コードとする。会場名と会場住所は対象公演の会場スナップショットを使用し、購入者住所は参照・表示しない。座席表示名は当日案内用であり、電子チケット上の氏名は購入者名を用いる。項目が長い場合は文字を無制限に縮小せず、規定行数を超えた時点で生成前エラーとして対象を示す。

PDF生成確認には、対象席、現在のQR版、座席変更後の再生成か紛失再発行かを表示する。PDF生成だけでチケット準備状態を自動変更しない。管理者が保存・印刷結果を確認した後、別操作で`発行済み`へ進める。

ZIPは個別PDFだけを格納し、実行ファイル、フォルダー階層、総合名簿を含めない。ファイル名は`ticket-0001.pdf`からの連番とし、氏名、公演名、座席を含めない。格納順は確定済みの区画表示順、列表示順、席表示順、チケット番号の順とする。同名ファイルを作らない。

保存・印刷前に、PDFをそのまま使用すること、実際のサイズ100%、高品質・高精細、下書き・高速・インク節約を使わないことを表示する。システムからメール、LINE、SMS等へ送信しない。

## BD-07-06 印刷業者向けExcel

印刷業者向けExcelは、確定済みの現在席リストを1行1席で出力する。席順は区画表示順、列表示順、席表示順、チケット番号の順とし、欠番を補完せず、スペースセルを行として出力しない。

| 列 | 列名 | 内容 |
|---:|---|---|
| A | 区画 | 空欄可。階を含む区画名 |
| B | 列 | 空欄可 |
| C | 表示用座席番号 | 文字列として保持する |
| D | QR画像 | 当該席の現行資格。黒、白背景、4モジュール以上の余白 |
| E | 確認コード | QR読取り不能時の照合用 |

QR画像は座席番号の隣列へ置き、セルへ固定する。列Dの幅と行高は、100%表示時にQR本体が32mm四方を下回らない初期値とする。拡大縮小や画像圧縮で縦横比を変えない。印刷業者の指定寸法が新たに示された場合は、この論理列順と席対応を維持した別の出力プロファイルとして変更管理する。

ワークブックには数式、マクロ、外部リンク、名前定義による外部参照、非表示シートを含めない。文字セルはすべて値として書き込み、QR画像以外の埋込みオブジェクトを作らない。

## BD-07-07 CSV、当日運営表、匿名集計

### 通常CSV

CSVはUTF-8 BOM付き、CRLF改行、カンマ区切り、1行目見出しとする。各値を二重引用符で囲み、値内の二重引用符を2つ重ねる。改行、タブ、NUL等の制御文字は出力しない。

通常CSVと任意項目選択CSVは補助出力として維持する。出力画面ではPDF・Excelの主要選択肢と視覚的に区分し、利用者が必要な場合に展開または選択できるようにする。

| 順序 | 列名 | 内容 |
|---:|---|---|
| 1 | 開催日 | 会場タイムゾーンの`YYYY-MM-DD` |
| 2 | 開催回 | 公演名 |
| 3 | 購入者名 | 標準氏名 |
| 4 | 座席表示名 | 現在値 |
| 5 | 区画 | 公演時点の値 |
| 6 | 列 | 公演時点の値 |
| 7 | 表示用座席番号 | 文字列 |
| 8 | 来場有無 | `来場済み`、`未来場`、締め前は`未受付` |
| 9 | 初回受付時刻 | 未受付時は空欄、ISO 8601オフセット付き |
| 10 | チケット準備状態 | `購入確定`、`入金確認`、`発行済み`、`交付済み`の各チェック済み・未済み |

通常CSVには任意項目、QR資格、確認コード、認証識別子、端末識別子、詳細履歴を含めない。任意項目選択CSVでは、利用者が確認画面で選んだ項目だけを右端へ定義順に追加する。

CSV式注入を防ぐため、先頭の空白と制御文字を除いて最初の文字が`=`、`+`、`-`、`@`となる文字列は、出力値の先頭へアポストロフィを付ける。元の値は画面上で変更せず、CSV用に安全化したことを出力確認へ表示する。

### 当日運営表

当日運営表はA4横PDFとし、ヘッダーへ公演名、開催日時、会場名、出力時刻、`取扱注意`を表示する。列は区画、列、表示用座席番号、購入者名、表示用チケット番号、受付確認、例外メモとする。QR資格、確認コード、任意項目、住所、連絡先を含めない。

1ページ目から列見出しを表示し、2ページ目以降も見出しを繰り返す。席順は他の帳票と同じ確定済み順序とする。受付確認欄と例外メモ欄は手書きできる高さを確保する。開催前準備では、最新の来場者・座席件数、出力時刻、予備印刷完了チェックを表示し、印刷後に完了操作を監査記録へ残す。

### 匿名集計

匿名集計は開催日、公演単位の総席数、対象来場者数、来場済み数、未来場数だけを扱う。氏名、座席、チケット番号、端末、利用者、任意項目を含めない。締め前は未来場数を確定値として表示せず、未受付数と明記する。

## BD-07-08 2種類の座席表

座席番号版はPDF、座席表示名版はPDFと編集可能な`.xlsx`で出力する。初期印刷設定はA4横・1ページとし、座席表示名版のPDFとExcelで同じ印刷範囲、用紙方向、配置を用いる。舞台は座席配置の左端へ固定する。Excelは出力後に利用者がセル幅、行高、文字、印刷設定を調整できるが、システムへの再取込用ファイルとは扱わない。すべての出力へ公演名、区画名、出力種別、出力時刻を表示する。

座席番号版は各座席セルの中心へ表示用座席番号を表示する。座席表示名版は、各席を四角枠で表し、枠内へ座席表示名または確保済み席の管理用表示ラベルを表示する。表示用座席番号は各座席枠の左隣へ自動配置する。座席表示名は空白を除いて最大6文字とし、空白がある場合はその位置、ない場合は3文字ごとで2行に分ける。

```text
座席番号版                       座席表示名版

A列  [A-1] [A-2]   [A-4]        舞台  1 ┌─────┐ 2 ┌─────┐   4 ┌─────┐
                                        │架空 │   │田中 │     │スタ│
                                        │来場A│   │太郎 │     │ッフ│
                                        └─────┘   └─────┘     └─────┘
            ↑欠番A-3は作らない
            通路のスペースセルは空間だけを残す
```

座席セルは確定済み座席への参照がある場合だけ描画する。欠番はセル自体を生成せず、スペースセルは配置上の空白として描画する。どちらもQR、来場者、座席数、空席数の対象にしない。確保済み席は座席数と座席表の対象とするが、来場者未割当てならチケットとQRを生成しない。購入者名を座席表示名へ自動的に再上書きせず、出力時点の現在値を使う。

## BD-07-09 ファイルと出力の安全対策

| 脅威・誤操作 | 対策 |
|---|---|
| 拡張子偽装 | 拡張子だけで判定せず、ZIP署名とOffice Open XML内の必須構造を確認する |
| マクロ・埋込み | `.xlsm`を許可せず、VBA、OLE、ActiveX、埋込みパッケージを検出したら拒否する |
| 外部参照 | 外部リンク、外部データ接続、リモート画像、DDEを検出したら拒否する |
| ZIP爆弾 | 圧縮前後サイズ、エントリー数、入れ子ZIP、パスを制限する |
| 数式実行 | 取込数式を評価せずエラーにし、Excel出力へ数式を書かない。CSVは式開始文字を安全化する |
| パストラバーサル | ZIP内名に絶対パス、`..`、区切り文字を使わず、生成側で固定名を作る |
| 個人情報漏えい | ファイル名、ログ、監査、エラーへ氏名や任意項目値を含めない |
| 古いデータの誤出力 | 出力直前に公演、座席構成版、QR版、権限を再取得し、確認画面の版と違えば中止する |
| メモリー残留 | 生成完了・失敗・取消し後に一時オブジェクトURLとバッファ参照を破棄し、Service WorkerとCache Storageへ保存しない |
| 誤保存 | 保存前に個人情報の有無と取扱注意を表示し、共有端末では保存先を確認する |

入力ファイルと生成物を外部サービスへ送信しない。クライアント側の生成が端末性能上成立しない場合も、未承認のサーバー生成へ切り替えず、不適合として設計へ戻す。

## BD-07-10 生成、一時保存、失敗時の扱い

1. 対象公演と現在役割をオンラインで確認する。
2. 対象件数、項目、座席構成版、QR版を固定した生成スナップショットを端末メモリーへ作る。
3. 入力値を出力形式別に安全化し、ファイルを端末内で生成する。
4. 件数、ページ数、ファイル数、除外件数、警告を検証し、exportId・対象版と監査用情報を暗号化して端末へ保存する。
5. 現在認可・同一版を再検査し、利用者操作による保存要求の直前状態を端末へ永続化してからブラウザーへ渡す。端末保存失敗時は渡さない。
6. 観測結果と監査送信内容を固定して端末へ保存し、完了後に監査を送信する。本体バッファ・一時URLと監査待ち情報を区別して回収する。

途中で権限失効、対象公演変更、データ版不一致、容量不足、生成例外が発生した場合は、部分的なファイルを成功として渡さない。新しい出力を利用者が選ぶときは新しいスナップショット・exportIdを作る。監査再送では元のexportId・固定本文を保持し、ブラウザーへの保存要求と結果不明を区別して表示する。実ファイル保存完了と断定せず、自動再生成・再ダウンロードをしない。停止・失効中はロックし、現在認可が成立してから監査だけを照会・再送する。

ブラウザーのダウンロード先へ保存されたファイルはアプリから確実に削除できない。画面では、保存先、共有先、印刷業者への受渡し、使用後削除が利用者管理であることを案内する。BD-08で具体的な確認時点と削除手順を定める。

## BD-07-12 外部サービス交換と後続設計

PDF、Excel、CSVおよびプレビューは、版情報とともに取得済みのデータから端末内で生成する。生成のために全件を再取得せず、生成自体では共有DBへ書き込まない。出力監査は生成処理と分離し、利用者が出力を確定した操作だけを対象に、引渡し前の端末保存と監査の受領を別に行う。

出力生成はFirestore SDKから直接帳票へ書き込まず、BD-03の共通データ形式を入力とする。Firebase交換時も、Excelテンプレート列、QR論理形式、CSV列、PDF・帳票レイアウト、座席並び、式注入対策を維持する。交換対象は、出力元データの取得、認証、権限確認、監査記録の保存である。

移行時は、旧環境の共通形式出力を新環境へ再取込し、公演、座席、来場者、QR版、現在状態、件数を照合する。QR資格を維持できない方式へ変更する場合は、全QR再発行と旧QR無効化が業務へ与える影響が大きいため、新しいADRと依頼者承認を必須とする。切戻しでは、移行開始後に新環境で作られたイベントを失わない統合方法を先に決める。

JSONは通常出力として採用せず、出力画面にも表示しない。バックアップ・復旧・移行でJSONを採用するかはBD-08で検討し、採用する場合は対象データ、形式版、整合性確認、暗号化、保存期限、再取込時の権限と検証を定める。BD-09では、破損、欠落、改変、形式版不一致、重複取込、途中失敗と切戻しを試験対象へ割り当てる。JSONを採用しない場合も、共通データ形式から安全に出力・再取込する代替方式を明示する。

## 懸念と残存リスク

- ブラウザーの保存先へ渡した個人情報ファイルは、アプリから削除や転送先を制御できない。運用手順と使用後削除が必要である。
- 500件のPDF・ZIP生成は端末メモリーと処理時間に依存する。対象PCで上限時の完了、取消し、容量不足をBD-09で確認する。
- プリンター、PDF閲覧ソフト、印刷業者の処理で拡大縮小や画像圧縮が行われるとQR品質が低下する。100%・高品質案内と実機読取り試験が必要である。
