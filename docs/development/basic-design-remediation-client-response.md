## CONF-050 M-06の追加回答

2026-09-25に開発者が「依頼者に確認しました。M-06：推奨案で良いです」と明示して伝達した。前回提示した推奨案に従い、各公演の締め後バックアップを次の公演の締め後バックアップ取得まで保管し、旧世代を削除する。保管期限を過ぎた世代からの復元は認めない。公演前確定後と締め後の必須取得時点は`CONF-049`のままとする。

次公演の締め後バックアップがまだない場合、直近の締め後バックアップを保持する。次公演の公演前バックアップは、その公演の締め後バックアップが検証されるまで保持する。旧世代の破棄は新世代の復号・内容・復元練習の成功後に行う。個人情報削除などによって旧世代に削除済み情報が残る場合は、この周期を待たず旧世代を復元禁止とし、削除を反映した新世代の取得と旧世代の安全な破棄を行う。これらは回答の実行条件を具体化した設計案であり、再レビューと受入試験は未了である。

## CONF-052 ADR-006の容量上限

2026-09-26に開発者が、先に伝達した依頼者回答の続きとして「200KBを上限としてよい」と回答した。続けて、この回答が依頼者からのものであることを確認した。会場画像は1枚200KB（200,000バイト）以下、最大5枚、合計1MB（1,000,000バイト）以下に変更する。スマートフォンで拡大して必要な文字と配置が読めることは`CONF-051`のまま維持する。画像の実画質は未確認であり、上限内で読めない画像は調整するか座席一覧を代替表示する。費用枠はプロジェクト全体で監視し、画像だけを根拠に無料運用を保証しない。

本回答は容量上限と画質条件の依頼者判断である。ADR-006の技術方式は限定検証を経て採用判断し、是正後の要件・基本設計一式の変更承認および実装後のAC-025合格と区別する。

この上限は後続の`CONF-053`で1MBへ変更された。現在の上限は次節を参照する。

## CONF-053 ADR-006の容量上限変更

2026-09-26に開発者が「依頼者より、やっぱり１枚1MBが良い」と明示して回答を伝達した。`CONF-052`の200KB上限は履歴として保持し、最新の上限を1枚1MB（1,000,000バイト）、最大5枚、合計5MB（5,000,000バイト）に変更する。スマートフォンで拡大したときに必要な文字と配置が読めるという`CONF-051`の画質条件は維持する。1MBを超える画像は拒否し、容量内で読めない画像は調整するか座席一覧を代替表示する。

画像本体だけなら5枚で最大5MB、6端末が各1回取得して最大30MBである。Firestoreの1文書上限1MiB（1,048,576バイト）には、1,000,000バイトの画像と少量のメタデータを収められる見込みであり、POC-006で限定確認した。実サービスの使用量と実画像の可読性は未確認である。ADR-006の容量上限、要件、受入条件、設計案を本回答に合わせて改訂する。基本設計一式の変更承認とAC-025の実装後合格は別判定とする。
