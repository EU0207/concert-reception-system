## 結論

検証用プロジェクトは本番へ転用せず、全PoCの確認完了後に1回だけ削除する。プロジェクト削除は関連するFirebase資源全体を使用不能にし、プロジェクトIDも再利用できないため、本書で対象と影響を確認し、依頼者が削除を明示承認した後だけ実行する。

## 復元可能期間と注意点

[Google Cloud公式のプロジェクト削除・復元説明](https://docs.cloud.google.com/resource-manager/docs/delete-restore-projects?hl=ja)では、削除要求後は原則30日間`DELETE_REQUESTED`状態となり、権限を持つ所有者は期間内に復元できる。ただし、サービスによっては資源が30日より前に削除される場合があり、すべての復元は保証されない。復元後に各サービスが利用可能になるまで時間がかかる場合もある。

[Firebase公式のプロジェクト説明](https://firebase.google.com/docs/projects/learn-more)では、削除したプロジェクトIDとプロジェクト番号は再利用できない。また、[Google Cloud公式の削除説明](https://docs.cloud.google.com/resource-manager/docs/delete-restore-projects?hl=ja)では、完全削除までプロジェクト作成上限へ数えられるため、上限への反映は即時ではない。

以上から、本操作は「30日以内なら必ず元どおりになる削除」とは扱わず、元に戻しにくい操作として実行する。

1. 対象IDと請求状態を再表示する。
2. プロジェクト`crs-poc-001-20260902-01`へ削除要求を行う。
3. プロジェクトが有効な一覧から外れたこと、状態が`DELETE_REQUESTED`になったことを確認する。
4. ローカル専用設定`poc/POC-005/.firebaserc`を削除し、共有用`.firebaserc.example`は保持する。
5. POC-001～POC-005結果、技術検証計画、追跡表へ削除日と確認結果を記録する。
