# POC-003 実機確認手順書

## この文書について

| 項目 | 内容 |
|---|---|
| 目的 | IT開発経験がない確認担当者でも、POC-003の対象実機を安全に確認できるようにする |
| 主な読者 | 依頼者、実機確認担当者、開発担当者 |
| 前提 | 開発担当者から期限付きの確認用URLを受け取っていること |
| 使用データ | 画面に用意された架空データだけ |
| 状態 | Draft |

## 用意するもの

- iPhone 17
- iPhone 13 mini
- Galaxy Z Fold8
- A6縦100%で印刷した架空チケット1枚
- 充電とWi-Fi接続

端末購入、アプリストアからの追加アプリ導入、Googleアカウント設定、Firebase Console操作は不要である。対象端末やプリンターを用意できない場合は代替機で進めず、開発担当者へ連絡する。

## 安全上の注意

- 確認用URLには架空データだけを入力する。実在する氏名、座席、公演、QRを使わない。
- OS更新を求められても、この確認のために勝手に更新しない。表示された版を開発担当者へ伝える。
- 確認用URLは公開URLのため、第三者へ転送しない。
- 端末全体の初期化や他のサイトデータ削除は行わない。

## 1台ごとの確認

1. iPhoneはSafari、Fold8はChromeで確認用URLを開く。
2. 「架空チケット500件を端末へ準備済み」と「PWA資産を取得しました」を確認する。
3. 「カメラ開始」を押し、ブラウザーの確認画面でカメラを許可する。
4. A6の架空チケットを5回読み、毎回「次へ」を押す。失敗と最大時間を確認票へ記録する。
5. 別の端末に見本チケットを表示し、その画面を5回読む。
6. 受付結果を表示したまま別QRを提示し、結果が変わらないことを確認する。「次へ」後は読めることを確認する。
7. オンラインで見本表示まで済ませ、通信を切る。画面を再表示して架空QRを読み、受付件数が残ることを確認する。確認後は通信を戻す。
8. 「実機確認票」へ機種、OS版、ブラウザー版、回数、最大時間、各チェックを入力する。
9. 「確認結果JSONを保存」を押す。不足が表示された場合は、該当項目を確認してから再度保存する。

## Fold8だけの追加確認

1. 外側画面で見本表示とカメラ読取りを行う。
2. 内側画面で同じ操作を行う。
3. 受付結果または確認票を表示したまま端末を開閉し、表示と入力が残ることを確認する。
4. Fold8用の3つのチェック欄を選択する。

## 紙とPDFの確認

1. 開発担当者が用意したPDFをA6縦、倍率100%で1部だけ印刷する。
2. 公演、日時、架空氏名、架空会場・住所、階・区画・列・席、QR、確認コードが1ページ内にあることを確認する。
3. 3機種のカメラで紙から読めることを確認する。
4. PDFを対象端末へ表示し、別の対象端末から読めることを確認する。自分の画面を自分のカメラで読む必要はない。

## 結果の渡し方

各端末から保存した次の3ファイルを、このタスクへ添付する。

- `FAKE-P003-device-result-iPhone-17.json`
- `FAKE-P003-device-result-iPhone-13-mini.json`
- `FAKE-P003-device-result-Galaxy-Z-Fold8.json`

JSONには機種・版・件数・チェック結果・入力した備考だけが入り、Googleアカウントや端末識別番号は含まれない。スクリーンショットは原則不要である。

## 終了時の削除

結果を開発担当者が受領した後、案内を受けて次を実施する。

1. 画面最下部の「POC-003端末データを削除」を押す。
2. ブラウザーのサイト設定で、確認用URLのカメラ許可とサイトデータだけを削除する。
3. Downloadsから`FAKE-P003-`で始まる今回のPDF、ZIP、結果JSONだけを削除する。
4. 他のダウンロード、写真、ブラウザーデータは削除しない。

開発担当者は別途、Firebase HostingのPOC-003プレビューチャネルを削除し、URL無効化を確認する。
