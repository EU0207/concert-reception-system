## DD-98-01 範囲・設定者と既定値

2026-10-20、開発者がPR #247の先頭`621265ebd6b1ddb394497ae8d28f19cc40b83415`をレビュー承認し、mainへ統合した（`64f402cf46844e0608fc489de21c2b872f6024bf`）。DD-98とADR-012の案Aを承認済み。21ケースの製品試験は未実施。

臨時管理者へ既に許可された当日管理操作を、公演と本人UIDごとにON/OFFする。既存の禁止操作を設定で許可する機能にはしない。一般受付・主担当と代理管理者の権限表を変更せず、主担当引継ぎと役割変更はDD-96の別操作とする。

設定者は、有効な主担当または代理管理者。現在の対象役割が臨時管理者である場合だけ変更できる。臨時管理者は自分・他人の設定を変更できず、代理への設定変更や自己昇格にも使えない。設定者の権限は、既存の臨時管理者任命権限の範囲内に限定する。

初回任命時の既定値は、下表の全9項目をONとする。これは従来の臨時管理者の許可範囲を保つ値であり、管理者は任命確認画面でOFFに変更できる。任命と最初の設定を同じ確定で保存する。設定が存在しない・不正な場合に、既定値を自動補充して管理操作を許可しない。

全項目OFFでも役割は臨時管理者のままとし、画面に管理操作が許可されていないことを示す。一般受付として共通に許可される操作と、未送信の回収・結果照会を設定の取消しで止めない。公演終了・停止や本人・端末の失効は別に優先する。

## DD-98-03 保存・版と一体確定

権限の共通版にはDD-96の`roleVersion`を使う。役割名が変わらない設定変更でも版を1進め、端末の準備済み版と照合する。独立した権限版を別に設けず、役割変更と設定変更の競合もこの版で拒否する。DD-96の同一役割への無変更要求と、本書の専用設定コマンドを区別する。

| 領域・値 | 契約 |
|---|---|
| `roles/{personUid}` | 現在の役割・版と権限プロファイル参照。設定変更では役割名・任期と停止状態を便乗変更しない |
| `temporaryPermissionProfiles/{personUid}/{roleVersion}` | 対象UIDと役割版、形式版1、9項目の真偽値と有効開始・終了。状態は`active`または`revoked`で、後者は全項目OFF。確定後は不変 |
| `temporaryPermissionOperations/{operationId}` | 固定した入力・期待版と終端結果。設定確定・取消しと再照会を区別し、別内容の同IDを拒否 |
| 変更監査 | 実行者・対象UID、実行端末と役割版、9項目の変更前後・期限と結果を記録。秘密情報と実在者の情報をログへ出さない |

1. 設定者はオンラインで現在認可・対象役割版と設定を取得し、15分以内の本人再認証を確認する。設定対象・変更前後と期限を通常の確認画面で示す。
2. 固定した操作ID・入力と期待版を端末へ保存する。保存失敗なら要求しない。
3. 端末Authで確定し、サーバーで設定者の現在認可・対象役割と期待版を再判定する。新しい不変プロファイル・役割参照と版、監査と操作結果を同じRTDB確定へ含める。
4. 同じ確定結果を照会後だけ成功を表示する。各端末はDD-98-05の追加準備へ進む。

共通祖先の書込み後状態で相互参照・増分1と全9項目を検査する。対象者自身の設定・役割版更新を拒否し、設定変更で主担当・代理や別公演へ影響させない。欠落・余分なキーと不正型を拒否する。部分送信と削除は`.write`の拒否条件にも含め、広い祖先許可や`.validate`だけに依存しない。プロファイルだけ準備して権限を取得する経路は作らない。

変更案の中止は保存された現行設定へ影響しない。確定後の応答喪失では同じIDを照会し、別IDで自動再実行しない。競合と設定者の降格・停止では旧現行を保ち、入力を保持して再確認する。取消しと同時変更も同じ期待版で一方だけが成立する。成功監査は一体保存するが、拒否された不正要求の診断を必ずクライアントから送信できるとは保証しない。

## DD-98-04 期限・取消しと再任命

| 状況 | 判定・設定者の操作 |
|---|---|
| 初回任命 | DD-96の臨時役割と既定値または確認した9項目を一体保存。設定の有効期間を役割の期間内に収める |
| 期限指定 | `role.validFrom <= profile.validFrom < profile.validUntil <= role.validUntil`を要求。会場翌日23:59:59と公演終了時の管理終了も優先 |
| 時刻境界 | 開始時刻を含み、終了時刻から拒否。サーバーは`now`で判断し、端末時計で延長しない |
| 確定後の設定取消し | 全9項目OFFの新しい版を確定。旧プロファイルを消さず、既定の全ONへ戻さない |
| 設定の期限切れ | 追加管理操作を拒否。期限前のプロファイルや既定値へ自動で戻らない |
| 既定値へ戻す | 設定者が全9項目ONを明示確認して新しい版を確定。新権限は各端末の追加準備後だけ有効 |
| 役割解除・再任命 | 旧プロファイルを新役割へ流用しない。新任命の確認で設定を再作成し、停止端末を自動復帰させない |

設定期間は臨時役割の任期を延ばさない。役割終了や停止を設定OFFの代替にせず、本人UID・Authと他公演の割当は維持する。取消しは回復不能なデータ削除ではないため、DD-90の独立2回確認を一律追加せず、通常確認・再認証と監査を適用する。

## DD-98-05 現在認可・端末とオフライン

臨時管理者の操作許可は、現在の本人・端末とセッション、役割・公演状態に加え、現行プロファイルの有効期間と対象フラグをすべて満たす場合だけ成立する。通常の追加管理経路は端末の準備済み役割版の一致も必要とする。欠落・期限切れと版不一致を権限ONとして扱わない。主担当・代理の許可を臨時用設定値で代用しない。

読取りは操作に必要な最小の投影へ分ける。`dayManagementRead=false`は管理一覧・集計の取得を拒否するが、許可された手動受付等に必要な個別参照と共通の受付データは残る。この違いを設定画面に表示する。任意項目・購入者情報と認証管理監査を準備用・管理用という理由だけで配布しない。親への広い読取り許可で禁止経路を覆わない。

変更確定時にサーバーは削除された権限を拒否し、新しい権限の利用は端末ごとに保留する。残るON項目も、各端末が新しい版を確認するまで追加管理操作を保留する。端末は現在版・期間と差分を取得し、既存の公演・端末用鍵で暗号化して一体保存した後だけ準備済み版を更新する。準備専用の差分取得にも現在の設定と期間を適用し、未来開始・OFFの操作にだけ必要な管理データを先取りしない。一部端末の完了を他端末へ転用しない。設定変更だけで鍵再生成・PWA再インストールと全件の取り直しを要求しない。

設定変更では臨時役割自体を変えないため、共通操作は現在の本人・端末と公演条件が有効なら継続できる。ただし、旧版の通常管理経路を許可する一般的な例外にはしない。通常要求で自己申告した設定・版を使わず、サーバーの現在参照と検査済みの準備結果を照合する。

完全オフライン端末へ取消しを即時通知できない。最後に確認した役割版・設定と端末固有のオフライン許可を使い、設定・任期と公演許可の最も早い期限を過ぎた管理操作をロックする。通信復帰時は通常同期より先に現在認可を確認し、削除された権限の画面と旧差分をロックする。既に見た内容の回収や端末時計改変に対する完全な保証はしない。既存の画面ロック・紙切替と停止連絡の運用を維持する。

未送信の記録は発生時の役割版・設定版を保持し、現在版に書き換えない。現在も許可された操作は、新しい認可・準備を確認して既存の再送契約へ渡す。取り消された操作の後着は自動確定・公開せず、隔離・管理者照合へ渡す。連絡の「未共有」も勝手に共有へ変えない。受領済み結果の限定された照会・保全経路は通常業務読取りと分け、取消し後も二重実行を防ぐ。

旧差分・旧プロファイルは未解決の操作と受付記録が参照する間は保持する。受領確認前に記録や必要な鍵を消さず、整理は既存の保持・削除条件へ従う。設定の変更・期限到達を、利用者が削除するまで保持する要件の短縮に使わない。

バックアップ中の過去の設定を現在認可へ上書きしない。履歴の復元と現在の役割・端末承認を分ける既存の#221の条件を維持し、取消し済みの許可を古いプロファイルから復活させない。
