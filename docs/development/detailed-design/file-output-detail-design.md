## DD-235-01 対象と権限

2026-10-20、開発者がPR #243の先頭`671a1d9d120f1d2fd0555cb9bfa7b20f4f0d5428`をレビュー承認し、mainへ統合した（`81f2043d4d1b06637b19037dcdb7d367a97a81d8`）。出力契約・選定手順と14ケースが対象であり、依存追加・実ファイル生成と実印刷は未実施。

帳票は取得済みの共通データから端末内で生成し、外部生成サービスへ送信しない。主担当・代理管理者だけが対象公演をオンラインで確認して出力する。臨時管理者・一般受付には出力権限を加えず、表示を隠すだけでなく取得と出力要求でも拒否する。TBD-011の部品採用は別ゲートであり、本書で依存を追加しない。

ZIPと任意項目選択CSVは、最後の本人再認証から15分以内であることもサーバーで照合する。通常出力へ同じ高影響条件を一律に追加せず、各機能の現在役割と端末許可を検査する。出力操作では入金・券発行と券送付のチェックを変更しない。印刷・外部送付の確認後に利用者が別操作で更新する。

## DD-235-02 入力と同一版の確認

出力要求は環境・公演ID、出力種別と対象ID集合を持つ。選択した区画・券の順序と項目を確認画面で固定し、画面上のフィルターや表示中の1ページだけを黙って全体対象にしない。0件、重複IDと存在しない対象は生成前に理由を示して拒否する。

| 入力単位 | 受渡しと検査 |
|---|---|
| 公演・会場スナップショット | 公演名・日時・タイムゾーン、会場名・住所。コピー元や別公演の現在値へ置き換えない |
| SeatMapProjection | 構成・席設定と表示版、区画・列のdisplayOrderとseatId・表示番号、舞台方向、セル位置と席区分。画面のピクセル寸法やスクリーンショットを使わない |
| 券・QR | personId・seatIdと現在のcycle・資格版、credentialと確認コード。自由な席番号を資格として解析せず、#112が許可した現在資格だけを生成用メモリーへ渡す |
| 購入者・表示名 | personBuyers→buyerId→現在の購入者名。profile.nameは登録時の記録であり現在名にしない。席表は席の表示名・確保席ラベルを使う |
| 版集合 | 公演管理版、構成・席設定・表示と券の版、customer/head、実績・締めIDを必要範囲で保持。取得開始・終了と保存直前に同じ範囲を照合 |
| 出力監査 | exportId、出力種別・公演と件数、選択した項目IDと入力版、本人・端末と時刻・結果。氏名・任意項目値とファイル本体を複写しない |

同一版の取得済みデータを再利用し、生成のために毎回全件を取り直さない。初回取得・不足分は認可されたページ取得を行い、版が変わったら混在候補を破棄して入力を再確認する。生成中に席・購入者名の修正、取消し・再発行や権限失効があれば、保存前に再検査して中止する。既存のPDF内の氏名・QRが後から自動更新されるとは案内しない。

現在の管理一覧を出す場合は訂正後の現在値を使う。締め時点の記録を出す要求では、その締めIDに固定された氏名・実績を使い、現在名と混ぜない。チケット生成は常に現在資格を対象とし、古い締め結果から旧QRを再生成しない。

### 対象の採否

席未設定、不参加、未確定の構成、割当と券の参照不一致、旧cycle・無効資格のチケット出力を拒否する。選択対象の一部が不正なら部分生成せず、対象と理由を示して再選択を求める。未入金だけでは拒否せず、固定チェックの済み／未済みを資格状態の代わりにしない。確認用項目を発券可否の条件にしない。

確保済み席は座席表の席数と描画へ含めるが、来場者未割当てならチケット・QRを生成しない。未・欠番・空間・通路を実在席へ変換せず、欠番を補完して券を作らない。購入者名や任意項目をSeatMapProjectionへ混ぜず、用途別の入力を分ける。

## DD-235-03 レイアウトと生成物

### A6電子チケットと印刷業者向けExcel

PDFは105mm×148mmの縦1ページ、四辺8mmを安全領域の基準とする。以下は印刷用の初期テンプレート案であり、実装でフォントの実寸を測り、実PDFと印刷で確認する。長い値を無制限に縮小・切捨てしない。

| 領域 | 位置・初期条件 |
|---|---|
| 公演名・日時 | 左8mm・幅89mm。公演名は上8mmから最大3行・12pt、日時は上28mmから1行・10pt |
| 会場・住所 | 上36mmから会場2行・10pt、上48mmから住所3行・9pt。購入者住所を参照しない |
| 購入者名・席 | 上65mmから購入者名3行・10pt、上82mmから区画・列と表示番号。現在の購入者名を省略しない |
| QR・確認コード | 上88mmから中央に46mmの外接領域を確保し、本体32mm四方と四辺4モジュール以上の白余白。確認コードは上136mmから10pt、8文字を4文字ずつハイフン区切り |

各文字領域の下端が次領域・安全領域を越える、未収録文字がある、または必要な情報が入らない場合は生成前エラーにする。値・略称の訂正は元の管理画面へ戻し、出力処理で業務正本を変更しない。

QRは#112の正式な`crs:v1:<credential>`を使い、誤り訂正M、黒・不透明な白背景とする。補間・透過やロゴ装飾をしない。既存資格から描画するだけで、出力・再生成時に乱数資格や確認コードを振り直さない。紛失再発行は#112の別業務を先に完了する。

ZIPは`ticket-0001.pdf`から対象の確定席順で格納し、フォルダー・総合名簿と実行ファイルを入れない。500件を超える場合は利用者が出力範囲を分け、今回の範囲と残り件数を表示する。600人必須・1,000人目標を500人へ縮小しない。

印刷業者向けExcelはA～E列を区画・列・席番号・QR画像・確認コードとし、番号の隣列にQRをセルへ固定する。席番号は先頭ゼロ・文字と記号を含む文字列のまま保持する。QR本体が100%表示で32mmを下回らない列幅・行高を実装時に換算し、保存後のExcelでも縦横比・余白と同じ席への対応を確認する。

### 座席表・運営表と補助出力

座席表は1区画A4横1ページとし、四辺10mm、ヘッダー17mm・フッター9mmを初期の予約領域とする。舞台・席枠と表示番号は共通の印刷配置からPDF・xlsxへ変換し、画面向けカード配置を転用しない。舞台左／上、空間と固定seatId・自由番号を保持する。

番号版は枠内の席番号、名前版は枠左隣の番号と枠内の座席表示名を使う。最大6文字を既存規則の2行で表示し、確保席ラベルも同じ領域へ置く。左上の区画名とフッターの「現在ページ/総ページ」を席や舞台へ重ねない。複数区画はdisplayOrder順で連番とする。

xlsxは1区画1シート、各シートA4横1ページの印刷範囲へ対応する。シート名の禁止文字・長さ・重複は生成用の連番名`section-01`等で解決し、左上には元の区画名を保持する。出力全体のページ番号をシートごとの1/1へ戻さない。セルの幅・行高と印刷設定は編集可能にし、出力後の変更を席設定として再取込しない。

当日運営表はA4横、BD-07の列順と取扱注意・時刻を表示し、ページごとに見出しを繰り返す。手書き欄の高さを確保し、版・席順を他の出力と揃える。匿名集計は締め前の未受付と締め後の未来場を区別し、座席・利用者等の識別子を含めない。

通常CSVのチケット準備状態は現行3項目の「入金済み・券発行済み・券送付済み」を固定順で記載し、廃止した購入の約束チェックを復活させない。任意項目選択CSVはBD-07で許可した選択項目だけを追加し、新しい確認用項目や管理履歴を自動列挙しない。

## DD-235-04 生成・保存と安全性

1. オンラインで現在認可と対象・入力版を検査し、件数・個人情報の有無と保存先の取扱いを確認する。exportIdとスナップショットを固定する。
2. 文字・寸法と対象の事前検査後、端末メモリーで生成する。生成中の取消し・例外と容量不足では一時バッファとURL参照を破棄し、不完全なファイルを保存へ渡さない。
3. 生成・事前検査が完了したら、下記の監査用情報を暗号化IndexedDBへ保存する。同じ版と現在認可を保存直前に再検査し、利用者操作による保存要求の直前状態も永続化してから、ブラウザーへ渡す。端末保存に失敗した場合は渡さない。
4. ブラウザーへの保存要求と実ファイル保存完了を区別し、監査送信前に観測結果を含む不変の送信内容を端末へ固定する。監査だけ失敗した場合は同じexportId・同じ内容で監査のみ再送し、自動再生成・再ダウンロードをしない。中断で観測できなかった結果は不明のまま記録する。

### 出力監査の端末保存と中断復帰（#252）

状態：In Review。比較・提案理由は[ADR-014](../decisions/ADR-014-export-audit-recovery.md)、確認範囲は[設計照合記録](../technical-validation/export-audit-recovery-review.md)へ分ける。通常生成のDB書込み0件は維持し、監査用情報の端末保存と監査の受領を別に扱う。単なるプレビューや未確定の形式選択では監査待ちを作成せず、利用者が出力を確定した操作だけを対象とする。今回の追加は#236・104・110の実装前契約で、動作試験は未実施。

#### 保存する情報と境界

`exportAuditSchemaVersion=1`とし、環境・公演・本人と登録端末、storageEpochごとに分離する。#104の共通IndexedDB保存と#92の所有タブ・ownerEpochを使用する。監査内容は既存の公演・端末専用鍵で暗号化し、形式版・レコード種別と各識別子、phaseとローカルrevisionを認証付き追加データへ結ぶ。更新ごとに新しいIVを生成し、復号後も状態との一致を照合する。別のパスフレーズや鍵の共有方法を追加しない。

| 部分 | 保持する最小情報・扱い |
|---|---|
| 固定した意図 | UUID v4のexportId、環境・公演ID、本人・端末ID、出力種別と件数、対象データ版、選択対象・選択項目を表すダイジェスト、利用者操作の端末観測時刻 |
| 端末内の状態 | phase、ローカルrevision・storageEpochとownerEpoch、暗号化した固定情報、監査送信内容が固定済みならその本文と照合用ハッシュ。復号可能な本文と氏名を検索用メタデータに複写しない |
| 観測と監査結果 | 下表のoutcome、端末観測時刻、固定した監査送信内容、受領確認済みexportId・内容ハッシュとサーバー確定時刻 |
| 保存しないもの | PDF／xlsx／CSV／ZIP本体とBlob、QR生値・確認コード、氏名・任意項目値と保存先パス。対象ID一覧の複写も不要とし、再生成用スナップショットを監査キューへ保存しない |

選択ダイジェストは、確認済みの対象ID順と選択項目・出力条件を既存の正規化JSON規則で固定し、UTF-8のSHA-256を計算する。生成ファイルやQRのハッシュを監査へ保存する用途ではない。ダイジェストを認可・対象存在の証明として使わず、同一意図の照合だけに使う。

暗号化を済ませてから、固定情報と状態を同じIndexedDBトランザクションで保存する。durabilityは既存契約のstrictを要求し、トランザクションの完了後だけ次の処理へ進む。所有権・形式とstorageEpochを毎回検査し、旧タブの後着応答が新しい状態を書き換えない。保存領域の全消去・媒体故障・鍵喪失まで保証するものではなく、検出時は成功表示と保存への引渡しを止める。

#### 状態遷移と再開

| phase | 永続化・許可する処理 | 中断後の扱い |
|---|---|---|
| prepared | ファイル生成・事前検査後に固定情報を保存済み。まだブラウザーへ渡していない。利用者が確定した出力操作の途中状態として保持し、自動では渡さない | 再生成・保存を自動再開しない。引渡し前中断としてnotHandedOffを固定して監査待ちへ進める |
| handoffPending | 現在認可・同一版を再検査し、保存要求の直前状態を永続化済み。この完了後だけブラウザーへ一度渡す | 実際の呼出し直前・直後を判別できないためunknownを固定して監査待ちへ。未実行とみなして自動再ダウンロードしない |
| auditPending | 観測結果と送信内容を永続化済み。この完了後だけ監査を送信する | 内容を再分類・変更せず、現在認可で同じexportIdの結果照会・同じ内容の再送だけを行う |
| auditAccepted | 同じexportId・固定内容と一致するサーバー受領結果を照合し、端末保存済み | 監査受領済みを表示。ファイル保存完了とみなさず、既存の端末回収条件で処理する |

保存要求の呼出しから通常復帰した場合のoutcomeはhandoffRequested（保存要求を渡した）とする。呼出し後に監査用保存を終える前に中断した場合、または結果を確実に観測できない例外ではunknown（出力結果不明）とする。呼出し前の取消し・認可拒否など、まだ渡していないことを確定できる場合だけnotHandedOffを使う。「保存済み」「ダウンロード完了」と断定しない。

ブラウザーへ渡した後の状態保存に失敗した場合は新しい出力を開始せず、保存要求・監査の状態が不明であることを表示する。handoffPendingを残し、再開時にunknownとして扱う。unknownを後から成功へ上書きしない。監査送信内容はauditPendingへの保存時に一度だけ固定し、その前には監査送信を開始しない。

本体バッファと一時URLは、保存処理への引渡しに必要な期間だけメモリーへ保持する。生成失敗・取消しと引渡し後は生成部品の寿命条件に沿って参照を破棄する。終了時のイベントやService Workerへ状態保存を任せず、引渡し前の通常処理で完了させる。対象ブラウザーで利用者操作と永続化の順序を保てることは#236で確認する。

#### 監査受領・認可と回収

監査の正本は同じ公演の`event/exportAudits/{exportId}`とする。不変の監査本文は固定した意図、outcomeと端末観測時刻を持ち、サーバー受領時の確定時刻を別に付ける。観測結果は端末からの申告であり、サーバーが実ファイルの保存・所有を検証した証明にはしない。端末の任意の絶対時刻をサーバー時刻へ置き換えて扱わない。

#110・104は本人と端末の現在認可、対象公演と出力可能な管理役割を要求時に検査する。監査再送は過去の出力の記録であり、当時の入力版が現在版と違うだけで破棄しない。一方で、古い許可証や固定情報があるだけで失効後の書込みを認めない。ZIP等に必要な再認証が切れている場合も、必要な再認証後だけ照会・再送する。

未登録のexportIdは監査本文・サーバー確定時刻と`event/exportAuditHead`の監査revision・最終exportIdを一体作成する。新規受領だけ監査revisionを進め、同じID・同じ本文は既存の1件の結果を返す。時刻・内容と監査revisionを再更新しない。同じID・異内容は拒否して端末案を保持する。照会拒否・通信失敗をnotFoundに置換せず、読み戻した本文・IDとサーバー確定時刻を照合できるまでauditAcceptedへ進めない。

監査の保存で入金・券・席と受付実績を更新せず、出力元の業務版と監査revisionを分ける。#221は公演別バックアップの開始・終了検査と、集合の各公演の必要版へ監査revisionを含める。監査が増えた公演の旧ファイルを、業務版が同じという理由だけで再利用しない。監査本文・headの片側だけを直接更新する要求は拒否する。

停止・失効中は閲覧・復号と通常の照会・再送を禁止し、暗号文を保持してロックする。受付イベント専用の隔離送信権限を出力監査へ流用しない。認可が再び成立してから同じ内容で再送する。別利用者のログインで引き継がず、旧タブ・旧storageEpochからも送らない。
