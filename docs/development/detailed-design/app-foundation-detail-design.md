## 今回作るもの

TypeScriptと通常のDOM APIで共通画面枠を実装し、Viteを開発・ビルドに使用する。新しい画面フレームワークは採用しない。現在の規模では構成を小さく保ち、既存の業務計算を画面ライブラリに依存させないためである。複雑な画面状態が増えた場合は、その時点で別の技術判断を行う。

製品コードの起動確認C-01、公演一覧H-01と公演準備P-01の共通枠を接続する。ローカル評価では架空の公演2件を読取専用の入力例として表示し、一覧と詳細の移動を確認できる。これらは公演保存の正本ではない。公演登録・更新は#111・264、会場席と席設定は#105・106へ接続する。

### データの流れ

1. 同一配布元の`/app-config.json`を取得し、形式・版と環境種別を検証する。
2. IndexedDBに保存した環境識別子と設定指紋へ照合し、成功したトランザクションの完了を待つ。
3. ローカル評価だけ共通画面を表示する。Firebaseを使う環境は#110の認証アダプターが接続されるまで安全停止する。

現在のコードはFirebase SDKを含まず、認証とRTDBへ通信しない。非ローカル環境の形式検証が合格しても、ログイン・端末認可の成功を表示しない。#110ではこの起動境界の後に認証・現在認可を接続する。

## APP258-01 起動設定と環境の結付き

実環境の設定はGit管理しない。初期設定の省略時に既定のFirebaseへ接続する処理を設けない。`pnpm setup:local`は開発者の明示操作で、架空のローカル評価設定を作る。既存ファイルは上書きしない。

| 項目 | 実装する条件 |
|---|---|
| schemaVersion | 数値1。対応外を拒否 |
| appVersion | アプリの互換版と一致すること。初期値0.1.0 |
| environmentId | 小文字UUID v4。公演や利用者の識別子と区別 |
| environmentType | evaluation-local／evaluation-firebase／development／production |
| environmentName | 空白だけ・制御文字を拒否し、1～50文字。画面へテキストとして表示 |
| firebase | ローカル評価では禁止。他の環境ではapiKey・authDomain・projectId・appId・databaseURLを要求する。実際の認証接続は未実装 |

未知の項目も拒否し、認証秘密等の誤混入を避ける。設定取得は同一配布元・no-storeとし、リダイレクトを拒否する。失敗時は業務画面へ進まず、保存データを保持して再設定・管理者確認へ案内する。応答は16,384文字までとする。

環境の結付きは、同じ配布元のIndexedDB `concert-reception-bootstrap`／`settings`／`binding`に保存する。内容は検証済み非秘密設定とSHA-256指紋だけで、利用者・公演の実データと鍵を扱わない。取得・照合と更新は一つのreadwriteトランザクションで行い、並行タブでも別環境へ上書きしない。

指紋は環境ID・種別・表示名、設定スキーマ版とFirebase設定から生成する。配布アプリ版だけの変更は指紋へ含めず、アプリ版の一致を別に検査する。異なる設定への変更は保存データを削除せず停止する。保存不能・破損も成功扱いにしない。

ネットワーク取得自体が失敗した場合だけ、保存済み設定の形式・対応版と指紋を再検査して起動候補にする。HTTP拒否や取得した不正設定から保存済み設定へ戻って回避しない。環境切替・データ初期化ボタンは追加しない。正式な準備・削除は#110等の業務条件へ委ねる。

## APP258-02 共通画面と未保存離脱

共通メニューは公演一覧とアプリ情報を表示し、スマートフォン幅ではメニューダイアログから移動する。公演選択後は公演名・日付と会場を表示する。未接続の業務ボタンは無効とし、準備中と表示する。

接続状態を押すと、状態名と未取得の端末・送信状態を文字で確認できる。ローカル評価をオンライン同期済みや未送信0件と表示しない。`navigator.onLine`だけで接続成功を判断しない。役割・端末準備とオンライン復旧の認可状態は#110・261へ接続する。

[NavigationGate](../../../src/app/navigation.ts)は、後続の編集画面から未保存判定と保存・破棄処理を受け取る。未保存なら「保存して移動」「保存せず移動」「編集を続ける」を表示する。保存失敗・例外では移動せず、保存と破棄の二重要求を拒否する。ブラウザー終了時は未保存判定を標準警告へ接続する。今回、業務編集の偽の保存機能は作らない。各編集画面での実接続・入力保持は#105・106等で確認する。

## APP258-03 静的資産・更新とセキュリティ

`pnpm build`で生成した汎用HTML・JSとCSS、アイコン・manifestだけをService Workerへ列挙する。各内容のSHA-256をビルドで固定し、整合性検証した全資産の取得成功後にインストールする。環境設定はCache Storageへ入れず、検証済み設定の端末内保持と分離する。

| 対象 | 方針 |
|---|---|
| 静的資産の取得 | 同一配布元・GETの固定許可リスト。クエリ付きURLは対象外 |
| 認証・RTDBと出力等 | Workerによる取得・キャッシュなし。設定ファイルも対象外 |
| 新しいWorker | skipWaitingと自動再読込を行わず、作業・送信完了後に全画面を閉じる案内を出す |
| 旧静的キャッシュ | 旧Workerを使う画面がなくなって新Workerが有効化された時だけ回収する |
| 端末保存・鍵 | WorkerによるIndexedDBの変更・削除なし。未受領・鍵の処理は#104・110へ委ねる |

ローカルのビルド確認サーバーはCSPを自己配信へ限定し、unsafe-inline／unsafe-evalを使わない。HTML・設定・Workerはno-store、ハッシュ付き資産はimmutableとする。Referrer-Policy・nosniffとPermissions-Policyも設定する。Firebase接続・カメラの有効化に必要な範囲は、#110・233で再確認する。Nodeサーバーは開発用であり、製品に独自APIサーバーを追加するものではない。

実配信はHTTPSを前提とする。PCのlocalhostはブラウザーが安全な接続として扱う例外を使う。同一Wi-Fi内でもスマートフォンからPCのHTTPアドレスを開くと、PWA・安全な保存を利用できないため起動を拒否する。証明書やOSの信頼設定を自動変更しない。[Service Workerの公式条件](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API)を参照する。

## 確認方法と現在の結果

```powershell
Set-Location C:\dev\concert-reception-system
pnpm install --frozen-lockfile --ignore-scripts
pnpm setup:local
pnpm build
pnpm preview
```

PCでは`http://127.0.0.1:4173`を開く。公演を選択→「公演一覧へ」で戻る→右上の接続状態を開く。ウィンドウを狭くしてメニューを確認し、「このアプリについて」を開く。実装作業用の`pnpm dev`と異なり、`pnpm preview`はビルド済みPWAの動作を確認できる。

| 検証 | 2026-10-21の結果・範囲 |
|---|---|
| 型検査・ビルド | 合格。Windows x64、Node 24.19.0、TypeScript 7.0.2、Vite 8.3.4 |
| 単体・既存回帰 | 150件合格。APP258-T01～05と既存145件 |
| ブラウザー | APP258-B01～09の12条件×PC幅／スマホ幅＝24件合格。Playwright 1.62.1、Chromium 151.0.7922.34 |
| 完全オフライン・更新 | 再起動と画面移動が可能。未受領の架空記録と非抽出CryptoKeyの保全用試験を実施。Worker更新待ちで自動更新・消去なし |
| 設定・セキュリティ | 未設定・不正版・環境変更と保存不能、非ローカルの未接続を安全停止。外部接続なし・設定由来HTML不実行を確認 |
| 画面の画像確認 | PC幅1360×900、スマホ幅390×844で欠け・横方向のはみ出しなし |
| 開発者のPC操作 | 開発用URLと3操作を会話で通知済み。操作結果の回答は未受領 |
| 対象3実機 | iPhone 17・iPhone 13 mini・Galaxy Z Fold8は未実施。スマホ幅の自動試験を実機合格にしない |

ブラウザー試験は`pnpm test:browser`で実行する。Chromiumがない環境では、開発者が`pnpm exec playwright install chromium`で試験用ブラウザーを取得する。既にあるブラウザーは再取得しない。CIの追加・CDや公開は行わない。

### 実機確認へ残る条件

スマートフォンでは、端末が信頼する証明書を使ったローカルHTTPSが必要。`DEV_HTTPS_CERT`と`DEV_HTTPS_KEY`へファイルの絶対パスを指定し、`pnpm preview --host 0.0.0.0`で同一ネットワークから確認する接続口を用意した。証明書の作成・端末への信頼登録は未実施である。公開ホスティングを使う場合は新しい試行範囲・予算を別途提示し、承認前に配備しない。

#258はコードとローカル自動検証の途中成果をPRへまとめ、実機確認と開発者の操作結果を追跡してから完了判定する。依頼者の業務回答は変更せず、#220合格までの本番利用禁止も維持する。
