## 受付前と受付中

| 場面 | 適用する条件 |
|---|---|
| 初回開始・明示再開 | 対象公演の最新確定データ版で準備確認が必要。版ずれを検知したら自動で差分取得し、確認をやり直す |
| 稼働中の安全な変更 | 選択公演の検証済み版で受付を継続し、最新確定版との差分を裏で取得する |
| 旧QR無効化・発券済みの案内先変更等 | 既存の明示停止・全稼働端末の停止確認後に確定する。更新確認後に再開する。停止を確認できなければ確定を保留し、必要に応じて紙で個別対応する |
| 停止・失効を検知 | 既存の停止・隔離条件を適用し、未受領記録を保持する |

安全な変更は、既存のQR判定と案内先の同一性を確定経路で検証できる操作に限定する。例えば既存席の番号・割当・案内を保った未使用の余白調整を対象にできる。操作本文の自己申告だけで安全と扱わない。判定不能な変更は受付中の公開を拒否する。別公演の認可・端末データに変更を波及させない。

差分の安全性は、端末が最後に確認した版から到達版までのすべての更新に適用する。明示停止を伴う更新をまたいだ端末は、途中の安全な更新を根拠に受付を再開できない。既存の再開条件に従って現在状態・認可と最新版の取得を確認する。

## 差分の取得・反映

1. 端末は選択中の1公演の確定版を監視する。版が変わったら同期カーソルから差分だけを取り、同じ公演のダウンロードを重複起動しない。
2. 受付中は、QR判定と受付イベントの暗号化保存を差分適用より優先する。差分を小分けに取得・処理し、ネットワーク待ちや全差分の検証を受付の処理経路へ入れない。進捗・再試行は受付を覆わない表示で案内する。
3. 対象公演、基準版と到達版、件数、参照の一致を確認する。暗号化保存が完了した版だけを一括で公開し、同期カーソルも同じ確定で進める。開始済みの読取りはその時点の版で完了し、次の読取りから新版を使用する。
4. 切断、破損、取得中の新版公開、公演切替では途中版を適用しない。公演切替で旧購読を解除し、遅れて届いた応答は破棄する。失敗時は検証済み版と未送信イベントを保持し、選択中であれば再試行する。再接続時は認可・公演状態を先に確認する。

完全オフラインでは、事前取得した公演状態・認可・期限を既存条件で検査する。同期中に端末が取得できなかった新規情報は管理者照合へ案内する。失効や明示停止に伴う紙受付と、通常差分の取得遅延を分ける。
