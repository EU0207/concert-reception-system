## 用語

| 用語 | 説明 |
|---|---|
| 要件 | システムが満たす必要のある機能、品質、制約などの条件 |
| 機能要件 | システムが「何をできる必要があるか」を示す要件 |
| 非機能要件 | 性能、セキュリティ、操作性、可用性など、機能以外の品質に関する要件 |
| 受入条件 | 依頼者がシステムを完成と判断するための具体的な確認条件 |
| Issue | 作業、課題、確認事項をGitHub上で管理する単位 |
| ブランチ | 他の作業に影響を与えず変更を行うために、履歴を分岐させたもの |
| Pull Request | ブランチで行った変更を確認し、統合を依頼するGitHubの機能 |
| GitHub Flow | Issueごとにブランチを作り、Pull Requestで確認して `main` に統合する開発方法 |
| GitHub Projects | Issueなどを一覧化し、状態や担当者を管理するGitHubの機能 |
| ADR | Architecture Decision Recordの略。重要な技術上・設計上の判断と理由を残す文書 |
| API | 画面や別のプログラムからサーバーの機能・データを利用するための接続方法。画面でボタンを隠すだけでなくAPI側でも権限確認が必要となる |
| セッション | ログイン後の利用者を一定期間識別し、許可された操作を継続するための状態 |
| 本人認証 | メールアドレスとパスワード等により、操作しようとしている人が登録利用者本人であることを確認すること |
| 認可 | 認証済みの利用者について、役割、公演、端末、操作、データに応じて実行を許可または拒否すること |
| 役割割当 | 利用者へ特定公演の主担当、代理管理者、一時管理者、一般受付担当者のいずれかと有効期間を結び付ける情報 |
| オフライン許可 | オンラインで本人、役割、端末、公演、期限を確認した準備済み端末に、公演中の通常操作と公演翌日中までの確認・同期を許可する端末固有状態。固定24時間・48時間ではなく、会場タイムゾーンの公演翌日23:59:59に失効する |
| 会場タイムゾーン | 公演日と期限時刻を解釈するため、会場スナップショットへIANAタイムゾーンIDとして保存する地域時刻の基準。端末の現在設定は期限計算に使用しない |
| 端末停止 | 紛失等の対象となった端末IDだけを無効化し、本人認証に成功しても通常の受付、同期、データ取得、オフライン再準備をサーバー側で拒否すること。同じ利用者の別端末は個別に停止されない限り継続利用できる |
| 隔離領域 | 停止端末に残る未同期記録を正式な受付へ自動反映せず、管理者が紙記録等と照合して採否を判断するまで分離して保持する管理者専用領域 |
| 再認証 | ログイン中であっても、高影響操作の直前にパスワード等を再確認し、現在の利用者本人による操作であることを確かめること |
| メールアドレス列挙 | ログインや再設定画面の応答差から、特定のメールアドレスが登録済みか第三者に推測されること |
| スクリプト注入 | 入力値等へ不正なプログラムを混ぜ、他の利用者の画面で実行させようとする攻撃。一般にXSSとも呼ばれる |
| 脆弱性 | 不正操作、情報漏えい、停止等につながる設計・実装・依存パッケージの弱点 |
| トレーサビリティ | 要件、設計、テストなどの対応関係を追跡できること |
| CI | 変更のたびにテストや静的解析を自動実行し、問題を早期に発見する仕組み |
| CD | 確認済みの成果物を検証環境や本番環境へ継続的に提供する仕組み |
| QRコード | 情報を二次元の図柄として表し、カメラなどで読み取れるようにしたコード |
| 確認コード | QRコードを読み取れない場合に、認証済みの受付画面で同じチケットを照合するための短い文字列。パスワードではない |
| 受付用データ | 既存の購入者名簿から、氏名、座席、必要な状態・例外など当日の受付に必要な項目だけを取り込んだデータ |
| 購入者名簿 | 主催者がシステム外で管理する元データ。住所、電話番号、メールアドレス等を含む場合がある |
| 初回受付 | 対象公演で有効なQRコードを最初に受け付け、来場として記録すること |
| 再読取り | 初回受付済みのQRコードを再び読み取ること。正当な再入場か二重提示かを確認する契機となる |
| 例外対応 | 当日手渡し、現金受領、紛失、座席変更、特別案内など、通常受付と分けて確認・記録する対応 |
| 手動受付 | QRコードを提示または読取りできない場合に、管理者権限を持つ利用者が確認して受付を確定する操作 |
| 競合 | 複数端末で同じQRコードが初回受付として記録されるなど、復旧・統合後に管理者の判断が必要な状態 |
| 無効化 | データを通常利用の対象外にしつつ、履歴を残して必要に応じて復活できる状態にすること |
| 完全削除 | データを復活できない形で削除する高影響操作 |
| 管理者権限を持つ利用者 | 主担当、代理管理者、一時許可など、現在の役割により管理画面と高権限操作を許可された利用者 |
| 当日運営表 | システムを利用できない場合に紙受付へ切り替えるための、氏名・座席等を含む印刷用一覧 |
| 欠番 | 座席番号の並びの途中に、その番号の実在する座席が存在しないこと。画面上へ空間を置くスペースセルとは区別する |
| スペースセル | 通路や座席間の空間を座席表上で表す、座席ではない配置用の枠。来場者割当、QR発行、空席数・座席数の対象にしない |
| オフライン受付 | 通信を利用できない状態で端末に受付記録を保持し、復旧後の統合を前提として受付を継続すること |
| 独立した受付環境 | 他の環境とは別の端末内保存領域と識別子を持ち、受付記録を独立して保持・同期できる検証単位 |
| 事前取得 | 公演前の通信可能な時に、当日必要なデータや画像を端末へ保存して利用可能か確認すること |
| 差分同期 | 前回同期後に追加・変更された情報だけを送受信し、全データの反復取得を避ける同期方法 |
| 論理データモデル | データベース製品やコード上の型を決める前に、業務で扱う情報の意味、関係、制約を整理したもの |
| エンティティ | 公演、来場者、座席、チケット等、業務上ひとまとまりとして識別・管理する情報の単位 |
| 正本 | 同じ意味のデータが複数箇所にある時に、最終的な判断根拠とする記録。本システムではデータ区分と通信状態に応じて明示する |
| 変更不能イベント | 受付や訂正等の発生した事実を、後から上書きせず新しい記録として追記するデータ。本システムでは現在状態と履歴の根拠にする |
| 現在状態 | 変更不能イベントを順序と業務規則に従って読み取り、現在の来場、座席、QR、例外等を表示できる形へ導出した情報 |
| 冪等性 | 同じ送信や操作を再実行しても、1回実行した時と同じ結果になり、同じ受付記録等を重複作成しない性質 |
| 送信キュー | 端末へ保存済みで、オンライン共有の確認が完了していないイベントと再試行状態を端末内で管理する並び。業務イベント本体とは分離する |
| 同期カーソル | 端末が共有先のどこまで差分を取得済みかを示す位置情報。差分を端末へ保存した後にだけ進める |
| 状態導出 | 変更不能イベントの集合と業務規則から、来場状態、未送信、競合等の現在表示を再計算すること |
| 未解決競合 | 矛盾する複数イベントについて、管理者の判断イベントがまだ記録されていない状態。到着順だけでは解消しない |
| 競合確認イベント | 競合する候補イベントを参照し、管理者が判断区分と理由を追記する変更不能イベント。元イベントを削除・上書きしない |
| 同期アダプター | 業務層の共通イベント形式とFirebase等の共有サービス固有API・エラーの違いを変換する境界 |
| 共有確認位置 | 端末のどの連番まで共有先で受領確認できたかを示す位置。締め前の未送信0件確認に用いる |
| 削除記録 | 削除の対象区分、理由、実行者、時刻、結果等を残す監査情報。削除した個人情報を復元できる内容は含めない |
| 締め処理 | 公演終了、全送信確認、管理者確認の後に、公演を終了状態とし端末データ削除へ進む操作 |
| PoC | Proof of Conceptの略。技術方式を採用または本番実装する前に、限定した範囲で実現可能性や制約を確認する検証 |
| Firebase | Googleが提供するアプリ開発向けサービス群。本件のPOC-001では認証とCloud Firestoreだけを検証した |
| Firebase Hostingプレビューチャネル | live公開を変更せず、期限付きの公開URLへ静的Webアプリを配信して確認するFirebase Hostingの機能 |
| Firebase Console | Firebaseのプロジェクト、利用サービス、権限などをブラウザで管理する画面 |
| Cloud Firestore | Firebaseで利用できる文書形式のデータベース |
| Sparkプラン | Firebaseの請求先登録を必要としない無料プラン。無料枠超過時の利用継続を保証するものではない |
| Owner | Google Cloud／Firebaseプロジェクトの所有者権限。権限や請求を含む広い管理ができるため、依頼者側で保持する |
| Google Analytics | Webサイトやアプリの利用状況を計測するサービス。POC-001では目的がないため無効にした |
| PITR | Point-in-time recoveryの略。データベースを過去時点へ戻す機能。POC-001では課金対象機能のため使用しない |
| 追加要望 | 利用者から追加で示された要望。採否・詳細の決定前は受入対象と分離し、決定後は由来を示す要望IDと新しい要件ID・受入条件IDを対応付ける |
