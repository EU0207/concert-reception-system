## 対応状況

CONF-064の依頼者回答により、不参加者も含む名簿画面を「お客様情報」に改名した。メニュー、見出し、詳細、操作案内へ反映し、当日の来場・受付状態を指す表現は維持する。内部の画面識別子と保存処理は変更しない。

CONF-063の依頼者回答により、チェック一覧の画面名を「お客様対応状況」に変更した。「出力」は別画面とし、電子チケットの個別PDFと紙チケットの印刷業者向けExcel一覧を架空データで操作できるようにした。確認画面と模擬結果のみを表示し、実ファイルやQR画像は生成しない。出力操作は対応状況のチェックを更新しない。本番の帳票要件は既存文書と引継ぎ台帳を適用する。

2026-09-30の開発者による表示名の変更依頼で、モックの「出力」を「チケットデータ出力」に改名した。画面の対象と操作は変更しない。本番設計の`P-07 出力`には座席表や補助CSVも含まれるため、このモックの表示名を本番の出力範囲の縮小として扱わない。

CONF-062で依頼者の了承を受領し、お客様への席の割当を示す表示は「席設定」に統一した。メニュー・画面名は「お客様の席を設定」、タブは「席未設定」「席設定済み」とする。「この席に設定」「席設定を確定」を採用し、席替えの表現は維持する。過去の確認記録の名称は当時の表記として保持する。処理と内部識別子は変更しない。

2026-09-29の開発者依頼で「席番の順序」を追加した。横方向は左から／右から、縦方向は上から／下からを選択する。反転するのは各列内の採番順で、列名の並びは維持する。設定の未保存確認と配置保護を既存の処理へ統合した。CONF-060後の追加仕様として、[CONF-061](ui-mock-client-response.md#conf-061-席番の逆順設定の本番採用)で依頼者による本番採用承認を受領した。

会場席編集では「編集内容を確定」を標準の緑色、「下書きを保存」を少し薄い緑色とする。2026-09-28の開発者による表示調整の依頼に基づく。処理と保存境界は変更しない。

追加修正として、6人目を入金済み・未配置へ変更する。来場者管理の案内は、名前の詳細画面と一覧の案内欄から編集できる。変更は既存の名簿保存・未保存確認を通す。会場画像は設定欄から独立した参照領域に配置し、初期倍率で全体を表示する。PCでは画像領域を追随させ、座席キャンバスと見比べながら編集する。

その後の2026-09-29の表示調整依頼で、会場画像の独立パネルを廃止し、「選択」パネルの一番下へ移動した。初期状態は折り畳み、開閉と画像操作を維持する。PC・スマートフォンともに選択情報と画像が同じパネルで上部へ追随する。

同日の開発者依頼で、一般受付担当者の「スタッフ・端末」を非表示にした。自身の端末内データ削除は全役割の「その他」へ移動した。一般受付は他端末の変更と登録の模擬操作を実行できない。未送信削除拒否と2回確認は維持する。端末登録の2ボタンは上下とボタン間に余白を設けた。

2026-10-01の開発者指摘で、2種類の端末登録の意味と役割表示を修正した。一般受付の新端末申請は承認待ちとし、主担当本人の追加端末は関連付けの模擬確認後に主担当・承認済み・未準備とする。管理画面から他端末を準備する操作を外し、準備完了は端末自身の操作結果として表示する。停止は薄い赤、廃止は重大操作の赤で示す。管理画面の他端末データ削除ボタンを外し、廃止では削除未確認の状態を残す。自身の端末内データ削除は「その他」だけで扱う。これらは既存のBD-04・BD-06の端末管理と追加端末設計に合わせたモック修正であり、本番の物理削除を再現しない。

`CONF-065`の依頼者承認により、スタッフ・端末の役割変更を追加した。主担当は代理管理者以下、代理管理者は臨時管理者と一般受付担当者の間を変更できる。画面表示と確定時に対象と変更後の役割を検証する。役割は利用者と公演の単位とし、同じ利用者の端末を追加準備待ちにする。モックは認証とサーバー権限を再現しない。

2026-10-01の開発者による自己端末データ削除の確認を受け、承認済み設計の条件を「その他」に表示した。未送信・隔離記録0件、サーバーの全件受領、管理者による公演の締めまたは端末廃止、オンラインを全て満たすまで削除を拒否する。主担当または代理管理者はモック上で受領と締めを模擬確認できる。実際のサーバー照合や削除は行わない。公演翌日23:59は受付権限の期限であり、削除許可の条件にはしない。

2026-10-01の表示調整で、「当日管理」の端末確認と公演終了のパネルを16px離し、公演終了の2ボタンには共通の間隔を適用した。PC幅と390×844でパネルとボタンの間隔を確認した。操作と画面遷移は変更しない。

2026-10-01の開発者指摘で、利用可能な代替管理端末がない主担当・代理管理者の端末について、「スタッフ・端末」の廃止と「その他」の自己端末データ削除を無効にした。代替端末は承認・準備済みで、停止・廃止・削除されていない主担当または代理管理者の別端末とする。画面表示だけでなく、確認開始と確定時も再判定する。端末喪失時は既存のBD-08-03の環境所有者による復旧手順を案内する。これはモックの追加案であり、本番の例外を含む運用条件は依頼者確認待ちとする。

受付済み・受付不可の確認操作後に受付結果の表示アニメーションが繰り返される不具合を修正した。全体再表示で結果要素が作り直されるため、入場アニメーションを新しい結果の初回表示にだけ適用する。確認ダイアログの開閉と通知の消去では再適用しない。終了アニメーションと500msの再開待機は維持する。

座席キャンバスの表示名は3文字ごとに改行し、6文字なら上3文字・下3文字とした。標準セルを82×78pxから74×72pxへ縮小した。表示用の整形のみで、保存される表示名と席番号は変更しない。共通キャンバスを使う会場席編集・席配置・会場席管理へ適用する。

追加の表示調整として、セル間隔を8pxから6pxへ縮小した。席配置画面で、間隔6pxとセル74×72pxをブラウザーの表示寸法で確認した。

席配置画面の対象選択を「席未割当」「配置済み」のタブに変更した。配置済みの折り畳み欄は廃止し、選択したタブに対応する操作だけを表示する。初期は席未割当とし、件数は不参加を除いて表示する。追随帯のお客様名は選択したタブの対象に合わせる。切り替えで編集済みの配置を変更しない。

## 検証方法

- `node --test mock/scenarios.test.cjs`：状態整合性と誤操作防止の16試験。受付結果の表示、一般受付の操作制限、逆順採番、案内編集、出力対象と状態の非変更、自己端末削除の条件を確認する。
- `node --check mock/app.js` と `node --check mock/scenarios.js`：構文確認。
- `node mock/server.cjs` による静的HTTP配信。ブラウザーで座席の範囲選択と一括採番を操作。
- PC幅と390×844のスマートフォン幅で、選択帯と座席キャンバスの表示を確認。
- ブラウザーでカメラ結果の重ね表示と、結果から確認ダイアログを開く導線を確認。
- ブラウザーで個別既読の未読数3→2→1、席交換後の両者の席番号、画像拡大後の表示領域を確認。
- 追加修正では、6人目の未配置表示と案内の編集・保存後の詳細表示を確認。1440×900では会場画像の全体表示と追随、390×844では画像とキャンバスの縦並びを確認。
- 逆順設定は1440×900と390×844で、列の並びの右隣に表示されることを確認。新規会場で縦方向・下からを選び、上からA-3、A-2、A-1と表示されることを確認した。
- 一般受付へ切り替えた際の管理メニュー非表示と、「その他」の自己端末表示をブラウザーで確認。PCで登録ボタン間の余白、390×844で自己端末画面の表示を確認した。
- 端末登録の2経路を静的HTTP配信で確認。主担当の追加端末が主担当・承認済み・未準備で表示され、「その他」はこの端末だけを対象とすることを確認した。PC幅で停止の薄い赤、廃止の赤、管理画面に他端末の準備・削除操作がないことを確認した。状態整合性の12試験は合格した。
- 役割変更を静的HTTP配信で確認。主担当は一般受付担当者を期限付き臨時管理者へ変更し、対象端末が追加準備待ちになることを確認した。代理管理者は臨時管理者を一般受付担当者へ変更でき、代理管理者以上を選べない。変更範囲と権限喪失時の拒否を含む14試験は合格した。
- お客様対応状況の行選択はチェックボックス24×24px、操作領域44×44pxとした。各対応状況ボタンも高さ44px以上にした。ブラウザーで行選択、確認ダイアログの表示と取消しを確認した。
- 会場席編集の例の切替では、現在の例を操作できない「表示中」の文字で示し、別の例へ進むボタンだけを表示する。切替時の未保存確認は維持する。
- 静的HTTP配信で受付済みの理由確認と受付不可の例外仮登録を操作し、確認後と通知消去後の受付結果のCSSアニメーションが`none`になることを確認。ファイルURLでのブラウザー確認は確認ツールのURL制限により未実施。
- 座席表示名「架空太郎見本」を名簿から設定し、PCと390×844で「架空太／郎見本」の2行表示を確認。標準倍率の74×72pxセルで、席番と各行の表示範囲がセル内に収まることを確認した。既存11試験は合格。
- 席配置のタブをPCと390×844で確認。左右矢印での切り替え、対象者の追随表示、配置後の件数3／2→2／3を確認した。配置と席替えに関する既存11試験は合格。
- お客様対応状況と出力を静的HTTP配信で確認。PC幅では個別PDFの操作が横スクロールなしに見えるように調整した。390×844でもカードが縦に並び、出力ボタンが表示領域内に収まる。PDF・Excelの確認と模擬結果を操作し、12試験が合格した。
- 「その他」の削除条件を静的HTTP配信で確認。初期状態は全件受領と締めが未達で削除ボタンが無効。主担当による模擬確認後は全条件が確認済みとなり、削除の1回目の確認を表示した。自動試験では一般受付による模擬確認の拒否と、2回目の確認後に未送信が増えた場合の削除拒否を確認した。15試験は合格した。
- 「スタッフ・端末」の初期の主担当端末について、代替管理端末なしの警告と廃止ボタンの無効化をブラウザーで確認。「その他」では代替管理端末の条件が未達となり、自己端末データ削除ボタンが無効になることを確認した。自動試験では代替端末の停止・準備解除が確認中に発生した場合も確定を拒否した。16試験は合格した。

## 本番への引継ぎ

セルIDを表示番号と分離し、会場と配置を同じ保存単位で扱う。変更案を先に計算し、発行済み席の変更を拒否する。未発行席に影響する変更は配置解除の確認を通す。配置済みのサンプルは既存番号を維持し、新規会場で自動採番を体験する。

端末の役割と承認・準備・停止状態を分離する。停止はデータ削除を伴わない。未送信・隔離記録がある場合は自己端末内データ削除を拒否する。廃止と回復不能なデータ削除は重大操作として独立した2回の確認を行う。一般受付担当者の新端末は申請→管理者承認、主担当本人の追加端末は既存の承認済み端末との関連付けとして分ける。本番はサーバーの全件受領と締め・廃止の条件成立後に削除する。

本番の永続保存・同期、発行済み席変更時の版確認と旧QR無効化は未実装。#92の中断復帰試験も別工程で管理する。今回の静的モックを本番のトランザクションや復旧試験の代替としない。対象3実機の操作評価とGitHub Pages公開は別工程。

**依頼者に確認してください**
- 最後の利用可能な管理端末の廃止・端末内データ削除を本番でも禁止するか。管理操作を継続できなくなる誤操作を防ぐため、禁止を推奨する。
- 公演の締め後や端末紛失・故障時に代替端末を準備できない場合、環境所有者による復旧を経てから廃止・削除を許可するか。既存の全管理端末喪失時手順と、締め後のデータ削除条件を整合させるため、復旧後に再判定する案を推奨する。
