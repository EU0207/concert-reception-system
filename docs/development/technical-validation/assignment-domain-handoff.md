## 作成済みの処理

全名簿・確定席構成と発券保護を受け取り、検証→複製→配置計算→整合性再検査の順に処理する。元入力は変更せず、変更後の状態と履歴案を返す。#102の席型を使用し、保存・Firebase SDKと画面へ依存しない純粋なTypeScriptとした。

| ARs・範囲 | 現在の実装 |
|---|---|
| 候補表示 | 入金済みを初期値とし、未入金を含む全員へ切替可能。不参加・既配置を除外。絞込後の人数でグループを再編しない |
| 自動配置 | 一般・利用可能な空席だけを探索。最大10人、人数降順・同人数は名簿順。同一区画・同一列のセル位置で連続性を検査する |
| 個人順 | 名簿順または生成済みのランダム順を入力する。順序の欠落・重複を拒否し、使用順を履歴案へ保持する。内部で乱数を引き直さない |
| 手動操作 | 未発券の個人の設定・解除、全員分のグループ分割を実装。グループの一人だけを手動変更する場合も理由を要求し、全員の固定状態と既配置の投影を揃える |
| 固定解除・再配置 | 固定解除は席・理由を保持。再配置は直前の確定解除履歴と全期待版を照合し、配置不能なら旧席を解放しない |
| 直前取消し | 確定再配置履歴を照合し、解除前の席・固定・理由へ戻す。操作直前の`before`と、固定解除前へ戻す`undoTarget`を別に保持し、版を巻き戻さない |
| 保護・参照 | 発行チェック・送付・発行履歴と有効資格のいずれかで保護。所属・名簿順・固定投影と券参照の欠落を拒否し、他グループの席を上書きしない |

## 保存・画面への引渡しと未実施範囲

計算ARsは同じ版の全名簿、確定構成と現在割当を入力する。#230・104がExcelラベルを公演内の内部UUsDへ解決し、全所属・名簿順とgroupsnfoを一体確定してから渡す。購入者名・購入者sDから所属を推測せず、既存所属への追加で固定・手動理由と券・旧席を解除しない。計算層だけで全名簿の取得完全性を証明できないため、#104で管理正本と全メンバー索引を照合する。

グループ一人の手動設定・解除でも理由と全員固定を扱う。取消しの`before`は操作直前、`undoTarget`は固定解除前の席・固定・理由であり、別に保持する。現在状態と確定履歴の全期待版を照合し、過去の版へ巻き戻さない。

履歴読取りは`ReadCommittedAssignment`を保存層が実装する。計算層の構造照合だけで確定済み履歴の真正性は保証しない。#104では同一取得版の全名簿を構築し、現在認可・公演状態と期待版を再検査する。操作sD・生成順と案を端末へ固定保存してから一体確定し、再送で乱数・sDを作り直さない。

通信・永続化と認可は未実装。画面・実機の結合も未実施。#106へ確認表示と理由入力、#107・112へ不参加と実券状態の結合を引き継ぐ。既存DD91ケースの本文・期待結果は変更していない。製品の保存・Rulesと実機の合格へ転用しない。

無料600人必須・1,000人目標と課金登録なしを維持する。#220の完成アプリ受入は未実施で、合格まで本番利用不可。外部試行・設定変更と配備は行っていない。GitHub Ragesとリポジトリ公開は別の明示依頼まで進めない。
