## 結論と確認範囲

個別登録の空groupIdを共通表で全新規行へ要求していた点を修正し、個別登録・Excel空欄とExcel指定ありを区別した。入力ラベルと内部UUIDの対応を公演内で維持し、全名簿の所属と配置用索引を同じ確定へ含める。仕様比較と期待値の机上照合であり、取込器・Rulesと配置計算の動作試験は行っていない。

## 承認済み条件との照合

## 架空例の机上照合

以下のg-A・g-Bは異なる内部UUIDの説明用略記であり、製品へその文字列を保存する例ではない。

| 入力・事象 | 設計上の期待値 | 追加ケース |
|---|---|---|
| 個別1行・Excel空欄1行を同じ購入者へ追加 | 2人ともnull。購入者と連席所属を混同しない | DG251-T01・10 |
| 同じ公演のG-01を2行、G-02を2行 | G-01→g-A、G-02→g-B。各2人の正本・rosterとメンバー索引を一体生成 | DG251-T02 |
| 次ファイルでG-01を1行追加 | g-Aを再利用し既存2＋新規1の3人をプレビュー。別公演の同じ入力とは結合しない | DG251-T03 |
| 001と1、G-01とg-01 | 無断で文字を正規化せず別ラベル。安全検査の不正入力は行エラー | DG251-T04 |
| 応答喪失・並行取込 | 同一操作は固定対応で結果照会。旧版・未登録前提の競合は全体拒否し、再確認前に別UUIDで追加しない | DG251-T05・06 |
| 既存8人＋2人、さらに1人 | 10人は連続席へ配置可能か判定。11人は全体を対象外とし、連席を勝手に分割しない | DG251-T08 |
| 固定・発券済み、または不参加者を含む所属へ追加 | 既存の保護・理由と席・券を維持。全名簿を評価し、残りだけで自動再編しない | DG251-T09 |

直接要求の拒否、一般受付への情報配布禁止、長期保持の期待結果はDG251-T07・11へ、600／1,000人の保存通信量はT12へ追加した。全12件の製品試験は未実施。
