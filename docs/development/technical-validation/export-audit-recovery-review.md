## 結論と確認範囲

生成・事前検査の後に監査用情報を端末へ保存し、さらにブラウザーへの保存要求の直前状態を永続化する案とした。判別不能な中断はunknownとし、監査本文を固定保存してから監査のみ送る。ブラウザー・OSの実保存完了を成功と断定せず、同じexportIdでの再生成を行わない。

本記録は仕様比較と机上照合であり、IndexedDBとブラウザーの中断試験、通常権限の監査受領・再送は未実施。外部試行・実ファイル生成と製品実装は行っていない。

## 既存契約との照合

| 根拠・境界 | 維持・補完した条件 |
|---|---|
| BD-07-01・10、DD-235-04 | 通常生成はDB書込み0。監査用情報の端末保存と監査書込みを分け、ファイル本体・氏名とQRを永続化しない |
| DD-92の共通端末保存、#104 | 公演・本人と端末別の暗号化、strictのトランザクション完了と所有タブ・epochを再利用。終了イベント頼みの保存をしない |
| DD-235の現在認可、DD-96・98 | 監査も現在の本人・端末認可で照合。停止・失効を迂回せず、受付イベントの隔離送信を流用しない |
| 一体保存・同一操作ID | 監査本文を保存後だけ送信し、同じexportId・同じ内容は1件へ照合する。既送信のoutcomeと監査revisionを再送・再起動で変更しない |
| #250の公演集合・バックアップ | 監査headを本文と一体更新し、そのrevisionを必要版と開始・終了検査へ含める。監査だけ増えた公演の旧ファイルを再利用しない |
| 保持・締めと削除 | 未受領監査・鍵は自動回収を保留。サーバー正本は明示削除まで保持し、#221・239の目録へ接続する |

## 実装への受渡しと残作業

- #236は生成物をメモリーだけで扱い、利用者操作・端末保存の順序と対象ブラウザーの挙動を確認する。再出力は新しい入力・exportIdで別操作とし、監査再送と混ぜない。
- #104は4状態の暗号化保存・所有タブと受領照合を実装する。引渡し後の保存失敗、旧epochと監査受領前の回収を試験する。
- #110は現在認可・必要な再認証と、不変監査の直接要求・別人照会の拒否を確認する。#111は回収条件、#221・239は最小監査の目録・保持を接続する。
- #220は出力1回ごとの端末保存量・回数、監査書込み・照会と再送通信量を計上する。範囲分割や複数形式の別exportIdを含めて測定し、600人必須・1,000人目標を省略しない。

未決定の業務判断はなし。監査の通常権限Rulesと結果照会、実機の利用者操作・永続化順序、媒体喪失時の運用は未実装・未検証。課金登録・サーバー生成と新しい失効後送信権限は追加しない。#220合格まで本番利用不可。PR #249の実装は停止したままとする。
