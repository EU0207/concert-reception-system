## 結論

POC-001～POC-004で確認したPWA、IndexedDB、Firebase Hostingの期限付きプレビューを再利用し、座席一覧から生成する簡易座席表、会場画像5枚・合計25MBまでの事前取得、完全オフライン表示、現在席の強調、取得失敗時の代替一覧を検証できる見込みである。

POC-005はIssue #6で予定した最後のPoCである。実機確認と結果レビューが完了した後、プレビューチャネル、3台の端末内データ、ローカル生証跡を限定削除する。その後、検証専用Firebaseプロジェクト本体の削除対象と影響を再提示し、実行直前に別途確認を得てから1回だけ削除する。

本書の作成・レビューまではPoC開始に含めない。依存関係配置、`.gitignore`変更、POCコード作成、合成画像生成、Hosting配信、実機へのデータ保存は、依頼者が本書を確認してPOC-005だけを明示承認した後に開始する。

## 承認を依頼する範囲

明示承認後、次の作業だけを`POC-005`として行う。

1. Issue #6用ブランチの`poc/POC-005/`へ、本番利用を前提としない最小PWAを作成する。
2. 既に使用・固定した依存関係だけを配置し、実行時に外部CDNから追加コードを読み込まない。
3. 架空の複数階・500席の座席一覧と、PNG・JPEGを含む架空会場画像5枚を生成する。実在する会場図、写真、名称、住所は使わない。
4. 画像1枚5MB（5,000,000バイト）以下、最大5枚、合計25MB（25,000,000バイト）以下を許可し、6枚目、1枚超過、合計超過、PDF、拡張子と実体の不一致を拒否する。
5. 事前取得前に端末の概算空き容量を確認し、全ファイルを取得・検証できた時だけ準備完了とする。中断・容量不足時は不完全データを準備完了にしない。
6. 座席一覧はIndexedDB、URLで取得する画像と静的資産はCache Storageへ保存し、保存件数・合計バイト数・対象公演を画面に表示する。
7. 通信を完全に切った状態で、複数階の座席表、5画像、現在席の強調、拡大・移動、小画面表示、Fold8の内外画面と開閉後保持を確認する。
8. 画像取得失敗を意図的に再現し、画像なしでも座席一覧、区画、列、席番号、現在席を表示して受付を継続できることを確認する。
9. ローカル自動試験合格後だけ、既存Firebase HostingサイトのPOC-005専用プレビューチャネルへ最大3回・1日期限で配信する。
10. 匿名化した結果を文書化し、プレビューチャネル、端末データ、ローカル生証跡を限定削除する。
11. 結果レビュー後、検証専用Firebaseプロジェクト本体の削除について実行直前の確認を依頼する。

Firebase方式の採用、本番実装、本番用Googleアカウント・Firebaseプロジェクト、実在データ、liveチャネル配信、Cloud Storage、Firestore、Authentication、Analytics、App Check、Functions、Blaze変更、カード登録は承認対象外とする。

## 対象機能と合格基準

| 対象 | 評価方法 | 合格基準 |
|---|---|---|
| 座席一覧 | 架空の複数階・500席から区画、列、席番号、座席区分を表示 | 指定順で表示でき、一般、車椅子、同伴者、使用不可、確保済みを区別できる |
| 簡易座席表 | 区画・列の順序と席番号の昇順・降順を変更 | 変更後の順序で再描画され、受付操作が継続できる |
| 現在席の強調 | デコード済み架空チケットを選び、該当席を表示 | 対象階・区画へ移動し、色だけでなく枠・記号・文字でも現在席を識別できる |
| 画像形式 | 正しいPNG・JPEG、PDF、拡張子偽装を登録 | PNG・JPEGだけを許可し、PDFと実体不一致を理由付きで拒否する |
| 画像上限 | 5,000,000バイト以下、5枚、合計25,000,000バイトと各超過ケースを試す | 上限内だけを許可し、1バイトでも超える場合と6枚目を拒否する |
| 事前取得 | Wi-Fi接続中に座席一覧と5画像を取得 | 公演ID、件数、合計バイト数、完了時刻を表示し、全件検証後だけ完了になる |
| 容量不足・中断 | 低容量を模擬し、1画像の取得を失敗させる | 準備未完了を明示し、再試行または画像なしの代替一覧を案内する |
| 完全オフライン | 準備後にWi-Fiと携帯回線を切り、画面再読込み・ブラウザー再起動を行う | 座席表、画像、現在席を通信なしで表示できる |
| 代替表示 | 画像キャッシュ欠落状態で対象席を表示 | 画像がなくても座席一覧で区画・列・席番号・現在席を確認できる |
| 小画面・Fold8 | iPhone 13 mini、Fold8外側・内側と開閉後を操作 | 横スクロールだけに依存せず操作でき、開閉後も選択中の席と準備状態を失わない |
| 通信量 | Hosting転送量と端末上の取得バイト数を記録 | 事前取得量を当日20MB上限から分離して記録し、不要な再取得を行わない |
| 端末削除 | 終了画面からPOC-005保存を削除後、オフライン再表示 | 準備状態、座席一覧、画像キャッシュ、Service Workerが残らず、再準備を要求する |

実機のいずれかが用意できない場合、その機種は未判定とする。他機種、エミュレーター、画面サイズ変更だけで代替合格にはしない。

## 実施シナリオ

### P005-01 入力検証と座席表

- 架空の2階以上・500席を生成し、各座席区分と並び順を確認する。
- 5,000,000バイトちょうど、1バイト超過、5枚合計25,000,000バイト、合計1バイト超過、6枚目、PDF、拡張子偽装を自動試験する。
- 画像の拡張子だけでなくMIME型とファイル先頭の識別情報を照合する。
- 現在席を色、太枠、記号、文字で強調する。

### P005-02 安全な事前取得

- `navigator.storage.estimate()`で概算使用量・上限を取得し、必要量に余裕がない時は開始しない。
- 利用可能な端末では`navigator.storage.persist()`を要求し、許可・不許可を結果へ記録する。許可を合格必須条件にはしない。
- 画像は一時キャッシュへ取得し、HTTP成功、形式、サイズ、件数を確認した後だけ本番用キャッシュへ切り替える。
- 構造化した座席一覧、画像一覧、取得完了状態、合計バイト数はIndexedDBへ保存する。
- 中断、容量超過、検証失敗では準備完了を保存せず、再試行と画像なし代替を表示する。

### P005-03 実機の完全オフライン確認

- 対象3機種をWi-Fiへ接続し、画面の「事前取得」を実行する。
- 完了表示後に機内モードをオンにし、Wi-Fiと携帯回線の両方が切れた状態を確認する。
- ページ更新、ブラウザー終了・再起動後に、複数階の座席表、5画像、現在席を表示する。
- iPhone 13 miniで小画面操作、Galaxy Z Fold8で外側・内側画面と開閉後の状態保持を確認する。
- 画像なし代替モードを実行し、座席一覧だけで現在席を確認する。
- 確認後は機内モードを元へ戻す。

### P005-04 終了処理

- 端末ごとの匿名結果JSONを出力し、機種、OS・ブラウザー、件数、バイト数、合否だけを集計する。
- 3台でPOC-005の端末データ削除を実行し、サイトデータと対象ダウンロードを確認して限定削除する。
- POC-005専用Hostingプレビューチャネルを削除し、URL無効化とliveチャネル残存を確認する。
- 結果承認後、Firebaseプロジェクト本体削除の対象・影響・復元可能期間を示し、実行直前に確認する。

## 削除方法と確認

1. 匿名結果、再現条件、プレビューチャネルIDを確定する。
2. 各実機のPOC画面からIndexedDB、POC-005 Cache Storage、Service Workerを削除し、再読込み後に「事前取得が必要」となることを確認する。
3. 各実機のブラウザー設定からPOC-005プレビューURLのサイトデータを限定削除する。
4. Downloads内の`FAKE-P005-`結果JSONだけを確認して削除する。
5. 正確なFirebaseプロジェクト、Hostingサイト、`poc-005-...`チャネルを照合し、そのプレビューチャネルだけを削除する。
6. URLが無効で、liveチャネルが削除前まで残っていることを確認する。
7. `generated-assets/`と`artifacts/raw/`の絶対パスを確認し、POC-005生成物だけを削除する。
8. POC-005結果をレビューし、Issue #6の終了条件を確認する。
9. Firebaseプロジェクト本体の正確なID、含まれる既定Hostingサイト・履歴・設定、復元可能期間を提示し、実行直前の確認後にプロジェクトを削除する。

削除の一部が失敗した場合は対象を広げず、残存状態を報告する。ブラウザー全履歴、端末の他サイト、他のダウンロード、別Firebaseプロジェクトを削除しない。

## 費用0円の根拠と停止上限

2026-09-07確認時のFirebase公式情報では、Sparkプランは支払方法なしで利用でき、Hostingはプロジェクト単位で保存10GB、データ転送10GB/月まで無料である。上限に達したSparkプロジェクトは有料超過せず、新規配信またはサイト提供が停止する。各Hostingファイルの上限は2GBであり、POC画像の5MB上限を十分上回る。

| 指標 | POC-005停止上限 | 無料枠との比較 |
|---|---:|---|
| 1配信の静的資産 | 30MB以下 | 画像最大25MBとアプリ資産 |
| プレビューバージョン | 最大3回、合計90MB以下 | 保存10GBの1%未満 |
| Hostingデータ転送 | 1GB/月で停止 | 10GB/月の10%以下 |
| 実機1回の事前取得 | 30MB以下 | 要件上の画像25MBとアプリ資産 |
| 実機 | 既存3台だけ | 購入、レンタル、有料クラウド端末なし |
| データベース・Cloud Storage操作 | 0件 | 使用しない |

配信前にSpark、請求先未接続、Hosting保存・転送量を確認する。既使用量と停止上限の合計が無料枠の80%に達する見込み、Blaze・請求先・カード登録の要求、有料端末の必要性が生じた場合は費用を発生させず停止する。

## 主なリスクと停止条件

| リスク | 対応・停止条件 |
|---|---|
| ブラウザー保存は保証された永久保存ではない | 容量推定、永続化要求、完了検証を行い、当日も開始前確認と座席一覧の代替を必須にする |
| 端末容量不足・OSによる削除 | 事前取得を中止し、不要な端末データ整理を利用者へ強制せず、画像なし代替で判定する |
| 25MB取得の途中中断 | 一時キャッシュと完了目録を分け、不完全状態を準備完了にしない |
| SafariとChromeの保存挙動差 | 3実機すべてでページ更新・ブラウザー再起動・完全オフラインを確認する |
| Fold8開閉で状態・レイアウトが変わる | 外側・内側・開閉後を別項目として確認する |
| 画像破損・偽装 | MIME型、ファイル先頭、サイズを照合し、不正時は画像なし代替へ移る |
| 公開プレビューURL | 架空データだけを配信し、1日期限と終了時削除を行う |
| 実機が揃わない | 代替合格にせず、その機種を未判定として要件影響を報告する |
| Firebaseプロジェクト削除 | POC-005結果承認後も自動削除せず、正確な対象と影響を示して実行直前に確認する |
| 重大脆弱性 | High/Critical検出時は配信前に停止し、無断更新しない |
