## 照合した条件

CONF-065とBD-04の承認範囲を基準に、本人対応・役割確定と端末ごとの利用開始を区別した。Google連携の比較・採用理由はADR-011、採用する場合の処理とデータ境界はDD-96へ分離した。

| 観点 | 結果と実行上の限界 |
|---|---|
| 役割変更 | 4役割の実行者×現在役割×変更後の64組を照合。主担当の6方向と代理の2方向が許可条件の検査対象、残る56組は拒否。同一役割への再指定は変更なし |
| Google本人対応 | 公式資料は既存UIDへの連携と別UIDで使用中の資格の失敗を説明する。設計はメール一致・別UIDコピーを採らず、変更案に対応するGoogle本人確認を要求 |
| 2つのAuth | 本人Authによる証跡と端末Authによる業務確定を分離。端末の匿名資格へGoogleを連携しない |
| 一体確定・再開 | 役割・監査と結果を共同検査する契約を定義。直接要求の実拒否、Rules受理と競合結果は未確認 |
| 追加準備・降格 | 全端末の準備済み版を役割版と比較。一般→臨時の既存継続範囲を維持し、旧権限の拒否を追加準備まで遅らせない |
| 製品試験 | DD96-T01～18に#110と結合先を指定。全件未実施。Google連携の既知の問題を製品で解消したとは扱わない |

同一役割への要求は64組中の「役割変更を許可しない」側に含める。業務上の無変更として案内できるが、新しい版・監査を伴う変更にはしない。未知の役割と別公演等は64組の外でも拒否する。

変更文書11件の相対リンク744件に不整合なし。既存195ケースの本文を保持し、追加18ケースのID・担当の対応と64組の許可表をコマンドで照合した。`git diff --check`を通過した。これらは文書の確認であり、Rulesを実行した件数には含めない。

## 公式情報と確認範囲

2026-10-20、[Firebaseアカウント連携](https://firebase.google.com/docs/auth/web/account-linking)、[RTDB Rules API](https://firebase.google.com/docs/reference/security/database)と[再認証](https://firebase.google.com/docs/auth/web/manage-users#re-authenticate_a_user)を確認した。UID維持・連携失敗、認証プロバイダー・認証時刻と書込み後状態の参照を設計根拠にした。SDKの実版と実プロジェクト、対象実機の動作は今回確認していない。

## 引継ぎと残条件

#110で製品名前空間の通常権限を実装し、偽装証跡・部分送信と直接読取りを試験する。#104・233の未送信保護、#111の期限後管理と結合する。対象端末のGoogle連携・再認証、暗号化差分と降格後のロックは別の実行証拠を必要とする。
