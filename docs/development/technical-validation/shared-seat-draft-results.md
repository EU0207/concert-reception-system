## 結論と範囲

2026-11-16、開発者がPR #293のコードレビューを承認し、main統合を指示した。承認対象の実装コミットは`e968b4f946a6922dc73dff24ae9fff45f08f1fc4`。#292の共有保存・照会と別端末への一体復元が対象であり、画面接続・確定保存と実機確認の残条件は維持する。

構成形式2と共有用編集情報形式1を分け、通常の本人・端末認可で保存・照会できるようにした。独立した副担当端末へ取得し、その端末自身の鍵で下書きと全画像を一体保存するところまで確認した。端末鍵の複写と追加パスフレーズは行わない。

対象は会場構成である。割当・券保護を含む入力と、来場予定・割当・券の基準版が0以外の操作は送信前に拒否する。これらの共有と確定保存の業務結合は親#104へ残す。通常画面はローカル評価専用のままであり、「下書きを共有」は試験操作を維持する。実認証画面と共有・取込みの画面操作は#263・105へ接続する。

## 保存と公開

| 領域 | 実装した境界 |
|---|---|
| `generations/{operationId}` | 16セル単位・1片64KiB以内の不変候補。区画・座標とセル、表示番号と消費番号の索引を同じ片へ結合する。進捗の飛越しと部分送信を拒否 |
| `sharedDrafts/{operationId}` | 形式1の所属・版と送信照合値、初回採番状態と任意画像指定、旧理由と全画像の参照。編集情報の1件と進捗を一体追記 |
| `references/{operationId}`と世代・画像の参照 | 候補と基準、全画像の版・バンクを保持。予約だけ・片側参照だけの保存を拒否。時間や失効で解除しない |
| `sharedHead`・`sharedOperations` | 検査済み候補・編集情報だけを共有選択版と不変結果へ一体確定。操作者とサーバー時刻を保存。受付の構成と公演管理版は不変 |

構成の上限は共通の`SEAT_LIMITS`から参照する。RTDB Rulesに子件数を返す`numChildren()`はないため、固定枠と追記進捗で件数を検査する。編集情報の件数だけを進めたり、同じ部分を別内容へ置き換えたりできない。

最初の確定構成がない公演は基準世代を空文字・構成版0とし、実際に`head`がない場合だけ許可する。仮の確定世代は作らない。確定構成がある場合は既存の世代・版と`ready`を検査する。共有候補の`ready`は共有用の構造検査完了であり、業務公開・発券保護の検査合格を代替しない。

現在の役割版と端末の役割準備版、公演管理版と暦版を検査する。基準確定版・共有期待版も照合する。受信側へは共有元の基準版を返し、取得時の最新版へ黙って置き換えない。

## 復帰と画像参照

既存の`createSeatDraftStore`で本文を固定し、`createSeatOperationController`経由で送る。低水準のtransportだけを呼んで端末保存を省略しない。保存失敗なら送信しない。応答不明は同じ操作IDの結果照会で復帰する。共有の準備途中は、固定入力と全基準版を再検査した明示再開だけを許可する。確定処理の`preparing`へ、この再開条件を流用しない。

後続共有版へ置き換わった後も、過去の不変結果と候補本文・全画像を照合できる。結果確認で現在の共有先を巻き戻さない。一般受付へ共有候補・編集情報と結果を配布しない。

画像は区画との対応がないものも含め、最大5枚すべてを共有する。枠だけでなく版・バンクとハッシュを固定する。現在画像が差し替わった後も、参照中の旧バンクを管理権限で取得・検証できる。未参照の旧画像と準備画像を一般に読めるようにはしない。参照中の回収は通常権限でも拒否する。

数値キーの画像枠0～4はRTDBから配列で返る場合がある。空き枠を除いた辞書へ正規化し、同じ画像一覧として照合する。

## 端末への一体取込み

`createSharedDraftImporter.replace`は置換の明示確認を必須にする。共有案と全画像を再検証し、受信端末の既存鍵で暗号化してから、`seatDrafts`と`venueImages`を一つのトランザクションで置き換える。

- 旧下書き・全画像と未解決送信を事前検査する。保存直前も版・所属と暗号文を比較し、同時取込みは一方だけ成功させる。
- 保存失敗・失効と競合では部分状態を残さない。未解決の画像送信があれば拒否する。席の固定操作と他公演の記録は変更しない。
- 同じ端末の下書きIDを維持し、新しい端末だけ新規IDを作る。旧理由・任意設定を形式3で保持し、保存形式を降格させない。

共有案が固定した旧画像を明示して選ぶ場合は、新しい画像キャッシュからでもその版へ置換できる。端末のローカル版は進め、暗黙の古いタブの上書きとは区別する。画像本文と区画構成を同じ保存単位にし、旧構成と新画像が混ざらないようにする。
