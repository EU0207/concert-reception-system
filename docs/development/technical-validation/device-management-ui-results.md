## 結論と対象範囲

同じ公演の端末台帳を表示し、承認・停止・停止解除と廃止を確認ダイアログから実行する。変更を暗号化して端末内に固定し、通常SDKの最新認可・期待版検査と一体更新へ渡す。変更#310・[ADR-018](../decisions/ADR-018-current-device-stop.md)の依頼者了承により、使用中の自端末の停止は画面・業務計算とRulesで拒否する。

開始条件は#110の認可・暗号化保存基盤、#111段階Aの受渡しとPR #297の本人認証画面の統合である。スタッフの招待・役割変更、主担当本人の追加端末関連付けと全データ事前取得は親#263に残す。子#308の完了は、親全体や実環境での端末準備完了を意味しない。

## 操作と安全条件

| 操作 | 画面・保存側の扱い |
|---|---|
| 台帳確認 | 現在認可を取得し、管理端末だけへ対象公演の台帳を返す。本人・端末と保存領域の一致を検査する |
| 承認 | 確認後に固定入力を保存し、最新認可と期待版で一体更新する。承認しても役割準備版を更新しない |
| 停止・停止解除 | 使用中の自端末には停止ボタンを出さず、保存側も自己停止を拒否する。別端末の停止・解除は現在認可・期待版と再認証15分の既存条件を使う |
| 主担当端末の停止確認 | 対象と変更前後を確認し、最終確認で影響を再確認して停止する。2段階目を確定するまで暗号化保存・送信しない。最終確認の初期フォーカスはキャンセルとする |
| 廃止 | 元に戻せないことを確認する。管理端末の廃止には、現在役割の準備済み代替端末を選ぶ。主担当は同じ主担当の別端末を要する |
| 廃止後のデータ | 台帳の廃止だけで端末内データ・暗号鍵を消さない。未受領記録の回収と削除の別手順を維持する |

停止や役割変更、通信断の通知では台帳を隠す。セッション・役割と最近の再認証の期限にもタイマーを設定し、古い許可による操作を止める。経過時間は単調時計を用い、保存・結果照会の各段階でも認可を検査する。

失効前に送った操作が後で確定しても、古い応答で台帳を再表示しない。保存済み操作は保持し、許可される結果照会へ渡す。別端末から自端末が停止された後に通常の管理へ戻さない。

## 応答不明と再起動

固定入力は既存の`authorizationOperations`へ暗号化保存する。DB形式や既存のキーの意味は変えない。新しい列挙APIは同じ環境・公演と端末の操作IDだけを取り出し、本文の所属は個別復号で再確認する。別端末・別公演の本文を読み出さない。

1. 固定入力の保存が失敗したら送信しない。
2. 送信結果が不明なら、新しい変更を重ねず「結果を確認」へ進む。照会だけでは再送しない。
3. 再送するときは「同じ操作を再試行」の明示操作を要し、同じIDと入力を使う。SDKは既に確定した結果を優先する。
4. 画面を開き直したら保存済み入力と結果を照合する。自動再送は行わない。

結果が存在せず、対象端末の版が既に変わった入力は再送しない。端末版は単調増加するため、旧期待版の入力を新しい操作へ読み替えない。暗号化した本文を保持し、画面の折りたたみ表示で元の操作・対象を確認できる。現在の状態で改めて確認する。

SDK復元直後はDB接続が未確立の場合がある。その場合の`NETWORK_RECONFIRMATION_REQUIRED`をオンライン成功へ変更しない。接続成立後に利用者が「最新の状態を確認」して回収する。実接続前のキャッシュで管理操作を再開しない。

## 外観とPC確認

[確認済みモック](../../../mock/scenarios.js)のスタッフ・端末画面を参考に、役割と端末状態をカードへ分ける。台帳には端末名の保存項目がないため、今回の表示は役割名と端末UID末尾を併記する。名前を保存する項目は追加しない。未送信・端末内削除状態を未取得のまま0件・削除済みと表示しない。

2026-11-25の開発者レビューで、承認・役割準備・端末状態を色付きの○・△・×へ変更した。確認済みは緑の○だけを表示し、△は黄系で対応理由、×は赤系で停止・廃止を表示する。各項目名と凡例を残し、色だけに依存しない。正常の説明は読み上げ用に保持する。判定条件と保存処理は変更しない。役割準備の○を公演データの準備完了と誤認しないよう、公演データは未確認と明示する。

ローカル確認は架空公演の「スタッフ・端末」から開く。既定ポートなら次のURLである。

`http://127.0.0.1:4173/#/events/00000000-0000-4000-8000-000000000001/devices`

実際のPCレビュー用サーバーを別ポートで起動した場合は、PRにそのURLを記載する。見本は外部通信せず、画面を開き直すと架空台帳を初期化する。実際の認証・端末登録や準備完了と表示しない。主担当の追加端末を通常承認へ混ぜない。

確認する操作：

- 承認待ち端末の承認を取消し、再度承認する。承認済みでも役割準備が未完了と分かること。
- 「最新の状態を確認」で台帳を更新し、停止・停止解除と廃止を試す。廃止後は変更ボタンがなくなること。
- 主担当の端末を廃止しようとすると、同じ主担当の準備済み別端末がない場合は拒否されること。
- 見本の主担当の別端末（末尾`r-second`）では、停止から「最終確認へ」進む。最終確認でキャンセルした場合は変わらず、明示的に停止した場合だけ停止すること。

画面上の「現在役割の準備済み」は役割準備版の一致を示す。公演の確定データ版の事前取得・準備確認を代用しない。

## 試験と結果

| ID | 確認内容 |
|---|---|
| DEVICE308-B01 | PC・スマホ幅で確認・取消しと4操作、廃止の代替端末条件を確認 |
| DEVICE308-B02 | 確定応答を失った後、結果照会だけで回収し二重送信しない |
| DEVICE308-B03 | 未完了入力を再表示し、他の変更で版が変わった場合は保全して再送しない |
| DEVICE308-B04 | セッション期限で台帳を隠し、古い許可で変更させない |
| DEVICE308-B05 | 主担当端末の停止を2段階で確認し、最終確認前の保存・送信を防ぐ。取消し・Escapeで変更せず、最終確認後に同じ対象へ1回だけ送信する |
| DEVICE308-S01 | 通常登録の申請・本人証明から、通常SDKで4操作を確認。端末内保存失敗では未送信。代替なしの自己廃止と一般受付側の直接台帳取得を拒否。自己停止は暗号化保存前に拒否する |
| DEVICE308-S02 | 確定応答喪失と送信前失敗の両方で再起動し、既存鍵で復号した入力から結果照会・明示再試行を行う。二重確定しない |

型検査・Rules照合とビルド、単体・既存モック249件が合格。PC・スマートフォン幅のブラウザー全152件（端末管理8件を含む）と、通常SDKの4件が合格した。SDK試験にはローカルAuth・RTDBと架空資格だけを使う。実Googleの同意画面や実端末の寿命確認は含めない。

変更#310の反映後は、型検査・Rules照合とビルド、単体・既存モック250件、端末管理の画面8件と通常SDK4件が合格した。直接APIのAUTH110-R07で自己停止の拒否、端末状態・版と操作結果の無変更、同じ本人の別端末からの停止・解除を確認した。CONF066・069-R01で自己廃止の代替保護も合格した。DEVICE310-T01は主担当・代理管理者の両方を対象とする。実機受入は含めない。

主担当停止の2段階確認を追加した後は、ビルドと端末管理の画面10件が合格した。見本には同じ主担当の別端末を追加してPCでも操作できるようにした。二重確認は画面上の誤操作防止であり、直接APIに人間の確認を証明する項目を追加する変更ではない。通常SDKの現在認可・期待版検査を維持する。

最終確認だけ、赤系の枠・見出しと停止ボタンを使用する。「重要：主担当端末の業務を停止します」を淡い赤の背景で表示し、色と文言で通常確認と区別する。キャンセルは通常の配色と初期フォーカスを維持する。確認回数と保存処理は変更しない。
