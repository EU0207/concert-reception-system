## 結論と確認範囲

公演別ファイルの暗号化形式1を維持し、既存の独立復旧目録へバックアップ集合の識別と全保持公演の参照を追加する案とした。新しいBだけの復旧成功を世代交代の条件にせず、Aの必要版とファイルを新集合へ含める。比較と机上照合であり、実ファイル生成・削除と外部サービス試行は行っていない。

## 承認済み条件との照合

| 根拠 | 是正と維持条件 |
|---|---|
| CONF-049、REQ-NF-019・AC-031 | 公演前設定確定後と通常・例外締め後の取得を維持。対象公演だけでなく、新集合内の保持公演を照合する |
| CONF-050、BD-08-12 | 次公演の締め後の検証成功後に旧集合を復旧対象から外す。新集合で再利用するファイルと鍵は現行の構成要素として保持し、旧集合だけの不要な複製を破棄する |
| 明示削除までの保持、AC-013 | 公演集合は元環境内の未削除公演を網羅。月数・容量・権限不足を削除理由にせず、全体喪失後の復旧範囲に欠落を作らない |
| 122-Aの正式形式・独立削除証跡 | 公演別形式1と現在認可を維持。個人削除後の旧ファイルを復元禁止にし、目録自体の古さが不明な場合は有効化を拒否する |
| CONF-038、#251の所属対応 | 公演・環境の境界を維持し、別公演の認可を拡張しない。各公演の名簿・グループ対応等も既存の領域目録へ含める |

## 2公演の世代交代の机上照合

以下の集合S1・S2とファイルA1・B1は説明用略記であり、製品のsetId・exportIdにはUUIDを使用する。

| 状態・入力 | 期待結果 | 対応ケース |
|---|---|---|
| S1はA締め後のA1を参照。B締め後、Aは未変更 | S2はA1とB1を参照。A1の実ファイル・鍵も復号照合し、A・Bの隔離復元を確認してから採用する | BK250-T01 |
| S2がB1だけを列挙し、台帳ではA・Bとも未削除 | 台帳との集合不一致でS2を不合格とし、A1と鍵を破棄しない | BK250-T02 |
| A1の所在不明、鍵喪失または復元練習失敗 | S2は未完了。新しいBの成功だけでは旧世代の破棄に進めない | BK250-T03 |
| Aの実績訂正で必要版が進む | A1は再利用不可。訂正後のA2を生成・照合してS2へ含める。既知の新しい版を古い値へ戻さない | BK250-T04 |
| Aの個人削除で旧A1を復元禁止 | 削除後A2の確認までS2を採用しない。旧資料を保持していてもA1を有効な代替とみなさない | BK250-T05 |
| Aそのものの明示削除を確認 | 削除証跡を目録へ保持し、Aの業務参照をS2へ含めない。権限不足や部分履歴削除ではこの扱いにしない | BK250-T06 |
| S2の採用応答が不明、またはB隔離保存中に中断 | 同じ集合・内容で照合・再開し、旧資料を保持する。Aだけで集合全体の復旧完了としない | BK250-T07・09 |
| S2採用後にS1を旧指定へ変更 | A1はS2にも必要なので保持。S1だけの不要ファイル・複製を破棄し、S2は旧目録本文なしで復旧できる | BK250-T08 |

次公演なし、独立台帳の最新性不明と限定復旧、別環境混入・認可はBK250-T10・11へ定義した。全12件の製品試験は未実施。

## 保存量・通信量と未測定事項

全保持公演をR、変更・新規公演をCとする。再利用ファイルは現在必要版と削除境界が一致し、実物を確認できる場合だけRからCを除いた公演へ使用する。

| 経路 | 測定する量・保管対象 |
|---|---|
| 集合生成 | 全公演台帳・必要版の取得と変更公演Cの本文取得、新目録・変更ファイルのローカル生成。再利用参照を理由に台帳取得を0としない |
| 参照検査・復元練習 | Rの全ファイルのローカル読込み・復号、全領域の件数・ハッシュと参照検査。隔離先への試験保存を伴う場合はその送受信も計上する |
| DB喪失後の全面復旧 | Rの全本文を隔離先へ送信し再取得照合する。変更公演Cだけの通信で環境全体を復旧したと扱わない |
| 保管 | Rに必要な全ファイル・目録と別管理の鍵、採用確認前の旧資料と複製。物理的に同じ再利用ファイルを参照ごとに再保存すると仮定せず、実際の複製数を別に記録する |

#220・221は600人必須・1,000人目標で2公演と12公演を比較し、公演数・履歴量、変更公演数と再利用数を記録する。時間・メモリーと媒体容量に加え、RTDBへの送受信・保存を測る。既定の画像・バックアップ2回の予約と他用途を維持し、計画上の通信削減を無料受入の合格へ加算しない。

既存の12公演蓄積・月4公演での無料超過条件は変更しない。バックアップ集合の方式はDBの長期保存容量を減らさず、外部保管や媒体の無制限な無料保証も行わない。不足時は資料を保持し採用・復旧を未完了とする。課金登録・自動削除と公演の除外で成立させない。
