## 結論と実装範囲

#91・96・98の設計承認と#101・168の完了を確認し、#102の対象範囲に着手した。共通型・採番と変更影響の計算をTypeScriptで実装し、型検査と61件の単体試験が合格した。保存・認証と画面の製品実装は未実施で、この結果を全機能の受入合格にしない。

入力は公演全体の構成・割当と発券保護の参照、操作案とする。検証→入力の複製→計算→参照・保護の再検査を行い、変更案と影響を返す。元の入力を変更せず、通信・永続化は行わない。IDはWeb CryptoのUUID v4を使用し、試験では生成元を注入する。認可やサーバー時刻を端末申告で確定せず、保存層の検査へ渡す。

| 実装 | 入力→結果・保持条件 |
|---|---|
| 初期構成・採番 | 5種別→横・縦と通常・逆順の番号。seatとgapだけ消費し、非席はSeat・QRを持たない |
| 行列拡張・再構成 | 追加方向とセル案→既存ID・番号と相対位置を保持する拡張。全体再採番・縮小では割当済みを自動解除しない |
| 手入力・個別編集 | 対象セル・番号と理由→manual席または未割当席だけの番号・位置変更。他席と次番号を変えない |
| 全体スライド | 理由を持たないコマンド→外周が未の場合だけ1セル平行移動。セル・席と列IDを保持し、全未は変更なし |
| 基準から論理座標への投影 | 基準構成と区画の移動量→論理構成。`base`と`logical`を型・実行時に区別し、論理構成への移動量の再適用を拒否 |
| 表示名 | 原値→空白位置または3文字単位の最大2行。Unicodeコードポイントで空白を除く6文字、購入者名は入出力しない |
| 構成検証 | 環境・公演と参照→16区画・256採番列・総4,096セルを合算して判定。不正ID・重複と参照欠落を拒否 |

製品の単体は61／61、型検査はエラー0。ルートのモジュール設定による既存モックへの影響も確認し、モック回帰24／24が合格した。`pnpm test`は両方の計85件を実行する。参照が欠落した割当を未発券と判断せず、不正入力・競合の候補で元の入力を変更しないことを確認した。欠番から手入力席へ変えた消費番号は再採番でも予約し、番号の再利用と消費の返却を防ぐ2ケースを追加した。これらのケースの結合・実機部分は未実施のままとし、元の期待結果を変更していない。

## 後続実装への契約

- #103は型と採番済みの構成を配置計算へ使用する。自動採番と自動配置を混同しない。
- #104は最新の割当・発券保護と全区画を渡し、過去に削除したIDを`retiredIds`へ含める。変更案の`retiredIds`を保持し、将来の新規IDへ再利用しない。過去台帳を計算層が自動復元する機能はない。
- #104・110・111は認可・期待版と公演状態を確定時に再検査する。`duringPerformance`等の計算入力だけで本番業務を許可しない。入力の理由・操作IDと変更前後を監査へ渡す。新しいIDを含む変更案全体を送信前に固定保存し、再送時に計算し直してIDを振り直さない。
- #105・106は変更影響と確認を表示する。未割当席の番号訂正はmanual化し、別列への位置変更でも表示番号を維持する。表示の順序は番号の文字列順へ勝手に並べ替えない。
- #104は同じ取得版の基準構成・区画の移動量を`projectBaseLayout`へ渡し、一度だけ論理構成を作る。#108はこの確定した論理座標を受け取り、移動量をもう一度適用しない。今回の型は保存形式・Firebase SDK型に依存しない。

保存用の文字長は既存検査へ合わせたUTF-16長とし、表示名の6文字は承認済みのUnicodeコードポイント単位とする。区画100・列名64・表示番号64、確保用途100・理由200を超過させない。接頭部は64以内でも、番号を連結した表示が64を超える場合は拒否する。入力・候補が持つ区画数と現在状態は保存側でも再検証する。
