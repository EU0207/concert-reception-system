## 照合した条件

CONF-068と承認済みのBD-04・DD-91の権限表を基準に、臨時管理者に既に許可された9項目を設定対象とした。BD-04の「当日座席状態」は、DD-91で主担当・代理に限定した席移動・交換へ広げず、座席表示名の変更だけへ対応付けた。比較・理由はADR-012、採用する場合の処理はDD-98へ分離した。

| 観点 | 結果と実行上の限界 |
|---|---|
| 設定者 | 4役割の設定者×対象役割の16組を照合。主担当・代理→臨時の2組だけが設定候補。他の14組は拒否 |
| 設定一覧 | 9フラグの512通りを設計モデルで列挙。既知9項目のON/OFFを照合し、禁止12群は全パターンで許可対象外 |
| 初期値・取消し | 初回は従来の許可範囲を保つ全ON。欠損・取消しと期限切れで全ONへ戻さず、明示復元時は新しい版と端末準備を要求 |
| 役割・準備 | DD-96の共通版を設定変更でも増やす。新権限は端末別の追加準備後だけ有効、削除した権限のサーバー拒否は準備を待たない |
| 保持・後着 | オフラインの即時通知不能を維持。発生時の版を保存し、取消し後の後着・未共有連絡は自動確定しない。旧設定のバックアップで権限を戻さない |
| 製品試験 | DD98-T01～21のIDと#110・結合先を対応付けた。全件未実施で、512パターンの列挙を製品Rulesの合格件数にしない |

設定可否の16組は現在の役割だけの照合であり、実際の許可には現在認可・対象公演と再認証も必要。設定の512通りも、データ範囲と業務条件を省略して許可するという意味ではない。

変更文書14件の相対リンク734件に不整合なし。既存213ケースの本文を保持し、追加21ケースのID・担当を照合した。許可9項目と禁止12群、16組と512パターンを設計モデルで確認し、`git diff --check`を通過した。いずれも製品Rulesの実行合格ではない。
