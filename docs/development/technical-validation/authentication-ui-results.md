## 結論と境界

2026-11-25、開発者がPR #297をレビュー承認し、main統合を指示した。承認対象の実装は `de3f2398647a5a08b8dc3fcfc03cbd7349e0a4c9`。最新mainの公開READMEを維持し、ローカル見本の案内をローカル操作手順へ移した。実Google・実メールと業務画面の接続、対象実機の受入は残条件を維持する。

A-01・A-03の本人認証画面を、#110のFirebase Auth部品へ接続する。本人認証と、公演ごとの業務認可・端末準備を分離する。本人認証済みの表示だけでは、公演の読取りや保存を許可しない。

ローカル評価の `#/login` は、外部通信も資格情報の保存も行わない見本である。通常SDKとの接続はローカルAuthエミュレーターで別途確認する。実環境のGoogle同意画面やメール到達は未確認であり、実認証後の公演一覧への接続も含まない。

## 根拠と実装範囲

開始条件は、完了済み#110、レビュー済み#258共通画面、#111段階Aの受渡しである。親#263の全条件完了を開始条件とはしない。

| 契約 | 実装 |
|---|---|
| [BD-04](../basic-design/authentication-authorization-design.md)、[ADR-003](../decisions/ADR-003-role-based-auth-providers.md) | Google、メール・パスワードの本人ログイン。本人と端末のAuthを分離する |
| [BD-06 A-01・A-03](../basic-design/screen-flow-wireframe-design.md) | 入力条件、メール確認・再送、再設定メールの送信。登録有無を成功文から区別しない |
| #110本人認証契約 | 現在の本人による再認証。メール確認の再取得と再認証時刻を混同しない |
| #110端末保存契約 | ログアウトは本人Authだけ。端末Auth、暗号鍵と未送信操作は保持する |

ログイン前に公演データを取得しない。本人認証画面の部品は業務DBを参照しない。非ローカル設定を拒否する起動時の安全停止は維持する。

入力した資格やメール全文を独自の永続領域・ログへ書き込まない。パスワードは送信開始時と画面終了時に画面状態から消す。エラーは許可したコードから短い文へ変換し、SDKの例外本文を表示しない。処理中の重複実行を止め、終了済み画面に遅い応答を反映しない。

## 画面と確認手順

共通画面の配色・余白を維持する。承認済みモックに単独のログイン画面がないため、BD-06のA-01・A-03と既存の入力部品を使う。「このアプリについて」から見本へ移動できる。

1. `pnpm build` 後、`pnpm preview` で `http://127.0.0.1:4173/#/login` を開く。
2. Googleログインで本人認証後の見本を確認する。実アカウントを選択する操作は発生しない。
3. ログアウト後、架空の `fictional@example.invalid` と `Fictional123` を入力する。メール確認・再送と「確認状況を更新」を試す。
4. 「本人確認をやり直す」で再認証の入力を試す。再設定メールも見本では実送信されない。

見本の本人状態は画面を閉じると破棄する。Googleの実同意画面とメール内の操作は、実認証環境の後続確認へ渡す。実際のパスワードやメールを見本へ入力しない。

見本の「確認状況を更新」は、メール確認済みの表示へ進む簡略動作である。実SDKでは未確認のまま更新しても確認済みにはならない。見本の未確認分岐と確認結果の案内は、開発者が今回の変更を保留したため親#263の後続へ渡す。元の入力画面へはログアウトで戻る。

## 試験

| ID | 検査内容 | 結果 |
|---|---|---|
| AUTH296-B01 | PC・スマホ幅の見本で、入力検査からメール確認・再認証・ログアウトまで操作する | 確認済み |
| AUTH296-B02 | 連打、機密情報を含む例外と画面終了後の応答を扱う | 確認済み |
| AUTH296-S01 | 通常SDKで誤資格拒否、確認メール、確認後の更新と再認証を扱う | 確認済み |
| AUTH296-S01 | 登録済み・未登録の再設定メール要求を同じ成功文で扱う | 確認済み |
| AUTH296-S01 | 本人だけをログアウトし、端末Auth・暗号鍵と保存済み未送信操作を保持する | 確認済み |

SDK試験は `tests/emulator/authentication.spec.mjs`、画面試験は `tests/browser/authentication.spec.mjs` にある。既存の認可基盤試験と同じローカルdemoプロジェクトを使用する。エミュレーターのメール操作コードは架空であり、実メールを送信しない。トレースは無効にし、エミュレーターの出力はGit管理外の試験成果へ限定する。

`pnpm test` は249件合格。ブラウザー全144件のうち142件が初回合格し、既存PWA試験2件で期待一覧の不足を検出した。前回の写真変換で追加した配布ライセンス5ファイルを期待一覧へ明示した。静的資産以外の拒否と、環境設定がキャッシュされない検査は維持する。最終ビルドで本人認証4件・修正したPWA2件を再実行し、6件が合格した。通常SDKのAUTH296-S01はPC・スマホ幅の2件が合格した。
