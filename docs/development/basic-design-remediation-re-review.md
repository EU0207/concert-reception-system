## 横断整合の確認

架空データを使う机上シナリオも照合した。これは文書上の期待結果であり、動作試験ではない。

| 架空の状況 | 設計上の期待結果 | 関連ID |
|---|---|---|
| 公演Xの端末Aだけが見つからず、端末Bの全記録は受領済み | Aを停止し、紙照合と損失可能性を記録して例外締め。Aのデータ削除完了は表示しない。次公演Yは開始可能 | C-04、M-05 |
| 公演Xの詳細履歴を手動削除し、来場者Rは来場済み | 削除前に確定したRの来場実績と同版の集計を正本として表示。イベントから再計算しない | C-02、M-01 |
| Rの個人情報削除後に、削除前の暗号化バックアップしか残らない | 旧世代を本番へ有効化せず復旧保留。新世代の検証と旧世代破棄を記録する | M-06 |
| 管理端末2台が通信断中に同じ席を別客へ割当てようとする | 座席変更とQR再発行は実行させず、紙対応へ移す | M-03 |
| 客Sは未入金だがチケットは発行・交付済み | 支払だけ未チェック、発行・交付はチェック済みで表示・並べ替えできる | Q-01 |

- 要件と受入条件は`CONF-049`・`CONF-050`を基に改訂案を作成し、[トレーサビリティ](traceability-matrix.md)へ対応付けた。変更承認は未了である。
- C-01の端末Auth UIDは本人UIDと別である。既存BD-04・BD-05の「同じUIDと端末ID」の記述は旧承認時の内容を含むため、詳細設計では[ADR-005](decisions/ADR-005-device-principal-authorization.md)の認可契約へ全面展開する。
- C-03の画像試験は架空バイト列と試験用の簡易役割Rulesを用いた。最新の`CONF-053`の1MB上限で再実行したが、実画像の可読性とC-01の正式な公演・役割・端末条件は未結合である。
- C-02の削除は無人時に実行しない。C-04の例外締めは紛失端末内の未受領データを消さない。M-01の実績正本は例外締め時の欠落可能性を表示する。
- M-06の旧バックアップは個人情報削除後に復元を拒否し、新世代の検証後に外部保存を含む破棄を記録する。外部ファイルをアプリが遠隔削除できるとは扱わない。

## 再レビュー判定

11件すべてに対応方針と変更文書を割り当てた。CriticalのC-01・C-03は採用した上限・認可の限定条件で中核を確認し、C-02・C-04は依頼者回答で要件の矛盾を解消する案を作成した。Major 6件とQ-01は設計・受入条件への反映案を揃えた。**是正案としてレビュー可能**と判定する。ADR-004～006は採用済みである。基本設計一式の変更承認、UIモック、実装後の受入合格は未了である。
