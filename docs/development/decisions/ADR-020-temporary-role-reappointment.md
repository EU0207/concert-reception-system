# ADR-020：任命時の権限と任期終了後の再任命を一体確定する

| 項目 | 内容 |
|---|---|
| 状態 | In Review（#315・PR #316） |
| 日付 | 2026-11-27 |
| 読者・目的 | 開発者・実装担当者が、承認済みの初期権限指定と再任命を接続する方式を確認する |
| 根拠 | [DD-98-01・04、T02・16](../detailed-design/temporary-admin-permissions-detail-design.md)、[DD-96](../detailed-design/staff-role-change-detail-design.md) |

## 背景

DD-98は、任命確認時の9項目の変更と、任命・最初の設定の一体確定を定めている。任期終了後の再任命も、新しい設定を作り直す経路として試験対象にしている。初期の画面接続は全ONに限定され、既存の有効役割だけの検査では任期終了後の経路が閉じていた。

開発者からの2026-11-27の指摘を受け、既存設計へ接続する。新しい役割、設定可能な操作や設定者の範囲は追加しない。

## 候補と判断

| 候補 | 利点 | 欠点・影響 | 判断 |
|---|---|---|---|
| 任命後に設定を変更する | 既存の設定画面をそのまま利用できる | 任命時に選んだ制限を最初の設定へ含められず、DD-98の一体確定に合わない | 不採用 |
| 選択した9項目を役割と一体確定する | 初版から選んだ権限になる。同じ固定入力で再開できる | 固定入力とSDKへの選択値の接続が必要 | 採用 |
| 任期終了後に一般受付へ戻してから任命する | 別役割間の既存変更を順に使える | 二つの操作・版が必要で、途中状態と応答不明の扱いが増える | 不採用 |
| 終了した臨時役割を新しい任期・設定で一体確定する | 一つの操作結果で新しい任期へ切り替えられる | 期限切れの対象を例外的に扱うため、範囲を限定する必要がある | 採用 |

## 採用条件と実装への影響

- 初期9項目は端末側の固定入力として暗号化保全する。再開時はその選択を使い、欠損した保存済み設定を全ONへ補充しない。RTDBの役割変更案13項目と既存の一体更新境界は維持する。
- 再任命は、現在の役割が`temporary`で任期終了済み、本人役割が`active=true`の場合に限る。公演のスタッフ利用期限より前に、現在の管理者・代理管理者が現在版を確認して操作する。
- 新しい役割版とプロファイルを作り、旧プロファイルと監査は保持する。停止・廃止端末の状態と準備済み版を変更しない。期限切れの一般受付や代理への昇格へ例外を広げない。

解除は、日時編集を伴わず、現在時刻から一般受付へ戻す確認操作とする。一般受付の終了は公演のスタッフ利用期限であり、各端末の追加準備と現在認可の照合は必要なままとする。

新しい外部サービス・依存関係と、本番への配備は追加しない。対象実機と実認証後の業務結合は親#263等へ残す。開始前の役割変更は今回の追加対象ではない。

## 検証

[実装・試験記録](../technical-validation/staff-role-ui-results.md)で確認範囲を追跡する。初回から選択値が反映されることに加え、固定入力の再起動回収と欠損拒否を確認する。再任命では通常の役割許可表を回帰し、停止・公演期限と対象役割の迂回を直接要求でも拒否する。

**依頼者に確認してください**

- なし。DD-98の承認済み条件を実装へ接続する技術判断であり、新しい業務権限を追加しない。
