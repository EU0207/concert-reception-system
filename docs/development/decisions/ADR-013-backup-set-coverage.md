## 問題と判断基準

未削除の過去公演は保持する一方、CONF-050は次公演の締め後バックアップ検証後に旧世代を破棄する。単一公演のファイルしか確認しないと、新しいBの成功でAの唯一の復旧手段を失う。元DB喪失後も、目録にある全保持公演を復旧できる範囲を明示する必要がある。

明示削除までの保持と削除後の復活禁止を両立し、公演別の現在認可を広げない。形式1の単独ファイルを維持し、不要な全本文再取得で無料予算を消費しない。ハッシュだけで台帳の最新性を保証できない残存リスクも維持する。

## 候補

| 案 | 利点 | 欠点・評価 |
|---|---|---|
| A・提案：公演別ファイルと網羅性を持つ独立目録 | 既存形式を維持。未変更公演の検証済みファイルを再利用でき、必要な全公演を追跡できる | 目録・保管先と鍵参照の管理が必要。全参照の検査・復元練習は省略できない |
| B：毎回全公演を1つの暗号化ファイルへ再出力 | 一つの生成物で対象集合を扱える | 正式形式の拡張と全本文再取得が必要。長期蓄積時の生成容量・通信量が増えるため初期案にしない |
| C：最新公演だけを残し、以前の公演ファイルを破棄 | 保管・生成の対象は少ない | 未削除の過去公演を復旧できず、保持要件に適合しない |

## 提案と影響

Aを提案する。独立復旧目録の現行setIdから、必要な全公演のファイル・版と削除境界を参照する。再利用するAも新集合の構成要素として復号・照合し、Bだけの成功で集合を採用しない。公演台帳と各必要版を開始・終了に照合し、変化した場合は旧資料を保持して再準備する。

旧集合の復旧指定は外すが、現行集合の参照ファイル・鍵を破棄しない。旧集合だけの不要なファイル・複製と鍵を手動破棄し、元の公演データを保持する。現行集合は旧目録の本文なしで復旧できるよう、全ファイル参照を独立に持つ。過去世代を順に適用する差分復旧にはしない。

個人削除は旧exportIdの即時復元禁止を維持し、削除反映後のファイルへ置き換える。集合に必要な公演・削除証跡の最新性が不明なら、権限追加や対象集合の縮小で回避せず採用・有効化を停止する。未知の古い正規目録の巻戻しを自動検出できるとは主張しない。

未決定の業務判断はなし。#221で通常権限の全公演台帳取得、集合の採用確認と隔離復旧を実装・試験する。目録・ファイルの実保管手順と媒体喪失、全参照検査の容量・時間は未検証。保管先と復旧キーを失うリスクを監査記録やハッシュだけで解消しない。#220へ長期保存・復旧の測定条件を渡し、無料枠超過時も保持要件を縮小しない。

**依頼者に確認してください**

- なし。公演前・締め後の取得時点と明示削除までの保持を維持する。旧世代の破棄を、未削除公演を網羅する新集合の検証成功へ接続する是正。
