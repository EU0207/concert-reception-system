# ADR-016: 共有下書きの編集状態を欠落なく復元する保存契約

| 項目 | 内容 |
|---|---|
| 状態 | In Review |
| ADR状態 | Proposed |
| 日付 | 2026-11-16 |
| 判断主体 | 開発者 |
| 関連Issue | #290・104・105・244。公演形式は#111、参照の保持・復旧は#221 |
| 目的 | 承認済みの共有保存へ製品を接続する前に、現在の編集状態を欠落なく復元する契約を決める |
| 前提 | PR #287はmainへ統合済み。CONF-074と構成形式2、画像5枠・2バンクの承認済み契約を維持する |

## 結論

未決定。案Aを推奨する。既存の構成形式2は維持し、版を持つ共有用の編集情報を追加する。案Bは構成形式全体を3へ改訂する。承認前に新しい保存形式の製品コードを実装しない。

## 接続前に確認した不足

端末下書き形式3は、区画と画像の対応に加え、各区画の`initialNumbered`を含む製品の編集案を暗号化して保持する。一方、[採用物理契約の参照元](../detailed-design/seat-management-detail-design.md#v4の物理契約案)に対応する共有候補は、構成世代を示す選択版と操作結果を保存する。このままでは編集再開に必要な項目が不足する。

| 項目 | 製品と採用参照元を照合した事実 | 必要な対応 |
|---|---|---|
| 初回採番状態 | 製品の`SectionModel.initialNumbered`は必須。[参照元のencode/decode](../../../poc/GD91-102/layout-model.mjs)は区画ヘッダーへ保存せず、[確定構成の読取り](../../../poc/GD91-104/snapshot.mjs)は`true`を与える | 未採番・採番済みを保存時の値で復元し、席の有無から推測しない |
| 任意の優先画像 | 製品の`imageBindings`は区画IDから画像枠への対応。参照元の構成ヘッダーと共有選択版には項目がない | 全画像の閲覧とは分離し、任意の対応を共有・復元する |
| 公演全体の画像 | #289で、対応のない画像も全区画から閲覧する。枠と現行画像の版は別であり、枠だけでは固定した共有本文の内容を特定できない | 未対応画像を含む最大5枚について版・バンクとハッシュを固定し、参照中は回収しない |
| 旧下書きの理由 | 製品は互換読込みした`editReasons`を保持する。新規の下書き編集では理由を収集しない | 既存の値を落とさず保持する。業務履歴や確定時の理由強制の代用にしない |

ローカルの架空1区画・2セルで確認した。参照元の入力にだけ必要な`assignments`・`ticketRefs`を空配列で補ってから、既存のencode/decodeを適用した。`initialNumbered=false`は復元結果に存在せず、製品の`validateLayout`が拒否した。`true`固定では元の状態と異なった。生成Rulesの区画ヘッダーには同項目と画像対応がなく、未知項目は拒否される。

この確認は既存部品の入出力と生成規則の照合であり、新しい保存方式の成立性試験ではない。ネットワーク・外部Firebaseへの要求は0件。端末データと現行の確定データは変更していない。参照元PoCの旧形式との互換取込は要求しない。

## 候補

| 候補 | 内容 | 利点 | 欠点・影響 |
|---|---|---|---|
| A：構成形式2と共有用編集情報を分ける（推奨） | `sharedDrafts/{operationId}`へ形式1の編集情報を固定し、既存の共有選択版・不変結果と結合する。座標・番号と構成世代の形式2は維持する | 既存の席計算と公演の形式設定を維持できる。下書きだけに必要な情報を確定構成・一般受付へ混ぜずに済む | 新しい枝のRulesと取得が必要。構成と編集情報の一致・画像参照を一体検査する |
| B：構成形式全体を3へ改訂する | 編集状態と画像参照を含む構成形式を定義し直し、公演の`layoutSchemaVersion`も3へ変更する | 構成世代の形式判定へ一元化できる | 公演初期化と取得・確定保存を広く改訂する。出力・復旧への影響確認も増える |

いずれも未確定の案を業務へ反映しない。本文を1つの無制限なJSON文字列へまとめて、構成・件数の検査を省く案は採用しない。端末鍵を別端末へ複写したり、追加パスフレーズを導入したりしない。

## 案Aの保存契約案

### 固定する対象

| 対象 | 内容と検査 |
|---|---|
| 所属・形式 | 形式1、環境・公演と操作ID、現在認証に一致する本人・端末。未知形式・別公演は成功扱いしない |
| 構成との対応 | 候補世代ID・版、基準確定世代ID・版、共有期待版と公演管理版。既存の共有版比較と保持契約を維持する |
| 編集状態 | 区画IDごとの初回採番状態、任意の画像枠指定と旧理由。存在する区画・席だけを参照し、未知の項目を落として再保存しない |
| 画像一覧 | 最大5枠の有効画像について、画像版・バンク・操作IDとSHA-256。優先指定のない画像も含む。削除済み画像は有効一覧に混ぜない |
| 結果との対応 | 固定した送信本文の照合値と不変結果。共有先が別担当の操作で進んだ後も、同じIDの過去結果を照会し、巻戻し・再公開しない |

16区画・総4,096セルと既存の文字数上限を維持する。旧理由など件数が増える情報も上限と分割取得を定め、既存の16セル単位・1片64KiB以内の検査を抜け道にしない。個人情報や現在の割当・券資格を編集情報の権威として複製しない。再開・確定前には最新正本の保護を取得する。

### 処理順と失敗時

1. 下書きと固定した送信本文を、既存の端末鍵で一体保存する。失敗したら送信しない。
2. 現在認可・期待共有版と基準確定版を確認し、候補と基準の保持予約を作る。画像も同じID・版の参照を確保する。予約・参照は時間や失効だけで解除しない。
3. 不変の候補構成と共有編集情報を検査する。画像版・バンクの変更、欠損や競合では公開せず、端末の案を保持する。
4. 共有選択版・結果と編集情報の完成確認を一体で確定する。編集情報なしの共有公開や、共有結果だけの部分送信は拒否する。現確定版と受付向けの投影を変更しない。
5. 別端末では同じ共有結果の構成・編集情報と画像を検証する。既存案の置換確認を行い、端末保存の完了後だけ編集を再開する。画像取得失敗を別画像の同一版だと扱わない。

応答不明では同じIDを照会する。回線復帰による自動確定は行わない。画像が未受領のまま共有済みと表示せず、入力と保持予約を残す。#288の確認用画像の端末削除を、共有先や参照中のバンク削除へ転用しない。
