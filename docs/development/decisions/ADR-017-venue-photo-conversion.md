## 決定と根拠

開発者は、写真選択後に端末内で変換・圧縮し、調整結果を拡大確認して保存する機能の実装を依頼した。PNGとJPEGは比較的明瞭な方を使用する。これを今回の変更承認として記録し、1MBで実画像が読めるという受入合格には扱わない。

元ファイルを1MBで拒否する従来条件を、変換後の保存画像1,000,000 B以下へ変更する。公演全体5枚・合計5,000,000 Bと既存の保存・認可契約を維持する。1MBはFirestoreの単一文書案から継承した業務条件であり、現在のRTDBの絶対上限ではない。容量引上げは実画像比較後の別判断とする。

| 候補 | 利点 | 欠点・判断 |
|---|---|---|
| 利用者が事前変換 | 依存追加がない | スマートフォンから直接登録する操作に合わない |
| ブラウザー標準復号だけ | 実装と配布量が小さい | HEICを復号できない端末が残る |
| 標準復号と端末内HEICデコーダー | 外部送信なしで対応範囲を広げられる | 配布量・メモリーが増える。今回採用 |
| 外部の変換API | 端末負荷を減らせる | 写真の送信先と運用が増えるため不採用 |

## 入力と調整の契約

- 入力はPNG・JPEG・WebPとHEIC／HEIF。拡張子ではなくヘッダーと実際の復号で検査する。HEIFの全コーデック対応は保証しない。動画・RAW・PDFは対象外。
- 元写真は20,000,000 B以下、復号後50,000,000画素以下・各辺12,000px以下。入力容量はWorker起動前にも確認する。画素上限は復号後の検査であり、復号時の全メモリー消費を事前に抑える保証ではない。
- 同じ寸法ならPNGを優先し、上限を超えた場合はJPEG品質0.94・0.90・0.85を順に試す。PNGは白背景へ合成した画像を無劣化保存する候補であり、元の透過やメタデータをそのまま保持する意味ではない。
- 収まらなければ寸法を段階的に縮小する。最長辺1600px未満へは自動縮小せず、元が小さい場合は拡大しない。高解像度を優先した候補選択であり、画像内容の判読性を自動判定する処理ではない。
- 向きを復号時に反映し、Canvasから再符号化する。元のEXIF・位置情報は保存画像へ複写しない。HEICは主画像の静止画だけを使う。

## 処理と確認の境界

専用Workerで調整し、90秒で終了する。閉じる操作と画面終了ではWorkerを終了し、未保存の結果を破棄する。公演・区画と現在認可を結果取得後・保存前に再確認する。失敗・取消しでは既存の登録画像を変更しない。

調整中のダイアログは見出し末尾の点を0～3個へ繰り返し表示する。CSSで透明度だけを変え、領域を固定する。点は読み上げ対象から外し、動きを減らす設定では静止表示する。終了ボタンは「キャンセル」とし、処理結果を保存せず中断する。2026-11-16の開発者レビューによる表示改善である。

調整後の形式・容量・寸法を確認画面へ表示する。「原寸で確認」で画像内をスクロールし、文字と向きを確認できる。「端末に保存する」の明示操作後だけ既存の暗号化保存へ渡す。読めない画像は必要範囲の撮り直し等へ案内する。現在の評価画面の保存は端末内であり、共有完了とは表示しない。

2026-11-16の開発者レビューにより、保存後の閲覧倍率を原寸基準へ変更する。倍率欄には原寸基準の「N%」だけを表示し、「原寸」は保存した画像の1画素を1 CSS pxとして表示する。変換前の撮影画像の寸法を意味しない。最大400%まで拡大し、拡大後はドラッグ・スクロールで移動する。原寸基準の倍率は画面幅を変えても維持し、「全体表示」だけ表示枠に追従する。画像本文や席の保存状態は変更しない。

## 依存と影響

`heic-to@1.6.7`のCSP用ビルドを固定する。内部のlibheif 1.23.7・libde265 1.0.16と、LGPL-3.0系の表示・ソース案内を配布する。追加のサーバー・CDNと課金サービスは使わない。デコーダーが作る背景Workerのため`worker-src`へ`blob:`だけを追加し、`unsafe-eval`は許可しない。変換コードはアプリの静的資産・PWAへ同梱する。

保存先・公開バンクとRulesの容量上限は変更しない。直接APIも従来どおり変換済みPNG／JPEGの上限を検査する。[試験と実機確認手順](../technical-validation/photo-conversion-results.md)へ追跡する。
