# ADR-019: 公演内の最上位役割を「管理者」と表示する

| 項目 | 内容 |
|---|---|
| 状態 | Approved（名称変更・実装レビュー） |
| ADR状態 | Accepted |
| 日付 | 2026-11-26 |
| 判断主体 | 依頼者。開発者から承認済みと明示伝達 |
| 関連 | [変更#311](https://github.com/EU0207/concert-reception-system/issues/311)、#263・308、PR #309 |

## 決定

これまで「主担当」と表示してきた公演内の最上位役割を「管理者」へ変更する。「代理管理者」と名称を揃えるためである。画面、操作可能なモックと現行文書へ適用する。権限の追加・削除や公演内の役割数は変更しない。

| 表示名 | 製品の内部識別子 | 扱い |
|---|---|---|
| 管理者（旧称：主担当） | `owner` | 公演内で唯一の最上位役割。既存の認可・引継ぎ条件を維持する |
| 代理管理者 | `deputy` | 管理者を補佐する既存の役割。権限を変更しない |
| 環境所有者 | 既存の初期設定・復旧の主体 | 公演内の管理者とは別概念。今回の改称対象ではない |

管理者・代理管理者をまとめて指す場合は、必要に応じて「管理権限を持つメンバー」と記載する。役割名の管理者と総称を取り違えず、権限の可否は既存の権限表に従う。

## 比較と影響

| 候補 | 利点 | 欠点・採否 |
|---|---|---|
| 表示名だけを変更 | 保存済みデータと認可を維持できる | 内部識別子との対応説明が必要。採用 |
| 内部識別子も変更 | 表示名と内部名を揃えられる | 保存契約・Rules・既存データの移行が必要になる。名称変更には不要なので不採用 |

`owner`等の保存値、英語のAPI・ファイル名と確認IDは維持する。データ移行は行わない。文書の旧見出しへ向くリンクは、URLまたは互換アンカーを保持する。

## 過去記録と適用範囲

議事録と依頼者回答の原文、旧PoCの記録は改訂しない。これらと過去のGitHub投稿に残る「主担当」は、現在の管理者を指す。次の原文は旧表記を保持する。

- `docs/client/meeting-notes/2026-08-30-initial-requirements-interview.md`
- `docs/development/ui-mock/ui-mock-client-response.md`
- `docs/development/technical-validation/poc-003-approval-request.md`
- `docs/development/technical-validation/poc-004-approval-request.md`
- `docs/development/technical-validation/poc-004-result.md`

既存文書の役割名の改訂は、承認時の権限や判断主体を変更するものではない。停止・廃止の使用感は、端末準備と受付同期の接続が進んだ段階で改めて確認する。名称変更の試験を、その実業務の受入合格として扱わない。

## 確認

製品・モックの旧表示名の残存、内部識別子と認可条件の無変更を確認する。型検査・Rules照合とビルド、単体・ブラウザーと通常SDKの関連試験を行う。正式な名称変更PRはPR #309の後に統合する。
