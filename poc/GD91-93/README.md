[shared.mjs](shared.mjs)は共有先の世代と、基準世代ID・版を同じ操作結果に記録する。[shared-base-rules.mjs](shared-base-rules.mjs)で最新基準との一致を検査する。受付向けの確定座席表は変更しない。

確定座席表が進んでも、選択中の共有候補と基準世代の回収を拒否する。共有先の置換後も、他端末の世代参照があれば候補を保持する。参照の明示解除後だけ上限付き回収を再開でき、操作結果は残す。

- [共有保持9群](artifacts/validate-summary.json)：旧候補で基準世代の回収開始が通る不足を再現。新候補では基準欠落・不一致と部分送信を拒否した。別端末による参照解除、古い版と削除中の公開も拒否する。
- [既存参照12群](artifacts/regression-summary.json)：GD91-92の試験を、新しいRulesへ接続して再実行。未解決案・端末失効時の保持と、結果解決後の回収を維持した。

共有の結果照会は読取りだけで、後続の共有先を巻き戻さない。同じIDの別内容を成功扱いしない。今回は実通信切断・IndexedDBや実機を試していない。他端末の保持は既存の世代参照形式を使った検証で、共有再開画面との接続ではない。

共有アップロード中・応答不明の候補の予約、受付キューの参照と全業務予算は残条件。本番コードと外部Firebaseは変更しない。今回の結果をGD91-92の外部合格へ拡張しない。

## 再現

既存POC-004の依存関係を使用し、追加導入は不要。`generate.mjs`でRulesを生成し、本フォルダーの`firebase.json`でdemoプロジェクト`demo-concert-seat-gd91-84`のAuth・Database Emulatorを起動する。

`validate.mjs`、`regression.mjs`を順に実行する。各試行は全拒否Rulesと空ルートを再取得する。`audit.mjs`で原データ・ソースと生成Rulesを照合する。実行後にEmulatorを終了する。
