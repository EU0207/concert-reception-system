# GD91-148 移行後訂正の履歴参照

状態：In Review。TECH-DD91-118-Aの継続。通常の取込6群だけでは、移行後の訂正に必要な関連付けを保証できないため確認した。

## 確認した制約と候補

現行の訂正Rulesは、参照IDから元端末の過去記録をたどる。最小fixtureでは参照なしで401、`active:false`の参照ありで200となった。現在の主担当による訂正で実績と集計が一体更新され、元の締め結果は保持された。未登録の旧匿名端末は、取得も過去イベントの変更も拒否された。[診断結果](artifacts/lineage-summary.json)は本文をownerで前提投入した依存関係の確認であり、正式な取込の合格ではない。

v2候補では、参照を過去の関連付けとして保持し、移行先で全件を無効にする。元参照に対応する世代の稼働用ピンも移さない。元の業務ハッシュと参照ハッシュを残し、元の端末台帳も履歴として分離する。旧役割・端末とセッションを登録する処理は追加しない。

元データは変更せず、変換後の本文ハッシュと元データの照合値を分ける。v1の全件同値コピーへ含めず、形式名を`gd91-native-rtdb-closed-v2`へ変える。共有案と旧Firestore形式は引き続き未対応であり、有効化しない。

node poc/GD91-148/normalization-test.mjs

RAMの正規化モデルは8不正入力を拒否し、原本が変わらないことを確認した。[モデル結果](artifacts/normalization-summary.json)を参照する。モデルだけで業務データの全形式成立としない。

合同試験は、通常の4人の締め後に、元端末の残存記録を主担当の許可で通常受領する。未照合のまま原本を固定し、v2へ変換・取込する。公開後、現在の主担当が紙原本との照合を表す通常の訂正要求を送る。要求の部分欠落を拒否し、元の締め結果と現在の集計を区別して保持する。元端末のAuthを引き継がず、過去イベントの改変も許可しない。

## 結果と限界

[合同試験](artifacts/local-summary.json)は4人・8登録端末、23領域・89片で6群が合格した。移行後の通常訂正も成功し、要求7部分をそれぞれ省いた更新を拒否した。現在の操作主体と新しい訂正時刻を記録し、元の締め結果と変更不能イベントを保持した。締め後に受領済みで未照合の隔離記録を移したもので、未送信キューや結果不明の操作を無視した移行ではない。

現行候補の件数情報3枝には、参照先の旧UID一致だけで未登録端末の読取りを許す経路があった。148では既存の現在認可または期限付き回収許可の条件も検査する。最小fixtureで旧UIDの取得を200から401へ変え、現在の管理者は取得できた。停止端末の正規の回収条件を一律に禁止する変更ではない。

認可27反例とコピー索引の反例も合格。[331ソース照合](artifacts/audit-summary.json)が一致し、Rules 9,851,885 Bはローカルで受理された。HTTP本文は要求13,921,102 B・応答8,367,519 B、要求1,612回。故障注入と再取得を含み、TLS・請求や端末20MBの判定へ使わない。元・先の全拒否Rulesと空データ、Auth 0件を確認した。追加外部試行0件。

最初の前提生成では、他SDKの参照を管理者が読めない条件と、締め後許可に元端末の停止が必要な条件を修正した。元端末の停止はowner前提投入である。次にブラウザー遷移先がv1のまま残るハーネスを修正した。先行失敗を最終結果へ加算しない。

再移行時の来歴継承、イベント再計算と利用者の手動削除は残条件。通常訂正は隔離記録の採用に限定され、一般的な紙入力や来場取消しの全条件ではない。600／1,000人の取込と請求、全形式移行と方式採用の合格を宣言しない。本番実装・配備なし。
