# GD91-116 区画数と採番列の初期上限

状態：Approved（PR #216、2026-10-17）。読者：開発者・設計担当者・テスト担当者。#167条件1の入力境界を対象とする。本番実装と外部接続は行わない。

## 結論と適用範囲

2026-10-17、開発者がTECH-DD91-108-Aを承認。初期版の上限を1公演16区画・1区画256採番列とする。総4,096セルは維持する。横採番では行数、縦採番では列数を数え、両方の寸法を一律256へ制限しない。区画名と舞台位置の業務回答は変更しない。

[policy.mjs](policy.mjs)を保存前の計画と取得予算へ接続した。超過した編集も端末下書きへ保存してから共有・確定を止める。取得上限の上書きによる迂回は通信前に拒否する。保存片と席IDの形式は変更せず、将来は設定と追加検証で拡大する。

[generate.mjs](generate.mjs)はGD91-113のRulesに境界を追加する。候補の作成だけでなく、旧Rulesで保存済みの過大候補を共有・確定する操作も拒否する。認可と操作結果の保持は維持する。未解決参照がある旧候補は保持し、参照なしの候補だけ通常の回収で削除できる。

## 確認結果

| ID | ローカルEmulatorで確認した内容 |
|---|---|
| B01～03 | 16区画、横256列と縦256列を通常権限で初回保存・公開・取得 |
| B04 | 17区画の直接宣言を拒否し、公開版を保持 |
| B05～06 | 画面側検査を迂回した横・縦257列を拒否。失敗候補を通常回収 |
| B07～08 | 旧Rulesで成功した17区画・257列の確定要求を、新Rulesでは同じ内容のまま拒否 |
| B09～10 | 同じ比較を共有下書きでも実施 |

B07～10では未解決参照による回収拒否も確認した。参照なしの別前提をownerで復元し、通常回収を確認する。ownerによる復元は試験前提の切替であり、業務上の強制解除の合格とは扱わない。

通信なしの方針検査10条件も合格。[audit.mjs](audit.mjs)は実行ソースを現在ファイルと照合し、Rules変更が3か所の追加検査だけであることを確認する。[結果](artifacts/audit-summary.json)。600／1,000人の通信測定は変更前のGD91-113による[GD91-115](../GD91-115/README.md)の別証拠であり、本Rulesでの再実行とは扱わない。

初回は既存の公開版を汎用の初回公開操作で置き換えようとしてB01が拒否された。既存の構成編集契約どおりの動作であり、Rulesを緩和せず初回作成の前提へ修正した。失敗時の結果は[最初の記録](artifacts/first-failure-summary.json)と[診断記録](artifacts/diagnostic-failure-summary.json)に保持する。最終10群では終了後の全拒否・空試行根も確認した。
