## 処理と結果

[model.mjs](model.mjs)で確認済みの変更案を作り、[lifecycle-rules.mjs](lifecycle-rules.mjs)が最新認可・公演版と業務状態を照合する。席の正逆参照・投影と券を、操作結果と同じPATCHで確定する。入金は独立し、QR生成だけで発行・送付チェックを更新しない。

未割当の記録が無い場合は、取得済みの公開構成で席と確認できたセルだけを未割当と扱う。初回割当時に必要な正逆参照と投影を作る。存在しない席や通路を割当対象にできず、読取り拒否を「割当なし」へ置き換えない。

不参加は席を解放し、現在資格と確認コードを無効化する。来場記録・旧資格は保持する。復帰では券を変更せず、再割当後の生成で次cycleを開始する。閉じた券を新しい席の発行済み保護へ流用しない。

### 旧QR識別の修正

[修正前診断](artifacts/pre-binding-probe.json)では、復帰前後の版がともに1となると、版だけの旧要求が受理された。[中間コミット](https://github.com/EU0207/concert-reception-system/commit/75a5f5817a2f08dbe771e4f92e7a9585f6052e95)へ旧ソースと22群を保持し、最終合格へ加算しない。

[receipt-rules.mjs](receipt-rules.mjs)はschemaVersion 2で資格ID・cycle・版を現在券と照合する。旧形式・旧cycleとID混在を拒否する。生成済みの有効QRは、発行チェックを外しても無効にしない。[sdk-adapter.mjs](sdk-adapter.mjs)は券の確定スナップショットと送信内容を照合し、操作IDがあるだけで成功にしない。登録項目は変更不能な正本で照合し、氏名を操作履歴へ複写しない。氏名の訂正等を接続する際は、この前提も再評価する。
