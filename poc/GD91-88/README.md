## 処理と制約

`model.mjs`は変更案を作り、`lifecycle-rules.mjs`は最新の認可・公演版と業務状態を照合する。席の正逆参照・投影と券を、操作結果と同じPATCHで確定する。入金チェックは独立し、QR生成だけで発行・送付チェックを更新しない。

不参加は席を解放し、現在の資格と確認コードを無効化する。来場記録と旧資格の履歴は保持する。復帰では券を変更せず、再割当後の新規生成だけで次cycleを開始する。閉じたcycleの券を、現在の席の発行済み保護へ流用しない。

[修正前診断](artifacts/pre-binding-probe.json)では、旧・新資格の版がともに1となる場合、版だけの旧要求が受理された。これは隔離候補の未達であり、22群の合格を全業務合格へ拡張しない。修正前のソースと結果は中間コミットへ保持する。

公演開始・停止と登録済み端末はownerの前提投入。`stopConfirmed`は申告値で、実端末の停止・未受領キュー解消の証拠ではない。全員一括配置・緊急編集と回収参照は未接続。#167の4条件は未完了、600人の無料成立・#168の採用を宣言しない。

## 再現

PowerShell 7で既存のdemo Emulatorを使う。外部接続は実装しない。

```powershell
node poc/GD91-88/generate.mjs
node poc/POC-004/node_modules/firebase-tools/lib/bin/firebase.js emulators:start --config poc/GD91-88/firebase.json --project demo-concert-seat-gd91-84 --only auth,database
```

別ターミナルで`node poc/GD91-88/validate.mjs`を実行する。修正前の`binding-probe.mjs`は、中間コミットのRulesでだけ再現する。通常の再現手順に旧候補の配置を混ぜない。
