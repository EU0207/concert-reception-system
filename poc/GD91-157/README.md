# GD91-157 現在形式の再移行と来歴継承

状態：In Review。#168・TECH-DD91-118-Aの残条件を対象にする。PR #227は2026-10-19に開発者がレビュー承認し、mainへ統合した。統合コミットは`957b6daac68081a4eac1e5c1bdfec626fc0dc667`。方式全体の採用ではない。

## 作るものと理由

締め済みの現在形式を再び取り込む変換器を追加する。既存148の変換器は`migrationOrigins`と`imports`を未知ルートとして拒否する。これらを無条件に除去すると、以前の取込来歴を失う。

過去の取込記録は`migrationOrigins/importArchives/{exportId}`へ平らに保存する。末端のパスをUTF-8の16進表記のキーにし、元の値を保持する。履歴の階層は移行回数で深くならない。各記録の復元後ハッシュは`importArchiveHashes`と比較する。履歴は監査用で、現在の認可に使用しない。

## 処理とデータの流れ

1. 現在の取込が公開・複製回収まで完了したことを確認する。目録・受領記録と許可切替の履歴を照合する。未完了や未知項目は拒否する。
2. 元の締めで使った端末台帳を保持する。現在の役割・端末とセッションは移さず、過去の取込記録を来歴へ追加する。既存の来歴を入れ子に包み直さない。
3. 通常のv2取込へ渡し、全領域を再取得して公開する。現在の管理者を再準備し、実績を過去の受付・訂正から再計算する。

wire形式は既存の`gd91-native-rtdb-closed-v2`を使用する。`migrationOrigins`の履歴項目を拡張した候補であり、旧変換器の対応完了を意味しない。生成Rulesと通常の取込・公開経路は155から変更していない。
