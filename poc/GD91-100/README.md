# GD91-100 締め後回収と実績訂正の保全

状態：Approved。読者：開発者・設計担当者・テスト担当者。#167の保持・回収条件を同じ検証単位で継続する隔離PoC。本番方式は未採用。TECH-DD91-092-Aの外部12群と後処理を完了し、PR #203は2026-10-15に開発者がレビュー承認・main統合。承認は本書の限定結果に限る。

ADR-004・CONF-049とBD-08に従い、例外締め後に発見した端末の記録を自動受領しない。管理者の明示照合と、締め後の実績訂正を通常受付から分ける。失われた端末の受領・物理削除を完了扱いにしない。

## 基準候補の診断

`closed-baseline.mjs`はGD91-99のRulesと自動隔離送信を変更せずに使う。公演締め・紛失端末状態は前提投入し、締め後の未送信記録が自動で隔離受領されるかを確認する。業務上の許可を示す試験ではない。

[診断結果](artifacts/closed-baseline-summary.json)は締め後の隔離自動受領を再現した。自動採用は拒否できるが、ADR-004の自動受領禁止を満たさない。修正前のソースを`d98807a`へ保持した。

## 保存と確認の契約

| 操作・データ | 契約 |
|---|---|
| 締め後の隔離送信 | 管理者の回収許可がなければ新規受領を拒否。既受領結果の照会は維持し、未送信と鍵を端末へ残す |
| `postClosePermits`・`postClosePermitHeads` | 最近再認証した主担当・代理が、停止端末と参照・連番範囲を指定。理由・紙確認と最大15分の期限を保存。許可履歴と現行の指示を一括保存し、過去許可を上書きしない |
| `lossDeclarations` | 未受領件数は不明、端末削除は未確認として不変の損失記録を残す。後から回収できても当初の判断を消さない |
| `postCloseCorrections`・`actuals`・`actualTotals` | 採否・管理者受付イベントに、締め後訂正と実績・集計を一体保存。閉鎖実績のcycleを照合し、来場済みなら加算0。理由は採否履歴だけへ残す |
| 最終連番と参照解除 | GD91-99の元端末による最終連番・全件判断と監査を維持。別の回収不能端末は解除せず、元記録を保持 |
| 端末の固定案・結果 | 非抽出鍵で送信前に保存。応答不明・再起動後は同じIDを照会し、許可・受領と実績訂正を重複させない |

実績と集計は`partition`ごとに分け、訂正した人と対応集計だけを更新する。全体を毎回書き直さない。パーティション数は製品上限の決定ではない。

### 手順と後処理

1. 専用プロジェクトの所有者・請求先未登録、全拒否Rulesと空DB・Auth残数0を確認。元の認証設定・許可ドメインをGit管理外へ保持。
2. Google・メールパスワード・匿名認証を一時有効化。本人Googleログイン後、架空本人1・匿名端末3を作成。メール送信・許可ドメインの変更はしない。
3. `common-closed.mjs`の12群を比較。管理者照合・監査解除に、締め後の自動受領拒否、明示回収と実績・集計の一体訂正を接続する。架空2人、締めと実績スナップショットは前提投入。
4. 全拒否Rules・所有試行根とDB全体の空を再取得。追跡した5Authだけを削除し残数0を確認。認証設定を復元し、許可ドメイン・請求先未登録を再確認。Googleアカウント自体は削除しない。

通常処理は240呼出し未満で止め、60を後処理へ確保。観測JSON要求・応答20MiBを停止目安とするが、SDK内部通信と実課金量の上限証明ではない。認証情報はメモリー、設定・UID台帳はGit管理外だけに保持。失敗時も自動再試行せず後処理へ進み、未解決台帳・終了済み結果があれば再実行しない。課金・公開・3,000人試験は行わない。
