# GD91-43 区画追加・差替えの接続検証

## 目的と範囲

読者は開発者・設計担当者・テスト担当者。状態はIn Review。
区画単位の構成と、公演全体で一つの席割当を接続する論理計画を確認する。
本番アプリケーション、Firebaseの新しいRulesと削除処理は実装しない。
正式な契約と主要試験は[詳細設計](../../docs/development/detailed-design/seat-management-detail-design.md#gd91-43-区画追加差替えの公開接続契約)へ置く。

## 再実行

リポジトリ直下から既存Node.jsで順に実行する。標準ライブラリーのみを使用し、依存追加・ネットワーク接続はない。

```text
node poc/GD91-43/tests/plan.mjs
node poc/GD91-43/analyze.mjs
```

- [計画処理](plan.mjs)は公演日前・準備中の区画追加と差替えだけを扱う。完全な取得済み論理スナップショットを入力し、新しい計画を返す。入力を変更しない。
- [計算試験](tests/plan.mjs)は24シナリオ。GD91-07の区画検査を再利用し、他区画・割当と券参照の保持、競合とID再使用を確認する。500人は架空ID。maxCells=10000は試験条件であり製品上限ではない。
- [静的照合](analyze.mjs)はGD91-42の単一区画前提と既存予算を読み取る。公開区画の照合を既存経路へ単純追加すると、要求21参照・文書別11参照になる例を確認する。

結果は[計算JSON](artifacts/plan-summary.json)と[静的照合JSON](artifacts/contract-analysis.json)に出力する。実行前後のLF正規化ソースハッシュを照合する。静的照合は計算JSONを参照するため、再計算後は静的照合も再実行する。

## 未検証範囲

論理スナップショットのschemaVersion=1はFirestoreの保存形式ではない。業務形式10の置換や次の形式番号の採用を意味しない。
区画モデル内のassignments・ticketRefsは空とし、業務参照は公演全体の入力へ集約する。
最初の新規区画は全セルをunsetから作り、その後の編集済み案を公開計画へ渡す。

差替えの計算は公開境界の検査であり、舞台・名前変更を世代コピーへ変更する指示ではない。
個別編集・行列拡張とスライドは別経路で確認する。当日操作の新しい制限は追加しない。
認可・サーバー不変条件と物理保存容量は未検証。旧世代の物理回収、IndexedDBと実機も未確認。
GD91-42の63件は当時の結果を静的に照合し、今回の再実行件数へ数えない。
