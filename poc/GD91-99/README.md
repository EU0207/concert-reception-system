# GD91-99 受付の共通連番と照合完了の保持契約

状態：In Review。読者：開発者・設計担当者・テスト担当者。#167の残条件を同じ検証単位で継続する隔離PoC。本番方式は未採用。外部はTECH-DD91-091の判断待ちで未実行。

通常と隔離で保存先が分かれても端末・公演単位の連番を共通にする。イベントIDの全体索引と連番の受領先を同じ確定へ結び、欠番・重複と復旧後の番号再利用を拒否する候補である。過去のGD91-98の証拠を保持し、新候補の合格へ流用しない。

## 保存と解除の契約

| データ・操作 | 契約 |
|---|---|
| `receiptClocks`・`receiptSources`・`receiptEventIds` | 通常／隔離に共通の連番と不変ID索引。イベントと一括保存し、単独更新・欠番・再利用を拒否 |
| `quarantineReviewState` | 参照別の受領数・判断数。受領または不変の判断記録と同じ要求で更新 |
| `quarantineReviews`・`reviewOperations` | 最新の主担当・代理だけが理由・紙確認付きで判断。採用・重複・誤読・不審を保持し、元の隔離記録は変更しない |
| `managedReceipts` | 採用時だけ、判断と一括で別の管理者受付イベントを作る。現在券のcycleを照合し、理由・本人UIDは配布しない |
| `referenceClosures` | 元端末が最終連番・隔離受領数を申告。共通連番と一致させ、閉じた参照への追加送信を拒否 |
| `reviewReleases` | 最終連番確認と全件判断後だけ、監査・保持印解除・参照解除を5パスで一括保存。原記録と結果は残す |
| 端末の固定案と結果 | 送信前に暗号化保存し、応答不明時は同じIDを照会。結果の再取得は二重反映・端末結果の重複を起こさない |

最終連番の申告は、サーバーが受領した連続範囲との一致を検査する。端末内に隠れた未送信データが無いことまで証明するものではない。回収不能端末の申告を管理者が代行せず、参照と削除未確認を残す。復旧後は共通連番の次から開始する。
