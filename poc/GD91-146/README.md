# GD91-146 主担当の移行専用Rulesとブラウザー取込

状態：In Review。TECH-DD91-118-Aの追加設計・隔離検証。本番アプリの実装ではない。

## 作るもの・方式と流れ

現在の本人・端末認可を満たす主担当が、固定した取込IDで未公開保存を開始する。1片16個の末端値を順番に保存し、値とコピー済み索引を一体更新して通常の物理パスへ配置する。全領域をブラウザーで再取得・照合し、一度だけ公開する。親ルートへの広い書込み許可や管理資格を使う取込は追加しない。

移行元の通常接続を先に拒否し、固定後の再取得ハッシュを確認する。原本を保持したまま移行先へ配置する。原本と通常データは、作業用複製の回収では削除しない。

端末の計画は、公演・端末・取込IDごとの非抽出CryptoKeyを使ってAES-GCMでIndexedDBへ保存する。Authトークンは保存しない。再起動時は目録と位置を再取得する。応答喪失は、成功したHTTP応答をアプリ側で捨てる注入であり、実回線の切断測定ではない。

同じ主担当の新しい準備済み端末は、原本と固定目録から計画を再生成し、取込許可の版を進める。旧端末は同時に未公開本文へ接続できない。許可の発行履歴を変更不能で残す。新端末への原本受渡しはRAMのfixtureであり、実際の復旧キー・画面による受渡しの合格ではない。

## 証拠と残条件

[最終結果](artifacts/local-summary.json)、[元の通常4人経路](artifacts/source-capacity-4-summary.json)と[ソース照合](artifacts/audit-summary.json)を分ける。停止状態・端末登録と後処理はEmulator ownerのfixture。業務本文の保存・コピーと公開は匿名端末の通常トークンを使用する。Google方式もEmulatorであり、実Googleログインは行わない。

先行失敗は構文・キー制約、期限更新とコピー検査の不備を含む。旧画像の親GETは通常Rulesが拒否するため、取得を広げず既存のhead・bank取得へ直した。先行失敗のソースハッシュを現在のソース一致数へ加算しない。全最終試行の全拒否Rules・空ルートとAuth 0件を確認する。

600／1,000人の取込、旧Firestore締め済み形式と共有案の再暗号化は未確認。イベント再計算と移行後の訂正・手動削除も全形式の残条件。正式な保存先パスでのRules容量と要求量を別途確認する。本文通信はHTTPの測定であり、TLS・請求や端末20MBの合格を主張しない。方式全体の採用、外部試行と本番配備は承認されていない。
