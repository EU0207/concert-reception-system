## アカウントとGitの境界

| 対象 | 扱い |
|---|---|
| 環境所有者のGoogleアカウント | Firebase環境の管理用。公式ログインで認証し、パスワード・確認コードをコードやチャットへ渡さない |
| 試験用Firebase Authentication利用者 | 環境所有者とは別の架空利用者。最初は2利用者、実在する来場者・スタッフの情報は使わない |
| 環境固有の接続設定 | `firebase-client-config.local.json`または環境変数。Git管理外。追跡する設定例は架空値だけにする |
| トークン・ブラウザー認証状態 | メモリーまたはGit管理外の認証領域。ログと公開用結果へ出さず、サービスアカウント秘密鍵を新規発行しない |
| 生の外部応答 | `artifacts/raw/`へ分離しGit管理外。プロジェクトID・UIDと認証情報を公開用結果から除去する |
| 正式結果 | 件数・HTTP状態と合否を匿名集計し、対応するソース版を記録する。実際のアカウント名やメールは記録しない |

FirebaseのWeb設定は認証資格そのものではないが、本プロジェクトでは環境分離のためGitへ固定しない。データのアクセス制御はSecurity Rulesで検証し、設定を隠すことだけを防御としない。

## 接続前の確認

1. 所有者アカウントと、実データのない検証専用プロジェクトを確認する。既存環境のRulesを上書きしない。
2. Spark・請求先未登録を読み取り確認する。支払方法の登録とBlazeへの変更は行わない。
3. ローカル設定のGit除外と追跡対象を確認する。接続先が未指定・不一致なら外部要求を開始しない。
4. [TECH-DD91-079の範囲](../../docs/development/technical-validation/seat-capacity-validation.md#外部での認可確認案tech-dd91-079)内で要求上限と停止条件を設定する。試験コードは準備中であり、外部実行前に接続準備とローカル検査を完了する。

利用規約への同意を自動処理しない。課金を有効にして初期化エラーを回避しない。[プロジェクト準備結果](artifacts/setup-summary.json)と[サービス準備結果](artifacts/service-summary.json)は環境識別子を除いた記録である。初期化APIの初回失敗はGit履歴に保持し、成功結果へ混在させない。

`generate-rules.mjs`は既存PoCの認可関数から読取り専用Rulesを生成する。`probe.mjs --dry-run`は外部接続なしで契約を確認する。`--run-approved`は専用環境の準備完了後だけ実行する。架空の2利用者で認可を比較し、終了時に全拒否Rulesへ戻す。試験用データを回収し、認証方式の設定を元へ戻す。

## 外部認可比較の結果（GD91-80）

[匿名集計結果](artifacts/remote-summary.json)の5条件は、認可1文書の最小Rulesと本人役割・端末・セッション、公演制御の個別失効である。利用者の通常読取りはFirebase IDトークンを使い、owner取得を拒否の証拠へ使わない。

| 確認対象 | 5条件の結果 |
|---|---|
| 失効前の現在・過去時点取得 | get・list・batchGetとrunQueryでHTTP 200、各1文書 |
| 失効後の現在取得 | 上記4経路すべてHTTP 403、0文書 |
| 失効後の過去時点取得 | 失効前の`readTime`指定では上記4経路すべてHTTP 200、各1文書。読取り専用トランザクションも同じ結果 |
| 既存購読 | 認可変更だけで観測期限10秒以内に`permission-denied`。保持件数は1件のままで追加イベントを取り込まず、新しい購読も拒否 |

**結論：既存購読の停止は外部で確認できたが、過去時点を指定した直接取得の制約はEmulatorだけの現象ではない。サーバー認可全体を合格にせず、T73・#110・168の採用ゲートを維持する。** 公式に認定された不具合とは断定しない。画面で過去時点取得を使わないことだけでは、直接APIの防御にならない。

計測したアプリケーション呼出しは試験181回、回収再確認12回の計193回。Firestoreのowner書込み32回・削除27回を含む。SDK内部の通信・再試行と課金読取りの実数は未計測であり、193回を通信総数や料金の実測値としない。少量比較から共有時間のSLAや人数別の無料成立を推定しない。

[回収後の再確認](artifacts/cleanup-summary.json)では、公開Rulesが全拒否と一致し、試験に使った6種類のコレクション群とAuth利用者が空であることを確認した。認証方式の復元と請求先未登録も確認した。プロジェクト・データベース・Webアプリは残し、自動削除しない。

担当者の本人確認済み属性と役割等はownerが試験前提として投入した。実在利用者のメール確認と`issueSession`の発行は未検証。NodeのSDK・強制長時間ポーリングによる少量確認であり、6台の実機や人数試験ではない。600人・1,000人の無料成立と本番方式の採用は未判定のままとする。

ローカルで`node poc/GD91-80/audit.mjs`を実行し、結果の分類とソースハッシュを照合する。外部試験の再実行には、認証方式の再準備と予算確認が必要である。

GitHub Pages・Hostingの公開とリポジトリ公開は行わない。600人・1,000人の人数試験と本番アプリケーション実装も本検証へ含めない。
