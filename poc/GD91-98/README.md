# GD91-98 停止端末の受付記録を隔離受領する候補

状態：In Review。読者：開発者・設計担当者・テスト担当者。#167の未送信保持を、承認済みBD-08の隔離送信へ接続するPoC。本番実装は対象外。外部最小確認はTECH-DD91-090-Aとして実行承認済み。

停止後の記録は通常受付へ自動採用しない。元のイベントID・読取時刻と座席表の参照を保持して隔離保存し、管理者の照合待ちへ渡す。正常な受領済み結果が既にある場合は、同じ内容を照合して書き直さない。受領結果の端末保存が終わるまで未送信記録を残す。

## 保存と保持の契約

| 対象 | 契約 |
|---|---|
| 自端末の既受領結果 | 過去の本人証跡と端末登録へ結合して個別照会。停止後も結果だけ確認でき、受付用の公開行は取得できない |
| `quarantine/{deviceUid}` | 連番・原イベントとID索引を一体保存。照合待ち保持`leaseHolds/{referenceId}`も同じ要求へ含める。既存保持があれば同じ値を維持する |
| 端末記録 | 受領票を端末へ保存してから送信待ちから除き、元イベントと受領票は別の照合待ち記録として保持する。受領は来場採用・全件照合完了ではない |
| 管理者の一覧 | 最新管理権限で1回32件以下の絞込み取得。一般受付の一覧取得と、結果・保持の書換えや削除は拒否する |
| 座席表の参照 | 端末が復旧しても照合待ち保持があれば解除を拒否。無関係な参照は従来の空キュー・管理版進行の条件で解除できる |

停止・期限切れでも、匿名Auth自体が有効で過去の本人証跡を照合できる端末だけを対象にする。端末申告の時刻・資格が正しい証明ではなく、管理者が確認する資料の受領に限定する。申告時刻を権限の代わりに使わず、通常受付へ自動採用しない。受領後の採否・例外締めと保持解除は未接続で、回収不能端末は参照と削除未確認を保つ。

連番10,000と一覧32件は隔離候補の防御条件で、承認済み製品上限ではない。全業務の無料成立・600人と1,000人の容量へ換算しない。隔離記録の増加と管理者照合の費用は、全業務予算へ別途加算する。

## 初回の試験準備と修正

[初回結果](artifacts/setup-failure-summary.json)はH01合格後、H02の期待件数で停止した。試験コードは通常受付が停止後の結果照会も拒否すると仮定したが、候補は自端末の受領済み1件を照会できたため、その1件を正しく待ち行列から除いた。保存方式の容量制約ではなく、停止後の新規書込み拒否と受領済み結果の照会を混同した試験準備の問題である。全拒否Rules・空試行根を確認して終了した。初回ソースは修正前コミットで保持する。

[2回目の結果](artifacts/setup-failure-second-summary.json)はH08まで合格後、H09の内容不一致試験で停止した。異常要求の組立てが元fixtureの参照IDまで変更し、別のガードが先に拒否した。異常要求は元イベントの複製から作るよう修正する。原データと修正前ソース、全拒否・空試行根の確認を保持する。

初回は`efc5868`、2回目は`09c3661`へソースを保持した。失敗報告の個別フラグを全試験合格へ読み替えず、完了した群とfailureを照合する。回帰ハーネスの初回は全42群と空試行根を確認後も終了待ちが残ったため、対象のNodeだけ停止して親CLIでEmulatorを終了した。`dcbe2f9`に結果・ソースを保持し、明示終了を補ったハーネスで再実行して自動終了を確認した。
