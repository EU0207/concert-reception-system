# GD91-152 受付詳細の明示削除と途中再開

状態：In Review。TECH-DD91-118-Aの残条件のうち、移行後の手動削除へつなぐ隔離PoC。対象は確認済みの受付詳細だけで、個人の完全削除や全複製回収の合格ではない。

## 処理と選択理由

150の登録端末走査が終わった後、現在認可と直近の本人再認証を満たす管理者が、対象範囲と理由を固定する。削除確認と実績照合の宣言も必要とする。本文の消去・進捗と削除記録を同じ更新で保存する。削除記録へ消した本文を複写しない。

受付イベントは元台帳・受領索引と照合し、隔離記録は既存の照合区分も確認する。イベントを消し終えてから端末別の残存管理値を回収する。全端末の本文がなくなるまでは、受領索引等を先に削除しない。最終の残件確認後に、受付詳細のサーバー削除結果を一度だけ残す。

実績・集計と締め結果は保持し、クライアントで削除前後のハッシュを比較する。サーバーによるハッシュ計算・出所証明ではない。残る複製の状態は`externalCopiesPending:true`とし、論理的な全削除完了を出さない。元データや外部バックアップが消えたことへ読み替えない。

## 確認結果

```text
node poc/GD91-152/run-local.mjs
node poc/GD91-152/audit.mjs
```

[最小試験](artifacts/local-summary.json)は2端末・受領2件をownerで前提投入し、現在の主担当による通常トークンで10段階を削除した。要求3部分をそれぞれ省いた更新を拒否した。未確認の開始と早すぎる完了、実績の削除を拒否した。通常の管理値書換えも凍結したままである。

1段階目の成功応答を受信後に捨て、クライアントオブジェクトを作り直してサーバー進捗から再開した。物理切断・ブラウザー再起動の試験ではない。削除記録と完了結果の上書きを拒否し、端末停止も拒否した。実績・集計と締め結果のハッシュは変わらなかった。

ownerで台帳外の反例を注入し、逆引きだけがあっても削除を拒否した。台帳外の本文が残ると、管理値の削除と完了結果を拒否した。不正な照合区分の反例も拒否した。反例だけをownerで戻してから通常経路を続けたもので、その回収を通常削除の合格へ加算しない。

最終の全拒否Rulesと空データ、Auth 0件を確認。追加外部試行0件。最終ソースは[監査結果](artifacts/audit-summary.json)へ照合する。

## 制約と残条件

生成Rules 10,482,821 Bはローカルで受理された。Emulator上限との差は2,939 Bしかなく、後続条件を加えた全体には余裕がない。認可を保つ縮約と実サービスでの確認が必要であり、本番配備可能とは判断しない。

先行試行では正規表現のエスケープと、部分削除時の親検証を修正した。凍結を通常更新の式より先に判定してから削除経路を評価すると通った。JavaScriptのRAM診断だけでは捉えられなかった評価順の差があり、実行上の詳細原因を断定しない。台帳外反例が残る間に管理値の回収が拒否されることも確認し、反例の後処理を分けた。先行失敗と先行の最小成功を最終ソース照合へ加算しない。

この候補は削除後も安全停止を維持する。削除後の訂正とバックアップ再取込は未対応であり、業務上の禁止仕様として確定しない。現在の実績を正本とする復旧と、旧バックアップからの復活防止を追加設計する必要がある。

原本・端末内と外部バックアップの回収、個人の完全削除は未確認。正式な取込経路との合同接続、600／1,000人と全形式移行も未完了。本番実装・配備なし。

削除では`.validate`が適用されないため、削除の許可を`.write`側へ明示する。[公式の検証条件](https://firebase.google.com/docs/database/security/rules-conditions#validating_data)に沿い、既存の変更不能条件を親の広い許可で回避しない。
