# GD91-107 追加部分の自動採番の保存接続

状態：In Review。読者：開発者・設計担当者・テスト担当者。#167の隔離検証。PR #208は2026-10-15に承認・main統合済み。本番実装・方式採用を含まない。

## データと処理

追加行・列は初期値を未セルとし、選択した追加部分だけを採番する。席と欠番は番号を消費し、空間・通路・未セルは消費しない。既存席・欠番の番号とID、割当・QRを保持する。途中の個別追加は従来の手入力席として扱い、この次番号を進めない。

[edit.mjs](edit.mjs)で追加案を作り、[numbering-rules.mjs](numbering-rules.mjs)で各列の連続採番を検査する。新しい保存方式を採用する判断ではなく、承認済み仕様を同じRTDB候補へ接続する検証である。

| 段階 | 保存・検査 |
|---|---|
| 候補作成 | 追加辺と種別を選び、新IDと番号を計算。既存モデルを複製内で維持する |
| 保持 | 確定元と候補へ参照を置き、確定・取消しまで回収を拒否する |
| 採番検査 | `numberProofs/<check>/<line>/s<index>`へ順番に記録。最初は既存列の次番号、新列は開始番号を使用。前の検査記録が存在する場合だけ次へ進む |
| 構成検査 | 元と候補の全セルを比較。追加範囲・番号の連続性と次番号、理由・緊急印を検査。全検査完了後にだけ確定先を一括切替 |
| 終了 | 発行済みQRと割当を確認し、参照を解除。完了・取消し済みの採番検査記録だけを削除する |

検査開始時の構成・表示・業務と運用状態の版を保持する。途中で版が変わった検査結果は確定へ使わない。主担当・代理の最新権限と直近の本人認証も維持する。当日追加の席は用途の理由を保存し、緊急印はタップ時の理由表示へ引き継ぐ。

## 検証範囲と残条件

[全範囲](artifacts/validate-summary.json)は14群。別途[余白スライド後の追加](artifacts/slide-number-summary.json)1群が合格し、移動量を一度だけ反映して既存位置を保持した。正常系は縦横・通常逆順・行列追加・舞台左上の16組合せ。以下の異常系を同じ候補で確認する。

- 検査の飛ばし・改ざん、記録の上書きと早期削除。
- 不連続な番号、既存割当席の変更と手入力席の混入。
- 途中の業務更新・権限失効と同時確定。保持中の回収と取消し後の回収。

番号衝突と整数超過は計算側の拒否試験として区別する。試験ごとの初期化ではセッション版も初期値へ戻す。業務全体の不変比較は管理用の試験経路で行い、一般端末へ業務履歴の全体取得を許可しない。

[共通4群](artifacts/common-local-summary.json)は当日の逆順追加・理由とスタッフ再取得、検査改ざん・早期削除と両世代の保持をまとめる。[呼出しモデル](artifacts/common-budget-summary.json)では外部開始18と後処理予約60をモデル化し、試験部分240で停止する。ローカルの全実要求やFirebaseの料金ではない。

旧216群が今回の最終Rulesで合格。取得予算4試行も期待結果と一致した。24結果ファイルのソース920件を照合し、全拒否Rules・空試行根と待受終了を確認した。元の試験ソースと実行したRulesを区別してハッシュを残す。生成Rulesは2,302,870 Bで、外部成立・実課金量は未確認。初期状態は前提投入、端末はRAM。IndexedDB・SDK切断と実機は未検証。追加採番の呼出し増分を600人・1,000人の全業務へ合算する評価も残る。#167はOpenのままで、本番採用と全業務無料成立を証明しない。

この候補は末尾拡張と種別選択を同じ候補で確定する。拡張だけを先に確定した後で、追加セルの由来を端末再開後に識別して採番する経路は未接続。拡張後の未セルを途中追加の自動採番対象へ勝手に広げない。複数区画を含む下書きの一括確定との合成、区画削除と並替えは別の残条件である。

```text
node poc/GD91-107/run-local.mjs common-local.mjs validate.mjs
node poc/GD91-107/run-regression.mjs common-budget.mjs regression.mjs
node poc/GD91-107/run-extra.mjs
```
