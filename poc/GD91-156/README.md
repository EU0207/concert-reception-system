## 何を作るか・なぜ必要か

既存Firebase CLIの認証更新要求を計測できる試験用transportを作る。155の管理API許可先に認証更新先が含まれず、Firebase CLIの認証エラーに包まれて停止したためである。資格情報の期限切れや再入力が必要だとは判断しない。

実装済みCLIの`auth.js`は`https://www.googleapis.com/oauth2/v3/token`へmultipartのBuffer本文を送る。認可の範囲は既存80・82とApp Check helperと同じ。別アカウント、サービスアカウント鍵と新しい権限は追加しない。

## 処理とデータの流れ

既存CLIの資格情報をメモリーで参照 → 正確な更新URLへのPOSTを確認 → 本文のバイト数を計測 → 発行された資格で所有・課金と空環境を確認 → 155と同じ業務7群へ接続する。

更新先は上記URLだけに限定する。POST・multipartと16KiB以内のBufferに限定し、リダイレクトを拒否する。通常APIの本文型と許可先は広げない。資格情報・Buffer本文と発行トークンを実行結果へ保存しない。

通常の更新は最大3回。後処理の再開用に追加3回を許可するが、既存の後処理60回へ含める。全呼出し600回・本文64MiBを維持し、通常側3回を追加した計画は599回・63,028,720 B。外部準備・ログイン等の8MiB予約で認証更新本文も扱う。予約を実測とみなさない。
