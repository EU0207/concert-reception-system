# GD91-104 構造編集と余白スライドの保存接続

状態：Draft。読者：開発者・設計担当者・テスト担当者。#167の隔離検証。PR #205は2026-10-15に承認・main統合済み。本番実装・方式採用は含まない。

検証対象は、非未セルの範囲を通常保存で証明する初期生成、移動量だけの余白スライド、専用の拡張・未割当席編集を同じ確定構成へ接続すること。部分送信・旧版と対象外変更を拒否し、同一候補で既存経路を回帰確認する。中間結果はコミットへ残し、この範囲全体の確認または具体的な判断制約まで継続する。

| 保存契約 | 方式・理由 |
|---|---|
| 構成の範囲 | 各区画に非未セルの矩形範囲と四辺のセルIDを保存。全セルが範囲内にあり、四辺の証拠セルが実在することを検査し、自己申告だけの範囲を使わない |
| スライド | 同じ不変構成を保ち、区画のrowOffset・columnOffsetを更新。確定先頭へviewRevisionを持たせ、構成キャッシュと表示座標の版を区別する |
| 割当・QR | 移動量の保存では名簿・席設定と券を変更しない。共有の業務版と最新権限を照合し、方向・移動量を履歴へ保存する。理由は持たない |
| 表示と再取得 | 取得した不変の基準配置へ移動量を一度だけ適用。キャッシュを再利用しても現在の移動量を取得し、最後に確定版を再確認する |

外部Firebase・課金・公開は行わない。新形式の端末保存・実機と全業務無料成立は別の残条件。既存回帰を新経路の業務全体の合格へ加算しない。今回も3,000人試験は行わない。
