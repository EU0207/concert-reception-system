# GD91-104 構造編集と余白スライドの保存接続

状態：In Review。読者：開発者・設計担当者・テスト担当者。#167の隔離検証。PR #205は2026-10-15に承認・main統合済み。本番実装・方式採用は含まない。

検証対象は、非未セルの範囲を通常保存で証明する初期生成、移動量だけの余白スライド、専用の拡張・未割当席編集を同じ確定構成へ接続すること。部分送信・旧版と対象外変更を拒否し、同一候補で既存経路を回帰確認する。中間結果はコミットへ残し、この範囲全体の確認または具体的な判断制約まで継続する。

## データと処理の流れ

| 保存契約 | 方式・理由 |
|---|---|
| 構成の範囲 | 各区画に非未セルの矩形範囲と四辺のセルIDを保存。全セルが範囲内にあり、四辺の証拠セルが実在することを検査し、自己申告だけの範囲を使わない |
| スライド | 同じ不変構成を保ち、区画のrowOffset・columnOffsetを更新。確定先頭へviewRevisionを持たせ、構成キャッシュと表示座標の版を区別する |
| 割当・QR | 移動量の保存では名簿・席設定と券を変更しない。共有の業務版と最新権限を照合し、方向・移動量を履歴へ保存する。理由は持たない |
| 表示と再取得 | 取得した不変の基準配置へ移動量を一度だけ適用。キャッシュを再利用しても現在の移動量を取得し、最後に確定版を再確認する |
| 構造編集 | 新構成を作り、元の全セルと候補の全セルを双方向に検査。追加行・列は未セルだけに限定し、既存の番号と次の自動番号を維持する |
| 個別編集 | 非席4種からの手動席追加と、未割当席の番号・位置変更を専用意図に照合。当日の理由を確認し、割当済み席と対象外の変更を拒否する |
| 候補の保持 | 検査元と候補の両世代を参照で保護。最新の構成・業務版と表示版に一致する検査結果だけ公開し、結果確認または明示取消し後に参照を外す |

構造編集では現在の移動量を新構成の座標へ一度だけ反映する。新世代の移動量は0から始まり、元の世代と区別する。表示版だけが変わった場合も古い検査結果を使わない。スライドの履歴は方向と移動量を持ち、理由を追加しない。

今回の拡張は未セルの追加まで。追加末尾の自動採番、区画の新設・改名と舞台位置変更の専用保存は後続の接続条件として残す。既存の純粋計算の合格を、新しい保存経路の合格へ読み替えない。
