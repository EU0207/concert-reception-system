# GD91-63 席あり券・QRと不参加の合同接続

状態：In Review。読者：開発者、設計担当者、テスト担当者。

#166の同じ正本・共通版へ、発券済みの手動移動交換と券の操作を接続する隔離PoC。[合同検証記録](../../docs/development/technical-validation/seat-business-integration-validation.md)を結果の正本とする。本番アプリケーションではない。

## 処理とデータ

1. GD91-62の通常本人セッション・構成公開と来場者登録で、架空の2人を4席のうち2席へ設定する。券・資格と保護索引は通常要求から生成する。
2. QR資格は来場者と来場cycleへ結合する。席の移動交換で券・資格を再発行せず、現在の割当と保護対象席を一体更新する。`operationSeatId`は直近の券操作で照合した席であり、現在席の正本ではない。
3. 不参加は管理正本・参加索引と席割当を更新し、券・資格とコードを無効化する。共通版と履歴を含め、QRありの席ありは9件、QRなしの既存券は7件を一体保存する。
4. 復帰は4件。旧券を閉じたまま来場予定だけ戻し、席未設定と旧QR無効を維持する。再割当後に新資格を作るとcycleが進む。

初回QR生成6件、再発行8件、券チェック4件。チェックを外しても発券履歴・有効QRによる保護を外さない。チェックだけでは受付配布版を進めず、資格変更時は進める。管理履歴へQR資格値・コードを含めない。

発券後の空席移動は理由必須。交換理由は初回受付開始前に任意、開始後は停止中も必須。保護対象席の集合が変わる移動交換は4件、両席とも保護対象なら3件となる。

## 検査と一体性

GD91-60・62のRulesを入口単位で合成し、生成結果だけをGit管理外へ出力する。認可・完成証明と公演状態の22関数は静的比較する。

手動席検査は確定版が指す世代のseatFactsと、確定版の全席IDへ照合する。公開済み候補の再読取りを省くが、完成証明の検査は維持する。各席の参照を2から1へ減らし、保護移動を含む要求を参照予算20へ収める。

不参加の相互参照は「券→管理正本→参加索引→割当→券」で閉じる。途中の文書だけを省略できないことを部分集合試験で確認する。不参加マーカーは許可根拠ではなく、この相互参照の対象識別にだけ使う。

[算定コード](tests/budgets.mjs)は経路別の机上算定。キャッシュ減算なし。発券済み移動交換20、再発行20、QRあり不参加20、QRなし既存券不参加16、復帰19。式評価数・請求量の実測ではない。

## 証拠と未接続

- 32シナリオで、初回QR62・移動14、不参加510・復帰14、再発行254・QRなし不参加126の部分集合を拒否する。計980通りはシナリオ内の要求数であり、980シナリオではない。
- [全体結果](artifacts/lifecycle-summary.json)へ実行前後のソースハッシュと各結果を記録する。旧GD91-42の63件とGD91-62の20件を今回の再実行件数へ加算しない。
- 券を持ち席がある経路が対象。券未作成の不参加、席なしと構成未作成の分岐は未接続。4席の検証であり、500人更新と複数区画の合格ではない。
- 初期役割・登録端末と旧構成、空の業務索引は前提投入。受付実績の保持試験も前提投入であり、通常受付・QR読取りや配布投影は未接続。
- 停止確認は申告値の不足を拒否する限定試験。全端末の停止・更新受信確認ではない。同一ID照会も実際の応答喪失ではなく、SDK・IndexedDBと画面、実機は未実施。
- 本番形式や方式採用は未決定。通信復旧だけで共有・確定しない契約を維持し、費用・回収は#167、採否は#168へ残す。

起動前の合成パターン・旧ヘルパー依存の失敗は[初回記録](artifacts/first-attempt.json)へ保存した。最初の動作試験では、共有オブジェクトの版を試験用ヘルパーが二重加算し、L04で拒否された。案を一度だけ更新する形へ修正した。失敗実行のJSONと前後ハッシュはartifactsへ保持し、認可・業務条件を緩めていない。
