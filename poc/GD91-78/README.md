## 結果

[人数別結果](artifacts/watch-summary.json)は**合格2件・失敗1件**。全体合格ではない。600人は6利用者・6端末のSDKクライアントが同じ600件へ収束した。1,000人は60秒の観測期限で未収束だった。各受信数は114／114／174／126／120／162件で、原因の確定はしていない。恒久的な欠落や本番の障害と断定しない。

600人の書込みは204要求・600文書。データと券の基礎情報はowner投入。通常登録・発券、実QRの資格照合は未検証。共有時間の5秒目標・10秒上限も未確認で、今回の観測期限を製品条件に使わない。

|---|---|---|

## 処理

`watch-client.mjs`が対象公演のイベントを購読する。キャッシュ由来または未確定書込みを含む通知は表示へ採用しない。サーバー確認済み結果を時刻精度を保って正規化し、イベントIDで照合する。状態の導出後にjournalへ保存し、完了後に表示側へ渡す。

保存失敗・認可拒否では購読を解除して処理を止める設計。ただし10人の試験で、本人の権限失効だけでは購読の拒否を観測できなかった。本番でも起きると断定せず、#110・168の認可ゲートへ残す。過去時点指定の直接API問題も未解消。

今回のjournalはRAM。暗号化IndexedDB・画面と本番認証更新は未接続。SDKは既存のEmulator用トークン注入を使用し、実機・ブラウザーを証明しない。SDK内部の通信回数・バイト数も測定していない。

### 購読の境界

途中で範囲を動かす100件の試作では、並行送信中の収束を確認できなかった。[試作の失敗記録](artifacts/failed-1791816208236.json)を保持する。時刻表現差と範囲外通知も見つかったが、これらだけを未収束の根本原因とは扱わない。

比較版は範囲を固定し、最大受信時刻で完了カーソルを進めない。監視上限は2,048イベントで、同数に達した時点で成功を止める。取得完了と誤認せず、直前の保存を残す。新規・再接続時の全結果取得が残るため、本番の差分再開方式として採用しない。

`generate.mjs`はGD91-77から、受付イベントのlist上限だけを変更する。他の認可・書込み条件は維持する。2,048は隔離比較用で、承認済み製品上限ではない。長時間運用の分割と再開境界は未確認。

## 費用

[算定結果](artifacts/budget-estimate.json)は机上モデル。SDKのコールバック回数を請求実測へ置き換えない。600人の観測回数による比較値15,412は、未確定通知を除外しているため上限保証に使わない。1,000人の観測値による比較は未収束のため算定しない。

| 人数 | 1イベントごとに結果更新するモデル | 全結果の再接続1回を加算 |
|---|---:|---:|
| 600 | 43,572読取り | 50,820読取り |
| 1,000 | 72,372読取り | 84,420読取り |

いずれも6クライアント、安全係数2。受付書込みのRules依存6件と、取得時の依存4件を含める。座席再利用156読取りはGD91-77からの仮定で、今回の実測ではない。準備・再入場と急な変更は未算入。現在の依存構造では、購読に変えるだけで無料成立を保証できない。600人必須・1,000人目標は維持する。

[公式課金規則](https://firebase.google.com/docs/firestore/pricing)は、結果更新・再接続と依存文書変更時のRules評価を課金対象とする。今回の購読は明示的な範囲フィールドが1つなので索引読取り免除をモデルへ適用する。実際の請求・転送量と障害時の要求増加は未確認。

## 再現と次の対応

PowerShell 7でGD91-73・77のRulesを生成後、次を実行する。既存のEmulatorが同じポートで動作している場合は先に停止する。

```powershell
node poc/GD91-78/generate.mjs
$env:JAVA_TOOL_OPTIONS=($env:JAVA_TOOL_OPTIONS+' -Xmx4096m').Trim()
node poc/POC-004/node_modules/firebase-tools/lib/bin/firebase.js emulators:start --config poc/GD91-78/firebase.json --project demo-concert-seat-gd91-60 --only auth,firestore
```

別ターミナルで実行する。`validate.mjs`は失敗時に非0で終了し、失敗時点の保存件数とソースハッシュを記録する。`summarize.mjs`は現在ソースと一致する失敗記録から、合格と失敗を分けて集約する。合格へ変換しない。

```powershell
$env:GCLOUD_PROJECT='demo-concert-seat-gd91-60'
$env:FIRESTORE_EMULATOR_HOST='127.0.0.1:8181'
$env:FIREBASE_AUTH_EMULATOR_HOST='127.0.0.1:9191'
node poc/GD91-78/validate.mjs
node poc/GD91-78/lifecycle-tests.mjs
node poc/GD91-78/boundary-tests.mjs
node poc/GD91-78/summarize.mjs
node poc/GD91-78/budget-estimate.mjs
node poc/GD91-78/audit.mjs
```

次は未収束と権限失効の切り分け、認可依存・再接続を含む無料予算の改善。送信・応答不明にも試験の監督期限を設け、同一IDの照会を残す必要がある。既存BD-03-05の時間条件は変更しない。3,000人は検証せず、#167・168の採用ゲートを維持する。

公式根拠：[購読と解除](https://firebase.google.com/docs/firestore/query-data/listen)、[Emulatorの制約](https://firebase.google.com/docs/emulator-suite/connect_firestore)。
