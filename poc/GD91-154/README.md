# GD91-154 履歴削除後の実績訂正

状態：In Review。REQ-F-015とAC-009・035、BD-03の締め後訂正に対応する隔離候補。152～153の安全停止を、業務上の恒久的な訂正禁止へ確定しないため追加した。

## 作るものと処理の流れ

| 段階 | データ | 確定への条件 |
|---|---|---|
| 候補受付を開始 | 対象人と現在の実績版を固定。既存の進行中受付を共有する | 現在の主担当・代理がオンラインで再認証済み |
| 候補を追記 | 提案値・元版と理由を変更不能な候補として保存 | 候補・順番と件数を一体更新。競合時も候補を上書きしない |
| 受付を締め切る | 読み終えた候補件数を固定する | 同時追記で件数が増えたら締切を拒否し、全候補を再取得 |
| 訂正を確定 | 選んだ候補・確認理由と訂正前の版を記録。実績と集計を一体更新 | 締切後の全候補を確認。元の締め結果を変更しない |

詳細履歴の削除後は、保持した最小実績を正本として使う。候補の受付中はその実績を変えない。同時候補を後着順で消す方式を採らず、保存された候補を管理者が確認して選ぶ。既に締め切った受付への送信が拒否された場合も、端末側の候補を捨てない。

訂正イベントへ元の実績版と直前の集計版を記録する。削除済みの受付イベントを復元せず、訂正を逆順にたどって削除時点の最小実績を再構築し、削除境界のハッシュと比較する。本文を持たないハッシュだけを実績そのものの代わりにしない。
