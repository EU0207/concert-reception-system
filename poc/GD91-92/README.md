基準を取得する前に[references.mjs](references.mjs)で世代を保護する。固定案を端末へ保存してから、操作IDと期待する確定版を参照へ予約する。[reference-rules.mjs](reference-rules.mjs)はその予約と書込みを結ぶ。参照なし・他端末の参照と未予約の要求を拒否する。

結果照会で内容一致を確認するか、期待版群の進行で元の要求が通らないと確認してから予約を解く。期待版群は確定版・構成版と公演管理版を指す。解除応答だけを失った場合も再照会し、別の予約を解除しない。予約を解いても下書きの基準は保護したままにする。明示的な破棄・移行後に世代参照を解除する。時刻だけの自動解除はなく、失効・喪失した端末の参照は残る。

- [参照12群](artifacts/validate-summary.json)：未解決解除と他端末による解除を拒否。公演停止だけの版変更も比較し、予約済み案の版書換えを拒否する。全参照解除後だけ上限付き回収を再開できた。操作結果は保持する。
- [確認済み版4群](artifacts/known-reference-summary.json)：正常時は確認済み参照版を使い、古い版を拒否する。実際の確定応答を照合し、偽の応答では未確定の保護を解除できない。
- [Edge5群](artifacts/recovery-summary.json)：暗号化した固定案・参照IDを復元し、実REST応答切断と別端末のQR更新後も再書込み0件。権限失効時は案・参照を残す。

[外部と共通の600人対照](artifacts/capacity-local-summary.json)は4群合格。名簿をownerで前提投入し、通常の一括割当・QR作成と参照解決を比較した。最大38,839ノード・4,298,142 B、準備・後処理を除く100呼出し。一括要求336,910 Bの応答は約31秒。通常登録を含む全業務や、GD91-90の人数別結果と同じ候補の合格へ換算しない。

受付キューの参照・共有候補の保持と、新しい参照形式を人数別通常経路へ再接続する作業は継続対象。ブラウザー内の認証持続・実機、全端末停止と全業務の予算も未確認。本番採用は含めない。

[audit.mjs](audit.mjs)でGD91-91・92の110ソースハッシュと生成Rulesを照合した。前候補の人数別結果はGD91-90の監査で別に確認する。

### Aの範囲と後処理

1. 所有者・請求先未登録、全拒否Rules・空DBとAuth残数0を確認。元の認証有効設定・許可ドメインをGit管理外へ保持する。
2. 既存Google構成の有効状態と匿名認証を一時変更する。localhostから本人がログインし、照会APIでトークンを検証する。メール認証・OAuth構成の追加やIdentity Platformへの切替はしない。
3. [ローカルと同じ共通4群](capacity-cases.mjs)を行う。600人の名簿はownerで前提投入し、1,200セルの準備・600人の一括割当を通常認可で実行する。未解決・別端末の参照解除を拒否し、現在QRのサンプル受付を比較する。
4. セッション期限1条件で、SDKのページ・子の受信と独立RESTを比較する。別の有効端末は更新を受信する。両端末は同じGoogle本人の管理端末で、一般受付権限・役割単独期限や全業務の合格にはしない。世代回収の削除試験はEmulatorだけに残す。

上限は100,000ノード・試行根20MiB、後処理込み200アプリケーション呼出し。60件を後処理に確保する。[remote-capacity.mjs](remote-capacity.mjs)は明示フラグが必要で、終了済み結果・未解決台帳があれば再実行しない。REST・SDKで観測した本文200MiBを停止目安とし、SSE本文やSDK内部のプロトコル通信の上限とはしない。課金・公開と3,000人試験は含めない。
