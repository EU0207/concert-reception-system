# GD91-62 通常登録と未発券の手動席設定

状態：In Review。読者：開発者、設計担当者、テスト担当者。

#166の第2～4条件のうち、通常登録・入金と未発券の手動席設定を同じ正本へ接続する隔離PoC。[合同検証記録](../../docs/development/technical-validation/seat-business-integration-validation.md)を結果の正本とする。本番アプリケーション実装と全業務回帰の完了を意味しない。

## 処理とデータ

1. GD91-60の通常本人セッションで構成の完成証明を作り、区画を通常公開する。既存の空の業務索引と旧座席表は前提投入。架空の来場者は通常要求で登録する。
2. `registration`は管理正本attendees、表示名正本attendeeLabelsとeligible索引を作る。共通版・操作履歴を含む5件を同時確定する。表示名は管理正本へ重複保存しない。
3. `assignment`は公開済み区画の完成候補と、その世代の検査済みseatFactsを参照する。利用可能席・来場者と重複を照合し、割当・共通版・履歴の3件を同時確定する。元の席IDと公開操作IDは維持する。
4. 全体の共通版を使い、登録と席設定の間でも古い確認を拒否する。交換理由は公演管理の初回受付開始時刻で判定し、停止で理由不要へ戻さない。

入金だけの変更は管理正本・索引と共通版・履歴の4件。表示名と割当は変更せず、受付配布版を進めない。表示名の訂正経路は未接続。

## Rulesの組立て

`generate.mjs`はGD91-60の既存Rulesへ`business.rules`を合成する。出力はGit管理外のnode_modules/.cacheに生成する。既存Rulesの複製・直接変更を避け、合成元と生成結果のハッシュを記録する。

認可・完成証明と公演状態の22関数は文字列で照合する。通常業務の入口を追加し、旧assignmentProbeの許可を閉じる。検証用の任意割当を本番業務へ残さない。券保護の通常更新は後続で接続し、現段階では保護対象が存在する割当経路を許可しない。
