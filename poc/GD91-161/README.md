# GD91-161 台帳に限定した復旧手順

状態：In Review。TECH-DD91-120-Aの追加設計・隔離検証。方式採用、実資格の発行と外部試行は含まない。

## 作るものと理由

元DBの現行台帳を取得できる場合に限り、管理用実行器が台帳・結び付け・許可だけを設定する候補を作る。業務本文は118-Aのブラウザー取込を維持する。管理権限で本文を取り込む方式へ変更しない。

別DBの切替は一つのトランザクションにできないため、元DBを閉じてから移行先を開く。途中では両方が閉じることを許容し、両方を有効にしない。応答が失われた場合は、現在値を再取得して同じ操作を再開する。

## 処理とデータの流れ

1. 現在の主担当が159の通常認可で正本を凍結する。元台帳と元本文を実DBから取得し、移行先の未公開本文と全件照合する。保管ファイルだけから台帳を作らない。
2. 管理実行器が元台帳を`recovering`へ条件付きで変更する。この管理専用状態には通常Rulesの遷移を設けず、主担当による通常の凍結解除も拒否する。元の許可を`retired`にして取得も止める。
3. 移行先は許可を閉じた状態で結び付けと現行削除版を設定する。元DBの閉鎖と現在認可を再確認して、最後に移行先の許可を開く。保存先の値が取得時から変わっていたら、ETag条件で上書きを拒否する。

実行器の書込みは、固定した両DBの`restoreAuthorities/{performanceId}`と、各公演の`restoreBinding`・`restorePermit`だけに限る。ルートの一括上書きや業務本文の変更は許さない。段階ごとに現在認可と本文を再照合する。再開情報は進捗の手掛かりに限定し、最新性の根拠にはしない。中止しても自動で元DBを再開しない。

## 資格の取得・終了の設計

実資格は発行していない。専用サービスアカウントを手動で一時有効化し、環境所有者が短期の代理資格を得る候補を比較した。鍵ファイルを配布せず、資格は管理実行器のメモリーだけで保持する。ブラウザーと業務バックアップへ渡さない。取得対象と有効期限を実行計画へ固定する。

| 項目 | 採用前に必要な確認 |
|---|---|
| 発行 | [短期代理資格](https://docs.cloud.google.com/iam/docs/create-short-lived-credentials-direct)のAPIと必要IAM権限を確認する。候補の有効期間は600秒で、自動延長しない。実発行・API有効化は今回行わない |
| 対象制限 | [管理OAuth資格](https://firebase.google.com/docs/database/rest/auth)は業務本文にも届く広い資格である。今回のパス制限は実行器の制御であり、資格自体をメタデータ専用にできた証拠ではない。別プロジェクトへの誤接続も外部試行前に確認する |
| 終了 | 実行器を閉じ、代理発行権限を回収し、専用アカウントを無効化する。発行権限の回収だけで既発行トークンが無効になったとしない。[公式の失効手順](https://docs.cloud.google.com/docs/security/compromised-credentials)に従い、有効期限経過と実要求の拒否を確認する。無効化の反映待ちも未確認である |
| 費用 | [IAM APIの価格](https://cloud.google.com/iam/pricing)だけで、Spark環境の資格発行からデータ操作まで成立すると判定しない。課金登録なしでのAPI利用とRTDB転送予算を代表試行前に確認する |

ローカルでは実行器の期限と利用終了だけをモデル確認した。Emulatorの`owner`は実サービスのOAuth資格ではなく、Google IAMの失効・伝播の合格へ流用しない。実資格の発行・失効を含む外部試行は、他の残条件とまとめて新しい範囲・予算を提示する。119-Aは再利用しない。

## 全環境喪失時の保全と残条件

同じ署名済み台帳について、「取得後に削除なし」と「取得後に削除して全DBを喪失」は、残されたファイルの内容が同一になり得る。署名や複製数は真正性・可用性の対策であり、後続の削除がなかった証明にはならない。このため、元DBも独立した最新証跡もない場合は復旧を止める。

独立した保全先には、削除開始前の復元禁止記録と、削除完了後の版・対象を残す必要がある。全履歴の欠落検出と、復旧先を一つに固定する管理も必要となる。未完了の削除や記録欠落があれば有効化しない。保全先自体を古いバックアップから作り直して「最新」としない。保管期間は対象公演の復旧可能な複製が残る間を下限とし、自動期限削除を導入しない。

この保全先と全削除経路への接続は未実装・未検証である。通常の削除を管理者のコンソール作業へ変える案は、承認済み業務手順への影響があるため採用していない。全環境喪失時の復旧を合格とせず、#168の採用前ゲートに残す。

今回の候補は同じAuth Emulatorプロジェクト・同じ本人の2つのDB名前空間を使う。別プロジェクトの認証と所有者変更は未確認。削除時点から保持実績が変わった場合は現候補で拒否し、削除後訂正を含む一般の復旧は未確認である。新規公演の削除版0を正当に発行する初期作成手順も別に必要で、復旧の代替にしない。

全形式の取込と再暗号化、個人単位削除と全複製回収も残る。600人必須・1,000人目標の保存・通信比較には、外部保全と再取得の実量を加える。追加外部試行0件、本番実装・配備なし。方式採用と115の回答保留を維持する。
