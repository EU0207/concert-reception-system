# GD91-51 段階的な小片検査

## 結論と範囲

状態はIn Review。読者は開発者、設計担当者、テスト担当者。

GD91-50で上限に達した小片の検査を、別リクエストの7段階へ分ける隔離候補。局所の検査証跡を検証し、完成候補の発行や公開は許可しない。本番の保存形式・Rulesは変更しない。

## 処理

1. 構成片と属性片を同時に隔離保存する。この時点では内容検査済みとしない。
2. [Rules](firestore.rules)が1段階ずつ内容を検査し、成功時だけproofのstepを1増やす。
3. step=7で小片内の検査完了となる。区画全体の完成・公開可能を表さない。

| step | サーバーが確認すること |
|---|---|
| 1・2 | 各セルの形式・位置と旧セルID。元の消費番号を保持すること |
| 3・4 | 各セルの採番項目と旧構成との関係。自動席を保持し、非席からの追加は手入力に限定 |
| 5・6 | 各席の属性と理由。非席の属性はnull |
| 7 | 小片内の席IDと、同じ列の表示番号が重複しないこと |

幅2の末尾1セルでも7段階の順序を維持する。存在しない2番目のセルの段階は、片の大きさを確認して進む。幅は検証用の条件で、製品上限を決定しない。

全段階で最新の認可を確認する。管理状態と公開中の基準も再照合する。proofはgeneration・baseGenerationとcontrolRevisionへ結び付け、変更できるのはstepだけ。データは新規作成後に更新・削除できず、保存内容の差替えによる検査便乗を防ぐ。途中で止まったら保存済みstepから再開できるが、自動確定はしない。

## 前提と結果

親・列設定と旧構成はfixture。端末・権限と本人確認セッションもfixtureであり、その発行や完成証明を試験した扱いにしない。匿名認証の試験端末から通常の保存リクエストを送る。[試験](tests/emulator.mjs)の25ケースと[結果JSON](artifacts/emulator-summary.json)を参照。

500席・250小片では、隔離保存250リクエスト・500書込み、証跡更新1,750リクエスト・1,750書込み。計2,000リクエスト・2,250書込みであり、fixture作成を含めない。公開までの総費用ではない。保存内容と最終stepを管理用再取得で照合した。

静的参照上限は隔離保存の構成側6・属性側2、同時保存の合計8。証跡更新は1文書・最大9、進捗の単独取得は5。キャッシュによる減算はしない。今回の対象では式評価上限に達しなかったが、残りの検査も成立する保証ではない。

## 再現

既存のNode.js・Firebase CLIとJavaを使う。リポジトリのルートでpwshを実行する。実Firebaseへ接続しない。

```powershell
$env:CI='1'
$env:FIREBASE_CLI_DISABLE_TELEMETRY='1'
$env:GD91_FRAGMENT_WIDTH='2'
node poc/POC-004/node_modules/firebase-tools/lib/bin/firebase.js emulators:exec --config poc/GD91-51/firebase.json --project demo-concert-seat-gd91-51 --only auth,firestore 'node poc/GD91-51/tests/emulator.mjs'
```

## 残条件

小片をまたぐID・表示番号一意性と採番カーソルは未接続。旧席全件比較・全体完成候補と公開境界も残る。異なる形の差替え、当日の編集と既存業務全体は対象外。

この候補の書込み数を採用値にしない。次は全体検査への証跡接続を設計し、同時に実行できる検査を比較して書込み費用を評価する。段階をまとめる場合も、同じ条件と最新認可を維持する。

正式な結果は[検証記録](../../docs/development/technical-validation/seat-save-validation.md#gd91-51-小片検査の段階的な証跡)を参照。方式未採用・本番未着手。過去44件と63件の再実行、SDK・実機試験は実施していない。
