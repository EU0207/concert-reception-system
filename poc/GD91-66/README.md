# GD91-66 自動配置とグループ固定の計算検証

状態：In Review。読者：開発者、設計担当者、テスト担当者。#166の保存接続に先立つ隔離PoC。架空データだけを使用する。

## 対象と実行

```powershell
node poc/GD91-66/tests.mjs
```

Node.js標準ライブラリーだけを使用する。RES-005の12例と追加15件、計27シナリオを実行し、[結果](artifacts/calculation-summary.json)へ実行前後のソースハッシュを記録する。追加ケース内の入力違いは別件へ加算しない。Firebase・SDKへの接続、依存追加はない。

## コードとデータの流れ

| 関数 | 処理 |
|---|---|
| `validateSnapshot / begin` | 同じ公演の全名簿・構成投影と現在割当を検査。全期待版が一致する入力だけを複製する |
| `allocate / consecutive` | 全名簿からグループを作り、人数降順・名簿位置で処理。区画・列表示順と採番方向のセル順から一般空席を探索する |
| `splitGroup / unlockGroup` | 全員の席と理由を検査して固定。解除では席・理由を保持。発行履歴・有効QRが一人でもあれば拒否する |
| `reallocateGroup / undoReallocation` | 直前の解除履歴と版を照合し全員を再配置。取消しは再配置前の席と解除前の固定・理由へ戻す。版は巻き戻さない |
| `finish` | 変更した割当・グループ状態の前後差分を作る。commit・assignment・receptionだけを進めた案を返す |

席番号の文字列順は使わず、確定構成から得たセルの位置と列を使う。手入力席でも一般・利用可なら対象となる。既配置の一部だけを自動で動かさず、グループ全体を対象外として理由を返す。既存の割当と無関係な来場者項目を保持する。

手動固定はグループ状態1件から全員へ投影する候補とし、固定フラグを人数分変更する計算を避ける。所属は全名簿のgroupIdから作り、購入者IDや氏名でグループを合成しない。ランダム生成は外部の責務とし、生成済み個人順の過不足を検査して履歴案へ残す。

## 判定の限界と後続

- 純粋計算の自動単体試験。500人・2区画もメモリー上の入力であり、通常登録・500席の公開やFirestore保存の結果ではない。速度・請求量の合格ではない。
- 元の入力を変更しない。再配置不能・不正入力は案を返さず、元の席を解放しない。成功時も共有正本へ反映しない。
- `completeRoster`は計算側の前提マーカー。共有保存はこの自己申告を信用せず、通常名簿・最新の券保護と共通版から完全性を検証する必要がある。
- 解除・取消しに渡す履歴は、同じ公演の確定済み履歴から取得する前提。純粋計算の検査は履歴の真正性を保証しない。直接送信による偽履歴の拒否はRules接続で確認する。
- 役割・端末と受付状態の認可、部分送信・同時更新と応答喪失は未検証。現在のGD91-65のRulesは自動配置要求を受理するよう変更していない。
- #93共通の名簿順・グループ参照の通常生成、固定・解除と取消し履歴を同じ正本へ接続した後、27件を保存経由で再確認する。画面・IndexedDBと実機も残る。
