# GD91-48 形・列設定と手入力席の比較契約

状態：In Review。読者：開発者、設計担当者、テスト担当者。

[詳細設計](../../docs/development/detailed-design/seat-management-detail-design.md#gd91-48-席idによる差替え比較契約)と[結果・残作業](../../docs/development/technical-validation/seat-save-validation.md#gd91-48-形列設定と手入力席の比較契約)へ追跡する。架空モデルの純粋な計算検証で、本番アプリケーションではない。

## 処理

1. 新旧モデルの形式・参照を検査する。環境・公演と区画を区別し、業務正本の二重保持を拒否する。未知の項目も無視しない。
2. セルをcellId・seatIdで索引化する。比較用の論理factはSeat全項目と対応Cell、重複検査用の表示番号で構成する。原値をコピーし、入力を変更しない。
3. 旧席IDを一巡し、新版の同じIDと比較する。旧席の削除も変更席へ含め、新規席は追加一覧へ分ける。セル・列設定の差分も別に返す。

列名・区画名と舞台位置はSeatの変更へ自動で含めない。prefix・lineIdと席属性、Cellの座標・IDは比較する。手入力番号を整数やQR資格へ変換しない。表示番号の重複は前後空白を除いて同一列内で検査し、内部空白・大小文字と全半角は保持する。

逆順の外周拡張は旧セル座標が一律にずれる。今回の差替え比較は位置変更として検出するが、実際の拡張は承認済みの専用経路へ渡す。余白スライドも専用経路を維持し、その例外を個別移動の隠蔽に利用しない。縮小はこの候補の対象外。

## 再実行

Node.jsだけを使用する。依存追加・外部接続はない。リポジトリのルートでpwsh 7から実行する。

```powershell
node poc/GD91-48/tests/comparison.mjs
node poc/GD91-48/analyze.mjs
```

[計算単体試験](tests/comparison.mjs)は36件。[結果JSON](artifacts/comparison-summary.json)へ前後3ソースハッシュを記録する。[契約照合](analyze.mjs)は[分析JSON](artifacts/contract-analysis.json)へ前後6ソースハッシュを記録し、GD91-47の範囲制限と500席の費用を照合する。過去44件・63件の再実行へ数えない。

## 保存接続の残条件

比較用factはメモリー上の論理契約で、追加のFirestore文書を必須にしない。サーバーが認めるfactの発行には、全セル・IDと採番の完成証明が必要。手入力席では消費番号の保持と同一列内の表示番号重複も検査する。列の次番号が変わったことを検出しても、その番号の正しさを証明した結果ではない。

旧席の全件走査と欠落証明、候補発行前の最新認可・確定版照合をRulesへ接続する必要がある。現在のGD91-47 Rulesは同じ形・列設定の自動席だけが対象であり、今回の計算結果だけで制限を外さない。

GD91-47の500席は準備1,033・比較171・候補2・公開3の計1,209書込み。今回の計算にはFirestore書込みがないが、新方式の保存費用が減った証拠ではない。物理形式と参照予算、式評価・容量と費用は未確定。全業務回帰・安全な回収、SDK・端末保存と実機も残る。方式未採用・本番未着手。
