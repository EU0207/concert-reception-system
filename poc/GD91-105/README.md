# GD91-105 区画操作の保存接続

状態：In Review。読者：開発者・設計担当者・テスト担当者。#167の隔離検証。PR #206は2026-10-15に承認・main統合済み。本番実装と方式採用は含まない。

今回の単位は区画新設・改名と舞台位置変更の保存、再取得と保持。部分送信・対象外変更と競合を拒否し、同じ候補で既存経路を回帰確認する。計算や入力接続だけでは区切らず、この範囲全体の検証または具体的な判断制約まで継続する。

## データと処理の流れ

名前と舞台位置は席データから分離した区画表示情報へ保存する。表示版と業務版を同時に進め、取得時に確定構成へ適用する。セルと席番号の複製を避け、割当・QRと緊急印を維持する。

ここで検証する保存は確定時の境界であり、入力ごとのFirebase保存を導入しない。未確定の名前・舞台位置は既存の端末下書きの対象とする。新形式の実IndexedDBとの接続は別の残条件である。

区画新設は新ID・未セルで候補を作り、既存区画を双方向に検査して一体公開する。既存の区画名と舞台位置、余白スライドも最新状態で保持する。初回受付開始後の新規区画作成は許可しない。

追加末尾の自動採番、区画の削除・並替えと帳票の生成は今回の対象外。端末状態はRAMで、実IndexedDBと全業務無料成立は残る。外部Firebase・課金・公開と3,000人試験は行わない。

| 保存操作 | 検査と保持 |
|---|---|
| 区画新設 | 準備中・初回受付開始前だけ。新しい1区画を未セルで作り、既存区画のID・配置と最新表示を保持して公開 |
| 改名 | 安定したsectionIdへ表示名を保存。同名の別区画を統合せず、他区画の値と緊急印を変更しない |
| 舞台変更 | left／topだけを保存。セル座標と採番軸を回転せず、確定した現在値を再取得で使用 |
| 取得・回収 | 基準構成に移動量と確定表示を適用し、最後に表示版を照合。旧構成回収でも現在の表示情報は保持 |

## 検証範囲と残条件

[全範囲](artifacts/validate-summary.json)と[最小共通ケース](artifacts/common-local-summary.json)を分けて記録する。同じ最終Rulesで既存経路を回帰し、元の試験ソースと実行したRulesのハッシュを保持する。通常の登録・割当とQR発行を使用するが、公演管理と端末の初期値は前提投入。

[全範囲18群](artifacts/validate-summary.json)・[最小共通4群](artifacts/common-local-summary.json)と既存194群が同じ最終Rulesで合格。共通4群は最大1,807ノード・47,416 B。19結果ファイルのソース620件を照合し、全拒否Rules・空試行根と待受終了を確認した。生成Rulesは1,899,419 Bで、外部成立と実費用は未確認。

表示変更は5論理パス・セル書換え0件。同じ名前の独立区画と舞台切替、キャッシュ再利用を確認する。部分保存・旧版と権限失効を拒否し、取得中の更新を混在させない。区画新設とスライド、既存構造編集との接続も対象とする。

名前100字と片幅16セルは隔離評価値で、製品上限へ確定しない。帳票への名称・舞台反映は共通データ契約までで、PDF／Excel生成・紙印刷と実機は未確認。追加自動採番・自動配置全体、新形式の端末再開と全業務無料成立は残る。独立した表示情報の区画削除時の回収も未接続。

旧GD91-104の読取処理は独立した区画表示情報を適用しない。既存回帰は旧データ経路の確認であり、新旧読取処理の混在合格ではない。本番採用時には読取契約の形式確認と再ダウンロード完了のゲートを必要とする。現在の端末初期値だけで対応端末と推定しない。このゲートは未接続で、#168・#110の採用・準備条件へ追跡する。

新設1区画はこのPoCの1操作単位であり、区画数の製品上限ではない。一つの下書きに複数区画を作成・編集した場合の一括確定との合成は未確認。個別操作の合格から、変更一式の確定を合格としない。
