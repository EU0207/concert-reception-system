# GD91-110 保存・取得の共通容量予算

状態：Approved（PR #212、2026-10-16）。読者：開発者・設計担当者・テスト担当者。#167の残条件を対象とする。PR #211・212は承認・main統合済み。TECH-DD91-101のAに従い、隔離PoCへ共通上限を適用した。本番コードは未実装。

## 処理とデータ

[capacity-policy.mjs](capacity-policy.mjs)で総4,096セルと16セル／片を定義する。片数256を同じ設定から求め、保存計画とRules生成、取得側へ渡す。

上限は公演の座席構成全体に適用し、区画ごとに4,096を許可しない。席・欠番・通路・空間・未を含む。保存済みの別世代や端末の複製を論理セル数へ重複加算せず、保管量は別に評価する。

[layout.mjs](layout.mjs)は全区画の行列を合計し、超過した保存計画を通信前に止める。端末保存は先に完了し、共有・確定を止めても下書きを保持する。取得側の上書き指定でも共通予算を広げられない。

[generate.mjs](generate.mjs)は宣言片数と区画集計を検査する。既存の整合性検査を残し、公開・共有の切替時も候補の予算を照合する。古い過大候補の安全な回収は妨げない。

区画数の取得予算は、各区画が最低1セルを持つことから総セル数を上界にする。これは4,096区画の性能保証ではない。製品の区画数と列設定数の案は既存の評価範囲と区別して扱う。将来の増設も同じ保存形式と席IDを維持し、設定と資源予算を再検証する。
