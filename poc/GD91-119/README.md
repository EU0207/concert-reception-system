# GD91-119 上限と締めの代表経路を一括確認

状態：In Review。読者：開発者・設計担当者・テスト担当者。#167条件1・4の外部代表確認をまとめる。本番実装は行わない。

## 対象

GD91-116の最新Rulesで、既存の容量・保持6経路と締め4経路に、初期上限の4経路を接続する。個別の上限ごとにログイン・外部試行を増やさない。ローカルと外部は同じ[cases.mjs](cases.mjs)を実行する。

| 対象 | 主な確認 |
|---|---|
| 既存6経路 | 総セル数、共有下書きの参照保護と結果照会、構成編集と一般受付SDK取得 |
| 締め4経路 | 通常締めと初回実績、代理・検査省略の拒否、取消しと例外締め |
| U01～03 | 16区画、横256採番列と縦256採番列の初回保存・公開・取得 |
| U04 | 17区画の直接宣言拒否、横・縦257列の通信前拒否と公開版保持 |

上限の各前提はownerで切り替える。この切替を業務上の削除・強制参照解除の合格とは扱わない。最大4,096セルと600／1,000席の本体はGD91-117のローカル証拠を維持し、外部で人数試験を繰り返さない。登録端末の準備と停止状態は前提投入を含み、全業務無料成立の証拠へ換算しない。

## ローカル確認

`node poc/GD91-119/run-local.mjs`で14経路が合格。REST変換の追加1回を含めた呼出しモデル476回に、外部準備24回・後処理80回を予約し、合計580／600回となった。実サービスで予算内となる保証ではなく、実行中も520回の通常試験上限を検査する。観測最大6,899ノード・167,049 Bで、提案上限以内。[67件のソース照合と結果](artifacts/audit-summary.json)。

最初の実行は生成スクリプト内の置換文字列を監査がimportと誤認し、業務試験の前に停止した。生成スクリプトは単体ハッシュ、実行モジュールは依存ファイルを巡回する従来の照合で確認した。[停止記録](artifacts/first-run-failure.json)。

RulesのJSONは2,556,076 B、文字列式は290件、`child`参照の静的出現数は119,546件。最大の式は394,885 B。これらはソース内の数であり、1要求の実評価数やアプリの読書き回数ではない。実行時の式数は未計測とし、Firestoreの依存文書上限へ換算しない。

## 外部確認案（TECH-DD91-109・未承認）

| 項目 | 上限・条件 |
|---|---|
| 環境・回数 | 既存の検証専用Spark、承認後の1試行だけ |
| 認証 | Google本人1・架空メール本人1と匿名端末3、最大5Auth |
| 架空データ | 来場者2人。最大256実セル／世代、最大3世代 |
| 保存 | 試行根20,000ノード・1MiB以内。旧試行の4,000ノードから拡大する |
| 呼出し | 後処理込み600回以内。通常試験520回で止め、80回を後処理に予約 |
| 観測本文 | 要求・応答の合計20MiB以内。SDK内部の実通信と請求量ではない |
| ログイン | 承認済み検証アカウントへ開発者が手動で1回。追加認証が出た場合だけ開発者が操作 |

256列の正常保存を同じ試行に含めるため、ノード上限を20,000へ広げる。呼出し数・本文上限は増やさない。無料枠・課金設定とリポジトリの公開設定は変更しない。終了済みの承認を再利用せず、新Rulesと上限変更を含む109-Aの判断を求める。

手順は次のとおり。

1. ローカル結果とソースを照合する。`node poc/GD91-119/remote.mjs --plan`で外部要求0回の実行範囲を確認する。
2. 承認後だけ実行用引数で開始する。試験根と検証Authが空で、全拒否Rules・請求先未登録であることを確認する。初期化済みの既存プロジェクト以外は拒否する。
3. ローカルのログイン画面を起動し、開発者がGoogleログインする。認証情報はGit管理外の一時領域だけで扱い、結果へ出力しない。
4. 同じ14経路を実行する。上限・認証期限・検査失敗で止まった場合も、残りを合格と扱わず診断位置だけ記録する。
5. SDKを切断する。試験根のデータと今回作成した検証Authを削除し、全拒否Rulesへ戻す。認証設定と許可ドメインを復元し、請求先未登録を再確認する。

Googleアカウント自体は削除しない。後処理に失敗した場合はGit管理外の試行情報を残して報告し、次の試行を禁止する。[remote.mjs](remote.mjs)は承認前の実行と終了済み結果への再実行を拒否する。試行結果のソース位置は残すが、メール・トークンや要求本文をエラー記録へ含めない。
