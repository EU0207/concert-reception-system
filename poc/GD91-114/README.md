# GD91-114 保持・回収条件の統合確認

状態：Approved（PR #215、2026-10-17）。読者：開発者・設計担当者・テスト担当者。#167の完了条件2を対象とする隔離PoC。本番実装と外部Firebase接続は行わない。

## 結論と確認範囲

完了条件2の保持契約を以下に集約し、最新GD91-113 Rulesで37群が合格した。2026-10-17、開発者がPR #215をレビュー承認し、mainへ統合。条件2・3の2／4が完了した。条件1・4の総資源予算は残り、#167全体はCloseしない。監査原データの承認待ち表示は測定時点の記録として保持する。

| 対象 | 保持・回収の条件 | 証拠 |
|---|---|---|
| 公開中・共有中の構成 | 現在の公開先または共有先である間は回収しない | R06、G04 |
| 編集元・送信候補 | 保存予約、端末参照または公開検査の参照が残る間は保持。権限失効・時間経過だけで解除しない | R01・04・05・08 |
| 未公開・作成失敗・取消し済み | 参照がなく、公開・共有先でもない場合に、最新の主担当・代理権限で回収する | R07、G01 |
| 回収途中 | `deleting`へ遷移してから表示・索引と構成片を削除。中断後も同じ世代から再開し、最後に`deleted`とする | G02 |
| 予約と回収の競合 | 回収開始が先なら新規予約を拒否。予約が先なら回収開始を拒否する。途中の参照だけを残さない | G03・04。両保存順を比較 |
| 操作結果 | 共有・確定結果を世代の回収と一緒に削除しない。同じ操作IDの照会を維持し、後続の公開を巻き戻さない | R02～05、G04 |
| 受付参照・未送信 | 元端末の最終連番と全件判断まで保持。回収不能端末は削除未確認のまま残す | D01～08、F02・06・07・11 |
| 締め・実績 | 全登録端末の照合後だけ確定。途中結果を実績正本として公開せず、再開時も二重集計しない | F01～17。600／1,000人は既存GD91-111の証拠を維持 |

世代回収は不要な座席構成の回収であり、公演の詳細履歴や実績の一括削除ではない。[承認済みの保持・バックアップ](../../docs/development/basic-design/retention-backup-remediation.md)を維持する。公演終了1か月後の案内は自動削除を意味しない。回収不能端末の保持は容量を消費し続けるため、無料枠評価で無視しない。

## 処理と確認

[retention-suite.mjs](retention-suite.mjs)は既存の保持8群・台帳8群・締め17群を最新Rulesへ接続する。実REST応答切断と暗号化IndexedDB、Edge再起動の確認を含む。元の試験コードと実行Rulesのハッシュを両方記録する。

[collection-local.mjs](collection-local.mjs)は、作成途中・回収途中と予約競合の4境界を追加する。架空4人の前提を投入し、回収自体は通常管理権限で行う。応答喪失は意図的な例外で、実ソケット切断の証拠は上記R02・04とF15・16へ分ける。

回収4境界の初回は、試験の確認処理が操作結果一覧の読取り権限を要求して停止した。診断で操作を特定し、既存の操作ID単位の照会へ修正した。Rulesは変更していない。構成片の削除後確認だけはownerで検査し、回収要求にownerを使わない。[初回](artifacts/collection-first-failure-summary.json)と[診断結果](artifacts/collection-diagnostic-failure-summary.json)は失敗記録として保持し、37群の合格へ加算しない。

## 無料枠計算に残る不足

[budget.mjs](budget.mjs)はGD91-111の測定を分類する。登録～発行確認、6SDKの取得と受付で分類できる応答本文小計は600人25,884,591 B、1,000人38,205,860 B。構成準備の全体と締めの業務通信が未分類であり、これは全業務合計でも請求対象通信量でもない。

締めの通常要求数は600人7,778、1,000人12,577と分離できるが、応答本文は試験専用の読取りと混在している。診断の全体集計は測定区間が異なり、単純に差し引くと負数になる。計算コードでこの誤った差引きを検出し、未分類の通信を0として補わない。[分類結果](artifacts/budget-coverage-summary.json)。

2026-10-17に[料金](https://firebase.google.com/pricing)と[通信の算定](https://firebase.google.com/docs/database/usage/billing)を確認した。SparkのRealtime Databaseは保存1 GB、月間ダウンロード10 GB。同時接続は100。本文に加え接続・暗号化の通信も算定対象になる。Firestoreの日次読書き枠をこの候補へ適用しない。

前日までの準備完了は維持する。ただし、この候補の月間通信枠は翌朝の日次回復を前提にしない。複数公演と保持データを同じ予算へ加え、当日必要量に既存の安全係数2を適用する。次は業務・診断の通信を工程別に分け、追加変更・再送を含む予算を確認する。人数だけで無料成立を保証しない。
