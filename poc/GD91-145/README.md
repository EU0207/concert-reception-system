# GD91-145 通常締め後のRTDB形式の移行と再承認

状態：In Review。#168の117-Aに従う隔離検証。旧Firestoreの締め済み形式の変換ではない。

既存127の通常登録、6SDK受付と全8登録端末の締めを再利用する。準備中に通常権限で5枠・各1MBの画像を公開し、締め済みの現在形式を別のローカルEmulator名前空間へ移す。追加の本番DBは作成しない。

元と先は同じAuth Emulatorプロジェクト内の別DB名前空間である。本人はGoogle方式のEmulator資格であり、実Googleログインや実プロジェクト間のAuth再設定を確認したものではない。

```text
node poc/GD91-145/run-local.mjs 4
node poc/GD91-145/audit.mjs
```

対象は業務形式3・構成形式2の通常締めである。現在のRulesが定義するルート領域を明示して、未知領域を拒否する。認可の役割・端末・セッションを複写せず、参照と稼働台帳を移行先の有効な認可へ使わない。旧端末の稼働台帳はマニフェストの監査情報としてRAMに保持するだけで、正式な監査台帳移行の合格ではない。

4人で5群が合格し、存在する17業務領域を照合した。途中2領域で中断した取込は全拒否のまま再開する。全領域を再取得・照合した後で、別のGoogle本人と匿名端末を前提登録し、本人の通常要求でセッションを発行する。実績と画像を通常権限で取得し、旧操作の改変・締めの準備中への変更を拒否する。端末停止後は取得を拒否し、元データと移行先実績は保持する。

600人は通常登録中に意図して中止し、全拒否Rulesと空の試行ルートを確認した。1,000人は未実施である。取込の権限境界が未決定のまま規模再実行を先行したため、判断後に接続する順序へ修正した。今回の中断を人数条件の不合格・合格のどちらにも数えない。[中断理由](artifacts/scale-run-withdrawal.json)。

取込自体はEmulator ownerによる試験投入である。**通常クライアントの同じルートへのPUTは拒否される。** 現行Rulesだけで正式な移行機能が完成した根拠にはならない。移行用の書込み主体と検証境界はADR-007 TECH-DD91-118で扱う。

進捗と変換計画はRAM。暗号化共有案・私有案の再暗号化は未対応であり有効化を拒否する。例外締め、削除後の実績、訂正・削除の移行後通常操作と、イベント再計算は未確認。画像データはBytes検証用で、実デコードを今回の合格へ加算しない。全形式移行の完了ではない。

ラッパー作成時に、文字列中のimportを式と同じように置換して構文エラーが発生した。存在しないTypeScript依存も参照したが追加・インストールはしていない。既知の文字列パターンを保護し、実際のimport行だけを変換した。Emulator起動前に生成・`node --check`を実行する。先行4人結果は後続の再実行と重複加算しない。
